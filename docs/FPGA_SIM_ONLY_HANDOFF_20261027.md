### 当前候选的可复现缺口

打包时发现，r2 清单绑定的 `bayer_raw10_demosaic4_p4.v` 和 `img_algo_parallel_top_p4.v` 当前来源已漂移，尚未找到匹配原 SHA 的副本；不能把当前同名文件放进历史 r2 清单后宣称复现通过。另两份 r2 行窗口/高斯派生依赖已在 `r2-timing-experiment/` 找到匹配 SHA 的副本并归档。具体 expected/observed SHA 和可用副本以交接包 `source-map.json` 为准。

历史独立验收结果只属于当时绑定的输入，当前 r2 源码闭包不完整。恢复原字节或建立新的候选并完成等价/集成仿真之前，队友不能把本包当作已验证、可直接构建的 r2 整机工程；板级 filelist 的活动来源快照也不等于冻结验收输入。

## 本地下一步：只用仿真能推进的内容

1. **先恢复并冻结可复现的源码闭包。** 按 `source-map.json` 取得匹配原 SHA 的文件；无法恢复的两份算法源必须形成新的候选，重新做灰度/高斯等价、停顿与集成回归，不能沿用旧 r2 PASS。
2. **复现并定位整机仿真的出口 ARM 不出现。** 在冻结候选下，用相机/DDR/主机模型追踪压缩提交、槽发布、P2 描述符和 `desc_arm`。验收应实际产生完整 MWr/doorbell 及源/接收字节对照；计数为 0 时不能把未执行的比较写成 0 差异。此项是功能阻塞，不是次要优化。
3. **补齐压缩 PCIe 的字节与身份桥。** 复用 T03 的字节责任图与离线向量，逐项落实 44B 头和 CRC/几何来源、camera/session/seq/slot/epoch 的保留、word→byte 地址单位、精确长度与含头 DMA 长度、完整页尾零填充、容量拒绝、ACK 后全身份释放。先独立仿真，再接同一冻结候选；离线参考布局不是现有硬件实现。
4. **补主机可观察的控制/状态仿真。** 当前开发记录中的 BAR `0x130..0x13C`、CTRL[9..11] 尚未实现，`a_enable` 固定为 0。先冻结字段定义并验证读写/复位/模式切换，再向队友交寄存器表，不能只凭内部信号存在就说主机可读。
5. **候选迁移与算法只做等价回归。** H-only synthfix、P4 r2 和失败 r3 分开存放，避免同名覆盖；HE 对 ready 形态的敏感性保留已知项。先解除首帧出口和协议阻塞，再排不会阻挡单路交付的算法或裕量优化。

这些是后续任务顺序，本次仓库整理没有修复上述 RTL 问题，也没有启动新的仿真开发任务。原活动 run 的状态、计数和独立报告保持原样。

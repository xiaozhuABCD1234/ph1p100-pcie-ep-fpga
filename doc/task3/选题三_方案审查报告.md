## 2. P0 — 三个必须在开工前解决的硬伤

### 🔴 P0-1　PCIe1 与 4G 接口互斥：**方案自相矛盾**

#### 问题陈述

方案把 `PCIe1` 定为 FPGA↔RK 主通道（判断正确，板级已连），同时在 §1.2 拓展项 6、§4.8、§9 三处都承诺 **"4G 远程推送异常图像"**。**这两件事在同一块板子上不能同时成立。**

#### 证据

`MLK-AFH03-AFC03硬件使用手册.pdf` §13「RK3576J：USB HUB」原文：

> 开发板从 RK3576J 芯片上引出一路信号，通过 U24 转出四路信号，芯片型号为 FE1.1S-BSOP28BCN，分别连接 **PCIE WIFI/BT，USB2.0 HOST 接口和 4G/5G 接口**。**如 Combo PHY1 的 PCIE1 或 SATA1 功能被使用则无法使用此功能。**

`RK3576 硬件设计指南 V1.2` §PCIe2.1 电路原文（机理）：

> ⚫ PCIe1 控制器(RC)、SATA1 控制器、USB3 OTG1 控制器复用 PCIe2.1/SATA3.1/USB3.2_Gen1x1 **Combo PHY1**

#### 影响

"4G/双网 + 远程图像推送"正是**高级档拓展项 6** 的得分点。如果方案既占用 PCIe1 又承诺 4G，答辩时会被认定为"承诺了做不到的指标"，比不写更糟。

#### 建议（三选一，建议前两项并行推进）

1. **首选**：高级项"远程推送"改走 **2×千兆网（RGMII0/1）双链路** —— 板上现成、稳、且同样能拿"多网传输"的分；
2. **实测确认**：验证 USB2.0 HOST 是否随 PCIE1 一起失效；若可用，用 **USB 4G dongle** 替代 M.2 模块；
3. **兜底**：若必须保 4G，PCIe 主通道只能放弃（`PCIE0` 已给 NVMe M.2，板上**没有第三条 PCIe**），退回 MIPI CSI3 备份通道 —— 但该通道本身有 **P1-5** 的疑问，风险高，不建议。

**文档动作**：方案必须新增一节（建议 §4.7.1「**PCIe1 与 4G 二选一**」），把上述冲突、证据原文与最终选择写明。

### 🔴 P0-2　DDR3 带宽高估 1.75 倍（方案称 3.7 GB/s，实际上限 2.13 GB/s）

#### 问题陈述

方案 §2.1 / §5：*"DDR3L 256 MB，16 bit @ **1866 Mbps** ≈ **3.7 GB/s** 峰值"*，§4.4 据此得出"总占用 <40%，安全"。

#### 证据：安路两份文档、两处独立指出 PH1A90 的 DDR3 接口上限是 1066 Mbps

- **DS900 表1-2（PH1A FPGA 封装类型）**：`PH1A90 SEG324 … DDR3 **1,066** Mbps`（对照 `PH1A180/PH1A400 = 1,866 Mbps`）
- **DS900 表3-2-7（I/O 接口性能表·输入）**：`SSTL15, SSTL,VCCIO=1.5V` → `PH1A400/PH1A180 = 1866/1600 Mbps`，`**PH1A90 = 1066/800 Mbps**`（-2/-3 速度等级）
- **DS901 表3-2** 同样给出 `PH1A90 SEG324 → 1,066 Mbps`

即：**颗粒是 1866 速度等级的 GDP1BFLM-CB，但 FPGA 的 DDR3 控制器/PHY 是瓶颈（1066 Mbps）**。
→ **16 bit × 1066 Mbps = 2.13 GB/s 峰值**，计入刷新、Bank 切换、读写切换开销后的实用值约 **1.4 ~ 1.7 GB/s**。

#### 带宽预算对比

| | 方案假设 | 按数据手册 |
| --- | --- | --- |
| 峰值 | 3.7 GB/s | **2.13 GB/s** |
| 预算 1.2 GB/s 占用率 | 32%（结论"充足"） | **56%** |
| 按实用值（1.4~1.7 GB/s） | — | **70% ~ 85%（危险）** |

#### 影响

4 路 1080p60 "写 1 读 1 备用 1"的**整帧乒乓有闭不上带宽的风险**，会直接冲击基础项 1/2/3。

#### 建议

- **(a) 立即确认**：找安路 FAE / 米联客核实 PH1A90 的 DDR3 实际可达速率（UG915 未给出 PH1A90 的明确限值，属文档空白区，必须拿原厂口径）。
- **(b) 架构改为"流式预处理优先"**（推荐）：灰度化 / 高斯 / 直方图 / Sobel / 阈值 / 形态学 **全部只在行缓存（Line Buffer）内完成，不整帧过 DDR**；DDR 仅用于 **压缩后码流暂存** 与 **跨通道时分复用调度**。
  → DDR 压力从 1.2 GB/s 降到 **<0.7 GB/s**（占用 ~33%），风险消除，同时降低端到端延迟、简化时序收敛。
- **(c) 中间形态**：若确需整帧无损处理，规划"**2 路整帧 + 2 路流式**"，并据此重写 §5 的带宽表。

### 🔴 P0-3　GT 速率写错；FMC 的 4 对 GT 被限制到 3.125 Gbps

#### 问题陈述

方案 §2.1：*"FPGA GT \| 8 通道（**1.2~12.5 Gbps**）"*。

#### 证据

**DS901 表3-2 注 1 原文**：

> PH1A90SEG324 器件 SERDES 的 **BANK80 和 BANK81 最高速率 3.125Gbps，BANK82 和 BANK83 最高速率 6.25Gbps**。

**旁证 1**：DS900 变更记录第 11 条 —— *"在表 1-2 中 PH1A400 器件 PCIe 的 Max Data rate 中增加 GEN3，**删除 PH1A90SEG324 的 GEN3**"* → 与 `BANK83 = 6.25 Gbps < Gen3(8 Gbps)` 自洽，**同时反向证明方案选 PCIe 2.0 是对的**。

**旁证 2**：DS900 表3-3-2 `FMINRATE（最低线速率）= 1.0 Gbps`（方案写 1.2）。

#### 关键后果

FMC 的 4 对 GT（`DP0_M2C/C2M`、`DP1`、`DP2`、`DP3`）落在 **BANK80 / BANK81** → **每通道只有 3.125 Gbps**。

→ 方案 **§10-B3**（"串化器相机 + GT 接收"：*相机端加 GMSL2 / FPD-Link III 串化芯片（MAX96717 / DS90UB953 类），1.2~6 Gbps 串行 → 用 FMC 的 4 对 GT 接收*）**不可行**：

- GMSL2 6 Gbps 模式 → 超限
- FPD-Link III（≤4.16 Gbps）→ 超限
- GMSL2 3 Gbps 模式 → 已顶到边界，无余量

**另需注意的矛盾**：硬件手册规格表却写 `FMC-HPC | 底板有 HPC 接口的 FMC 1 路，具有 24 对差分对/**4GT Lane@10.3125Gbps**+2GT REF_CLK`，与 DS901 冲突。**在拿到原厂明确口径前，不要把任何高带宽功能压在 FMC 的 GT 上。**

**文档动作**：§2.1 GT 行、§10-B3 均需改写（见第六节）。

## 3. P1 — 需修正的技术事实

### 🟠 P1-4　MIPI 字对齐用了**不存在的**训练序列

**方案 §4.2 原文**：*"**字对齐（word align）**：MIPI 每个 HS burst 前有 **0xAA/0x55 训练序列** → 用状态机搜索'高 4 bit = 低 4 bit 取反'的模式，做 `bitslip`。"*

**问题**：**MIPI D-PHY 协议中没有 0xAA/0x55 训练序列。**

HS SoT 的 Sync-Sequence 固定为 `00011101`（即字节 **0xB8** 按 LSB-first 发出）。

- **NXP AN13573（i.MX 8/RT MIPI DSI/CSI-2）** 原文：*"Inserts the HS Sync-Sequence **'00011101'** beginning on a rising Clock edge"*、*"Synchronizes upon recognition of Leader Sequence **011101**"*
- **MIPI D-PHY 规范** §7.2 定义的错误类型为 `SoT Error`、`SoT Sync Error`，即围绕该固定同步码做校验
- 工业实现同样如此：**Jetson SFT 块**（*"searches for the CSI-2 **sync byte (0xB8)** to establish proper alignment"*）、开源 `gatecat/CSI2Rx` 的 `dphy_rx_byte_align` 模块（*"align bytes using CSI-2 **synchronization codes**"*）

**修正**：字对齐目标改为 **SoT 同步码 0xB8**，并用 **CSI-2 短包包头 + ECC** 做二次确认（这也正是方案 §4.3 已有的 ECC/CRC 模块可以复用的地方）。0xAA/0x55 只在 sensor 开启 test pattern 时才会出现，**不能作为协议依赖**。

### 🟠 P1-5　MIPI CSI3 备份通道的物理归属需打问号

#### 观察

`RK3576J_PH1A90SEG324_MIPI交互管脚定义表.xlsx` 中，FPGA 侧 net 名是：

```text
MIPI_DPHY_CSI3_RX_D0P (RK H28) → PLB_LANE0_P (T11) / MIPIB_FLANE0_P (P13)
MIPI_DPHY_CSI3_RX_D0N (RK H29) → MIPIB_FLANE0_N (R13) / PLB_LANE0_N (U12)
MIPI_DPHY_CSI3_RX_CLKP (RK 1H22) → PLB_DSI_CLK_P (P17) / MIPIB_DSI_FCLK_P (T15)
MIPI_DPHY_CSI3_RX_D2P (RK K28) → PLB_LANE2_P (R16) / MIPIB_FLANE2_P (U13)
MIPI_DPHY_CSI3_RX_D3P (RK L28) → PLB_LANE3_P (T18) / MIPIB_FLANE3_P (V15)
```

`PLB_LANE*` / `MIPIB_FLANE*` / `PLB_DSI_CLK*` / `MIPIB_DSI_FCLK*` **是 MIPI D-PHY 硬核的引脚命名**，而 **SEG324 根本没有 DPHY**。

**解读**：该链路是按"**装有 MIPI 硬核的器件（SEG325 / SBG484）**"设计的。方案 §10-C1 已经指出 "V14/U13/U14/U16/U17/U18/T17/T18/R17/R18/P17/P18 等球功能不同"，**方向判断是对的**。

**这条反而加强了方案的软 D-PHY 论点**（板级布线位置本就是给 MIPI 硬核预留的），但带来一个必须验证的新问题：

**BANK12 存在大量带配置/复用功能的球**（来自 `MLK-AFC03-…` 图框 `20.Connect` 的 BANK12 引脚表）：

```text
IO_L1P_12, D17      IO_L3N_12, D20      IO_L5N_12, D23      IO_L8P_12, D30
IO_L2P_12, D19      IO_L4N_12, D22      IO_L6N_12, D25      IO_L9P_12, CSN
IO_L9N_12, D31      IO_L21N_12, D5      IO_L24P_12, D0, MOSI
```

**行动**：做 MIPI 软 TX 之前，必须在安路 TD 里逐一确认这些球在 **SEG324** 上确实可作为普通 **LVDS 差分输出**，而非被配置功能（Dxx / CSN / MOSI / D0）占用。

**文档动作**：§2.1 / §3 / 架构图里"**MIPI CSI3 4-lane（现成硬件）**"的说法，应改写为"**板级已布线，需验证 BANK12 复用脚在 SEG324 上的可用性**"，不要写成"现成硬件"。

### 🟠 P1-6　PCIe1 的复用代价，方案完全未提

**RK3576 硬件设计指南 V1.2 §PCIe2.1 电路 原文**：

> ⚫ **PCIe1 控制器(RC)、SATA1 控制器、USB3 OTG1 控制器复用** PCIe2.1/SATA3.1/USB3.2_Gen1x1 Combo PHY1

### 🟠 P1-7　高级档"**4K@30fps 单路**"完全没落到方案里

**选题指南场景 1（工业机器视觉）高级档"落地效果要求"原文**：

> **4K@30fps 单路稳定运行**；测量误差＜0.1mm；多目标并行识别；断网本地缓存、联网批量上传

方案的目标始终是"4 路 1080p60"，**从 §1.2 到 §7 排期都没有安排 4K@30 这一条**。

**好消息**：4K@30 RAW10 = 3840×2160×30×10 = **2.49 Gbps**，用 **4-lane 时仅 622 Mbps/lane** —— 与 1080p60@2-lane **完全同档**，**软 D-PHY 能力上做得到**，只是需要换相机/改配置。

**建议**：明确增加"**4K@30 单路**"演示配置（复用同一套 RTL，仅改相机配置、行缓存深度与输出缩放路径），并在 §1.2 / §9 的证据表里列为可演示项。否则高级档这条会被直接判缺。

### 🟠 P1-8　精度/准确率类硬指标缺"数据来源"

**指南的硬指标**：场景 1 中级"缺陷准确率 ≥90%"、高级"测量误差 <0.1mm / 多目标并行识别 / 异常画面本地边缘告警"；场景 3、4、5 亦有同类指标。

**方案现状**：只写了 YOLOv8n int8 + 棋盘格标定，**没有数据集、没有精度目标、没有不确定度分析**。

#### 必须先算清的两件事

1. **像素当量**：1080p 下若 FOV 为 300 mm，则 ≈ **0.28 mm/px**；要达 0.1 mm 需**亚像素精度 ≤0.36 px**，且必须为照明一致性、镜头畸变、标定误差留余量 → 需明确 FOV / 镜头 / 标定靶 / 重复性 3σ 的测试方法；
2. **"异常画面本地边缘告警"在模块清单里没有落点** → 建议 FPGA 直接出 GPIO 驱动 LED/蜂鸣器，或经 EP 驱动下发 RK GPIO。

**建议**：新增一节「**数据集与精度验证计划**」，内容至少含：场景选定（建议 PCB 缺陷 或 零件尺寸）、数据集来源与增强方式、精度/重复性验收方法与判据。

## 5. 方案层面的四项建议

### ① 自研 FMC 转接板是基础项 1 的**单一故障点**；§8 采购清单里的"**洞板**"必须删掉

622 Mbps/lane 的 MIPI **绝对不能上洞板**（无阻抗控制、无参考平面、回流路径不可控），会直接毁掉眼图、让软 D-PHY 调试变成玄学。必须做**阻抗控制的 4 层 PCB（差分 100 Ω）**。

在此基础上建议三处改进：

- **把 MC20901 的焊盘 + 0 Ω 选择直接画在同一块转接板上。** §10-E2 已经想到"买 A1 做保险丝"，但**"再打一版板"在 10 周排期里来不及**；同板预留 = 出问题只需补焊，不用重新打样。这是性价比最高的一处改动。
- **每条 lane 预留片外 100 Ω 端接位**，按 UG711 的双档设计（`|Vp-Vn| > 500 mV` 用片外并关片内；`≤500 mV` 可用片内）。
- **补 I2C 电平转换（1.8 V ↔ 2.8 V）。** §4.2 只写了"1.8/2.8/3.3 V LDO"，但 BANK12/BANK13 的 VCCIO 都是 1.8 V，而多数相机模组的 I2C 是 2.8 V —— 这一条不解决会直接卡在"相机配不亮"。

### ② 把"**流式预处理优先**"上升为核心架构原则（联动 P0-2）

行缓存内完成全部预处理、DDR 只放压缩码流 —— 一举三得：消除 DDR 带宽风险、降低端到端延迟、简化时序收敛。建议写进 §4.4 / §4.5 并重出带宽表。

### ③ 压缩模块的时分复用前提要写清

方案称"4 路预处理全并行、压缩模块时分复用 2 份"。4 路 1080p60 = **500 Mpixel/s**，2 份编码器意味着每份处理 **250 Mpixel/s ≈ 16 pixel/clk @ 156 MHz** —— 对流水线深度、Huffman 表 BRAM 带宽都是硬要求。

**建议**：先做"**单路单实例**"的实测资源与吞吐，再决定复用策略；§4.6 的"~10K LUT、12 DSP、120 Kb RAM/路"应标注为"待实测回填"。

### ④ 答辩最好打的两张牌，证据链各差一步

| 牌 | 现状 | 补什么 |
| --- | --- | --- |
| "**无 MIPI 硬核的 PH1A90SEG324 上自研软 D-PHY**"（最大亮点） | 方案已有论点 | **把 DS900 表1-2（SEG324 该栏为 `-`）与 §2.12 原文截图放进答辩材料** —— 这是最有说服力的一句 |
| "**板级已连好的 PCIe**" | 方案已有论点 | 把原理图图框 `26.FPGA_RK3576_PCIE_RC_EP` 的 C200~C203 + PI6C557-03 链路截图 |
| "软 D-PHY 真的做出来了" | 方案 §4.2 已规划自检寄存器（很好） | 把自检寄存器做成固定答辩素材：**相位扫描热力图 + 眼图 + ECC/CRC 错误率 vs 速率曲线** —— 这是唯一能让评委相信"不是纸面设计"的东西 |

**补充（同步测量口径）**：§3.2 帧包协议含 ns 级 `ts_fpga`，设计良好。但要注意 —— 用 FPGA 侧 `ts_fpga(SOF)` 差值测出的 "<1 ms" **只反映"链路级同步"**（含相机内部曝光/读出延迟与链路延迟）。建议同时用 **LED/闪光同步 + 高速相机或示波器**做"**光学级同步**"验证，答辩时才不会被追问穿。

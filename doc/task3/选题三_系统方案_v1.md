# 选题三：基于 FPGA 的图像采集压缩与智能预处理加速系统设计

## 系统方案设计（v1，面向"高级档"）

| 项目 | 内容 |
| --- | --- |
| 赛题 | 2026 全国大学生嵌入式芯片与系统设计竞赛 · FPGA 创新设计赛道 · 选题三 |
| 平台 | MLK-AFH03-AFC03-2GB LPDDR4X+32GB EMMC（安路 PH1A90SEG324 + 瑞芯微 RK3576J） |
| 技术路线（已定） | **FPGA 侧纯软 D-PHY（LVDS 差分直收 MIPI）**，FPGA 负责采集/预处理/压缩，RK3576J 负责 NPU 推理与交互 |
| 目标档位 | 冲"高级"（4 路同步、形态学/亚像素、无损+有损双模、PCIe、多目标测量、4G 推送） |
| 团队特点 | Linux/嵌入式强、FPGA 弱 → 方案采用"**FPGA 侧模块化 + 尽量复用官方 IP/例程**，RK 侧承担主要软件工作量"的分工 |
| 硬件新增 | 自研 FMC(HPC) → MIPI 相机转接板（只做电平/供电/I2C/触发，不含桥接芯片） |

> 一句话方案：4 路 MIPI 相机（建议低速率 2-lane 或 4-lane）经电平网络进 FPGA 的 LVDS 差分脚 → FPGA 内实现"软 D-PHY + CSI-2 解包 + DDR3L 乒乓缓存 + 3 种以上硬件预处理 + JPEG/LZ77 双模压缩"→ 经**板内已连好的 PCIe2.0 x1**（FPGA=EP，RK=RC）送 RK3576J → RKNN 推理 → HDMI 实时显示 + SD/千兆网/4G 输出，并输出全套量化指标。

### 2.2 必须回避的三个坑

1. **PH1A90SEG324 没有 MIPI D-PHY 硬核**（安路 DS900：只有 SEG325 / SBG484 / PH1A180SFG676 有 2 组×4lane MIPI DPHY-RX；SEG324 引脚表 0 个 MIPI 脚）→ 因此才走"软 D-PHY"，且**不能使用安路官方 MIPI 硬核 IP/例程**。
2. **底板两个 CSI 座与 FPGA 无关**（接 RK），FPGA 侧没有现成相机座 → 必须自研 FMC 转接板。
3. **FPGA↔RK 的 MIPI 是单向、软 D-PHY**（原理图第 24 页"DSI电路，CSI协议"）→ 传输主通道建议用 PCIe，MIPI 作备份/对照。

## 3. 总体架构

见同目录框图文件：`选题三_系统架构.drawio` / `选题三_系统架构.drawio.png`

```text
 [相机1..4]  MIPI CSI-2 (2~4 lane, RAW10)
     │  I2C 配置 / 外触发 / MCLK
     ▼
 [电平网络]  AC 耦合 + 共模偏置电阻网络 (安路 UG711 图 2-6-6/2-6-9)  → LVDS18 差分入 FPGA
     ▼
┌───────────────────────── FPGA PH1A90SEG324 ─────────────────────────┐
│ 软D-PHY RX ×4 → CSI-2 解包(VC/DT/RAW10/ECC-CRC) → DDR3L 乒乓缓存     │
│        → 预处理流水线(灰度|高斯|直方图|Sobel/阈值|形态学|亚像素)      │
│        → 压缩(JPEG Baseline 有损 + DPCM/LZ77 无损, 码率可调)          │
│        → PCIe EP(DMA + MSI)  ────────────────┐  (备份: MIPI CSI3 软TX)│
│ 控制与同步: I2C / MCLK / 帧计数 / 时间戳 / 触发输出                   │
└──────────────────────────────────────────────┼──────────────────────┘
                                               ▼  PCIe2.0 x1 (板内已连)
┌──────────────────────── RK3576J (Linux) ────────────────────────────┐
│ EP 驱动(字符设备+DMA+中断) → MPP 硬解 → RKNN(YOLOv8n int8) → 多目标跟踪 │
│ → HDMI2.1 显示(原图+识别框) / TF 存图 / 千兆网日志 / 4G 远程推送      │
└─────────────────────────────────────────────────────────────────────┘
```

## 4. 关键模块设计

### 4.1 相机选型与 4 路同步（**先定这一条，它决定后面所有参数**）

| 候选 | 接口 | 是否支持外触发/同步 | 备注 |
| --- | --- | --- | --- |
| IMX219 模组（树莓派同款） | 2-lane MIPI，1080p60 RAW10 | ❌ 无触发脚 | 便宜、资料/寄存器公开，适合**先跑通单路** |
| SC500CS（赛题平台二同款） | 2-lane MIPI，2592×1944@30 10bit（≈756 Mbps/lane） | ❌ 无触发脚 | 官方有 PH1A90 例程（但要硬核 MIPI），可参考协议解析部分 |
| **支持 FSIN/STROBE 的全局快门传感器**（如 AR0234 / OV9282 / SC132GS 等模组） | 2~4 lane MIPI + 外触发 | ✅ | **4 路硬件同步的正解**，价格略高 |

**同步策略（三级）**

1. **硬同步（首选）**：FPGA 统一产生 FSIN 同步脉冲给 4 个支持外触发的传感器 → 帧起始误差 < 1 µs。
2. **软同步（备选）**：同时写寄存器启动 + FPGA 记录每路 `SOF` 到达时的全局计数器值 → 在测试报告中**用实测数据证明 < 1 ms**。
3. **时序校准**：若各路存在固定偏移，可通过各自延时（`VTS/HTS` 或行消隐）微调对齐。

> 若最终只能买到无触发脚的传感器：把"4 路同步 <1ms"降级为"4 路时间戳对齐 + 实测偏差报告"，并把高级分转移到"亚像素测量/双模压缩"上。

**每路相机的速率预算（RAW10）**

| 分辨率@帧率 | 总码率 | 4-lane | 2-lane | 建议 |
| --- | --- | --- | --- | --- |
| 1080p30 | 0.62 Gbps | 156 Mbps/lane | 311 Mbps/lane | 起步用这个，软 D-PHY 最轻松 |
| 1080p60 | 1.24 Gbps | 311 Mbps/lane | 622 Mbps/lane | 目标档；2-lane 也在 LVDS18 1250 Mbps 能力内 |
| 2592×1944@30 | 1.51 Gbps | 378 Mbps/lane | 756 Mbps/lane | 高分辨率可选 |

**引脚预算（FMC 24 对差分）**

| 配置 | 数据对 | 时钟对 | 合计 | 剩余 |
| --- | --- | --- | --- | --- |
| 4 路 × 2-lane（1080p60@622 Mbps/lane） | 8 | 4 | 12 对 | 12 对做 MCLK/PDN/RESET/触发/扩展 |
| 4 路 × 4-lane（1080p60@311 Mbps/lane，最宽松） | 16 | 4 | 20 对 | 4 对做控制/扩展（相机模组自带晶振时可省 MCLK） |

> 推荐 **4 路 × 2-lane**：引脚余量大、I2C/MCLK/触发都好安排；若软 D-PHY 时序收敛吃紧，再切到"4-lane 降速"方案。

### 4.2 软 D-PHY 物理层（本项目的技术核心 + 最大风险）

**硬件侧（自研 FMC 转接板要做的事）**

1. 相机 FPC 座（IMX219 是 15P/24P，按模组选）×4 + 供电（1.8/2.8/3.3 V LDO，从 FMC 的 3.3V/12V 取）。
2. 每 lane：**AC 耦合电容（0.01~0.1 µF）+ 共模偏置电阻网络**，按安路 UG711 图 2-6-6（BANK 1.8 V）设计；差分 100 Ω 端接用 FPGA 内部端接或板级电阻（**注意 UG711 提示：接收幅度 >500 mV 时必须用片外 100 Ω 并关闭片内端接**）。
3. 差分对**等长**处理（FMC 到相机座 ≤ 数 cm，对内偏差 <5 mil）；CLK 对优先走 FMC 的 4 个时钟专用脚（`LA00_CC`、`LA03`、`CLK0_M2C`、`CLK1_M2C`，对应 FPGA `B13_L13/L14/L11/L12`，都是 GCLKIOT/C）。
4. BANK13 的 VCCIO 由底板 J32 设定 → **必须切到 1.8 V**（3.3 V 时 LVDS 只能 AC 耦合输入且共模要 1.65 V，不适合本方案）。
5. 预留 LP 状态检测点（若要做完整的 LP→HS 状态机，用一根普通 IO 经分压看 LP 电平；v1 可以先不做 LP）。

**RTL 侧（`mipi_phy_soft`）实现要点**

- 每个 data lane：`IBUFDS(LVDS18)` → `IDDR` DDR 采样（1:2）→ 位对齐。
- **字对齐（word align）**：MIPI 每个 HS burst 前有 `0xAA/0x55` 训练序列 → 用状态机搜索"高 4 bit = 低 4 bit 取反"的模式，做 `bitslip`。
- **采样相位**：两种方案
  - *A. 转发时钟（推荐 v1）*：用 clock lane 经 GCLKIOT 进全局时钟，DDR 采样；burst 之间重新训练（同步头搜索 + 相位重扫）。
  - *B. 本地 PLL + 相位扫描（v2 优化）*：用 PLL 生成多相位 bit 时钟，逐相扫描选最佳采样点，避免依赖相机 clock lane 的抖动/停振。
- **HS/LP 处理**：v1 忽略 LP（CSI-2 的帧边界靠 HS 内的 FS/FE 短包识别）；LP 检测作为 v2 加分项。
- **自检手段**：内部把每路的"相位扫描结果、bitslip 次数、CRC/ECC 错误计数、SOF/EOF 间隔"寄存器化，经 I2C/PCIe 上报 → 答辩时可展示**误码率与同步质量数据**（这是软 D-PHY 方案最有力的说服材料）。

**速率与风险对应**：≤400 Mbps/lane 稳妥；400~700 Mbps/lane 需要仔细做时序约束与板级等长；>800 Mbps/lane 强依赖板级信号完整性（建议不要一开始就冲）。

### 4.3 CSI-2 协议层（`csi2_rx`）

- 短包解析：`FS/FE/LS/LE`，提取虚拟通道 VC、数据类型 DT、帧号。
- 长包解析：`PH(4B) + payload + PF(2B)`；支持 **RAW10**（Lane 打包 → 像素重排）、RAW8/RAW12 预留。
- 校验：ECC（包头）+ CRC16（包尾），错误计数与丢包上报。
- 多路复用：4 路相机各自一个实例，输出统一的 `axis` 像素流（`tuser` 带 cam_id/frame_id/sof）。

### 4.4 帧缓存（`frame_buf`，DDR3L）

- 结构：每路 3 帧乒乓（写 1 读 1 备用 1），或 4 路共享一个大缓冲按帧号轮转。
- 作用：吸收相机与压缩的突发差、避免撕裂、支持"压缩前整帧"与"整帧无损"模式。
- 带宽核算：4×1080p60 RAW10 写入 ≈ 5 Gbps ≈ 0.62 GB/s（占 DDR3L 峰值约 17%），读回压缩同量级 → 总占用 <40%，安全。

### 4.5 预处理流水线（`preproc_pipeline`，≥3 种必须硬件并行）

| 级别 | 算法 | 实现要点 |
| --- | --- | --- |
| 基础（必做，至少 3 种） | 灰度化 | Y = (77R + 150G + 29B) >> 8，1 DSP/路 |
| | 高斯滤波 | 3×3 可分离（行→列），行缓存 + 移位寄存器，2 DSP |
| | 直方图均衡 | 帧内统计（BRAM 累加器）+ 累积分布查表（LUT），需双缓冲握手 |
| 中级 | Sobel/阈值分割/形态学 | Sobel 梯度幅值；Otsu 阈值；腐蚀/膨胀 3×3 |
| 高级 | 亚像素边缘/尺寸测量 | 梯度重心法求亚像素位置 + 相机标定换算 mm（目标误差 <0.1 mm） |

流水线组织：**每级 `valid/ready` 握手 + 行缓存**，4 路可以"时空复用"（按行/按帧轮转）以节省资源，但要注意吞吐（4×1080p60 = 500 Mpixel/s，建议每路独立实例或成对共用）。

### 4.6 压缩模块（`img_compress`，有损+无损双模）

| 模式 | 算法 | 预期压缩率 | 资源（每路估） |
| --- | --- | --- | --- |
| 有损（基础项） | JPEG Baseline：RGB/YUV → 8×8 DCT → 量化（表可切换）→ ZigZag → Huffman | 8~20:1 | ~10K LUT、12 DSP、~120 Kb RAM |
| 无损（高级） | 预测 DPCM（MED/左邻）+ LZ77 字典编码（或 Rice 熵编码） | 2~3:1 | ~6K LUT + 大量 BRAM（压缩块可复用 JPEG 的 BRAM） |
| 动态码率（中级/高级） | 依据输出缓冲水位/目标帧率反向调整量化表索引（QP 逐块步进） | 可闭环 | 控制逻辑 ~2K LUT |

> 资源紧张时的做法：**4 路采集/预处理全并行，压缩模块时分复用 2 份**（帧级乒乓调度），实测帧率仍可满足 60 fps。

### 4.7 异构高速通道（PCIe 为主，MIPI 为备）

| 方案 | 硬件 | 带宽 | 优点 | 风险 |
| --- | --- | --- | --- | --- |
| **PCIe2.0 x1（主）** | **底板已连好**：RK `PCIE1_TX/RX` ↔ FPGA `bank83 lane1`，中间 100 nF 交流耦合（C200~C203）；RK 侧只支持 RC（官方手册明确），FPGA 侧用 PH1A PCIe 硬核配 **EP** | Gen2 x1 ≈ 4 Gbps 有效（≈500 MB/s） | 双向、可 DMA、有中断；**团队 Linux 强 → 价值最大化**；对应"高级-异构高速传输" | FPGA 侧要跑通安路 PCIe 例程；RK 侧要写 EP 驱动（BAR/ DMA / MSI） |
| MIPI CSI3 4-lane（备） | BANK12 HR IO + 串阻（现成） | ≈4 Gbps，**单向** | 现成、无需额外硬件，可作对照演示 | 软 D-PHY 发送；RK 侧 VICAP 多 VC 支持需确认 |

**PCIe 侧软件栈（团队强项）**

```text
RK3576J (RC, Linux)
  └─ ep_drv.ko：PCIe 枚举 → BAR 映射 → 分配 DMA 环形缓冲 → MSI 中断 → 注册 /dev/fpga_cam
       ├─ mmap：把接收环形缓冲映射给用户态
       ├─ ioctl：下发配置（相机曝光/增益、QP、分辨率、模式）、查询统计
       └─ poll：新帧就绪通知
FPGA (EP)
  └─ pcie_ep_dma：配置空间(BAR0 寄存器 / BAR1 DMA 描述符) + DMA 写主机内存 + MSI 上报帧完成
```

### 4.8 RK3576J 侧软件

1. **接收**：`ep_drv.ko` → 帧包解析 → 按 `frame_id/cam_id` 分发。
2. **解压**：调用 MPP（硬件解码器）解 JPEG；无损模式用软件解（CPU 8 核够用，或写定点解码器）。
3. **推理**：RKNN 部署 YOLOv8n/YOLOv5n（int8）；4 路 1080p60 建议"ROI/抽帧 + 多线程流水线"（NPU 6 TOPS：YOLOv8n 640×640 ≈ 10~20 ms/帧）。
4. **多目标跟踪 + 尺寸量化**：ByteTrack/SORT 轻量实现；像素→mm 标定（棋盘格标定 + 平面假设）。
5. **输出**：
   - 显示：HDMI2.1 四画面拼接 + 识别框 + 帧率/延迟/压缩率 OSD 叠加（**答辩最直观**）。
   - 存储：TF 卡按事件存原图/压缩图；断网本地缓存（高级项）。
   - 网络：千兆网实时上传检测日志（HTTP/MQTT）。
   - 4G：异常图像远程推送（底板 4G 接口 + 模块）。
6. **测试工具**：`perf/tegrastats` 类脚本统计 CPU/NPU/延迟；与 FPGA 时间戳对齐做端到端延迟测量。

## 10. 附录：把 MIPI 送进 FPGA 的全部可选路线（软 D-PHY 的替代/增强方案）

> 结论先说：**"FPGA 自研采集"这条赛题要求，只有 A 类和 D 类能满足字面要求**；B 类是"绕行+口径"、C 类是"换硬件"。

### A. 外置物理层桥接（MIPI 不进 FPGA 的 LVDS 脚，而是先变成 FPGA 好收的信号）

| 方案 | 器件 | 能力 | 对"FPGA MIPI 驱动 IP 核"的满足度 | 成本/周期 |
| --- | --- | --- | --- | --- |
| A1（推荐备选） | **MC20901**（Meticom，VQFN48）：MIPI D-PHY → LVDS(HS) + CMOS(LP)，5 通道 | HS ≤2.5 Gbps，兼容 DSI/CSI-1/CSI-2，输出可直接接 FPGA/DSP | **完全满足**：芯片只做 PHY，CSI-2 协议层（包头/VC/RAW10/ECC-CRC）仍由 FPGA 自研实现 | 芯片几十~百元/片，自研小板 2~3 周 |
| A2 | **TC358746AXBG / TC358748XBG**（东芝，BGA72/BGA80）：CSI-2 ↔ 并行 24 bit 双向 | CSI-2 ≤1 Gbps/lane、最多 4 lane；并口 PCLK ≤100 MHz | **部分满足**：CSI-2 协议在桥片里解完，FPGA 只收并口；答辩需说明"FPGA 实现的是 sensor 驱动 + 视频接收/加速 IP" | 芯片便宜好买，最省 FPGA 工作量 |
| A3 | MC20001（单通道 MIPI 接收）等同类 D-PHY 接收芯片 | 单 lane | 同 A1 | 视项目而定 |
| A4 | 离散 LVDS 中继（SN65LVDS / DS90LV 系列 + 电阻网络） | 只是"外置整形/驱动" | 属软 D-PHY 的增强版，不改变方案性质 | 十几元，可显著改善高速率下的眼图 |
| 方向陷阱 | TI SN65DSI 系列（DSI 发送）、LT8918/LT9611（HDMI↔MIPI）等 | — | **方向都不对**，必须是 "CSI RX → LVDS/并行 输出" | — |

### B. 不把 MIPI 送进 FPGA 的绕行方案

| 方案 | 做法 | 满足度与风险 |
| --- | --- | --- |
| B1 RK 采 + PCIe 转发 | 相机插 J8/J9（RK CSI0/CSI1）→ RK VICAP 出 RAW/RGB → 板内 PCIe2.0 x1 DMA 到 FPGA → FPGA 预处理/压缩 → 回传 RK 做 NPU | **零硬件改动**、最稳；字面上不满足第 1 条。可变形为"RK 把原始 CSI-2 packet（含包头/CRC）透传给 FPGA，由 FPGA 实现协议解析/RAW10 解包/ECC-CRC"，即物理层借 SoC、协议层自研（答辩需诚实标注） |
| B2 混合架构（推荐） | FMC 接 1~2 路走自研软 D-PHY（满足第 1 条 + 创新点）；J8/J9 接 2 路给 RK，再经 PCIe 送进 FPGA 一起做预处理/压缩 | **4 路并行照样成立**，风险分散、得分点最全；代价是两套采集路径要维护 |
| B3 串化器相机 + GT 接收 | 相机端加 GMSL2 / FPD-Link III 串化芯片（MAX96717 / DS90UB953 类），1.2~6 Gbps 串行 → 用 FMC 的 4 对 GT 接收，1 GT = 1 路相机，最多 4 路 | 创新性高、可讲长距离/抗干扰；但链路初始化与协议解析都得自己写，成本高（串化板+解串器），**不适合冲进度** |
| B4 SFP 光纤延长 | 相机端编帧后走 10 G 光模块（板上有 2 个 SFP+） | 适合"远端相机"演示（低空/园区场景），需两端设备 |

### C. 换器件 / 换平台

| 方案 | 说明 |
| --- | --- |
| C1 换 PH1A90SEG325 / SBG484（有 2 组×4lane MIPI 硬核） | **不是 P2P**：L17、U15 在 SEG324 是 VCCIO_12 电源脚，在 SEG325 是 MIPI 脚；V14/U13/U14/U16/U17/U18/T17/T18/R17/R18/P17/P18 等球功能也不同 → 比赛板改不了，不现实 |
| C2 换"有 MIPI 硬核的安路器件 + 带 NPU 的 SoC"板卡 | 公开资料显示米联客有 MLK-AFH01（PH1P100 + RK3588J）+ 2 路 MIPI 子卡；安路官方也有 PH1A90 4K 摄像头方案（MIPI 硬核 + SC500 例程）。走**选题五自主命题**，代价是偏离推荐平台三的评分口径 |

### D. 不换方案、只降难度的两个"软 D-PHY 简化档"（对 FPGA 弱的团队很关键）

| 档位 | 做法 | 适用速率 | 说明 |
| --- | --- | --- | --- |
| D1 **过采样法** | 不用 IDDR/bitslip，用 4~8× 采样时钟 + 边沿/状态机恢复比特 | ≤200~300 Mbps/lane | 逻辑简单、几乎一定能出图：适合作为 **第一步**（如 720p30 RAW10、2-lane 每 lane ~166 Mbps），出图后再升级到 DDR 采样 |
| D2 降速率组合 | 4-lane 模式 + 低帧率/低分辨率（1080p30 4-lane = 156 Mbps/lane） | ~150~350 Mbps/lane | 把时序收敛压力降到最低，接口对数量换速率，FMC 引脚足够 |
| D3 DVP/并口兜底相机 | OV5640-DVP / MT9V034（全局快门、支持外触发、便宜） | 并口 ≤100 MHz | 直接进 FPGA，零 MIPI 风险；用来先把"预处理+压缩+PCIe+NPU"全链路跑通，MIPI 通道后补。严格说赛题要求 MIPI，定位是**进度保险丝 + 对照实验** |

### E. 推荐组合（在"FPGA 弱 + 冲高级"约束下）

1. **主线**：D1 过采样法先打通 1 路（W2~W3）→ 升级 D2 配置做 1080p60。
2. **保险丝**：D3 一块 DVP 相机 + A1（MC20901）小板的采购与原理图并行推进，W3 若主线未出图，**立刻切 A1**（保留"FPGA 自研 CSI-2 协议层"的说法，得分不受影响）。
3. **保 4 路并行**：若 W6 仍只有 1 路 MIPI 打通，采用 **B2 混合架构**（1~2 路 FMC 自研 + 2 路 RK 采经 PCIe 转发），4 路同步与并行处理照样能演示。
4. **答辩口径**：明确区分"物理层（PHY）"与"协议层 + 加速层"——无论走软 D-PHY 还是 MC20901，**CSI-2 解析、RAW 解包、ECC/CRC、预处理、压缩都是 FPGA 自研 RTL**，这正是赛题考察的核心。

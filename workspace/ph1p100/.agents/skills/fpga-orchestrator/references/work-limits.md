# 工作范围、停止与有限返回机会

本文件是本项目现行有界规则的唯一正文，供主传输、规划、开发和综合测试使用。角色技能、dispatch及使用说明引用本文件；不授予新权限，不替代系统工具的实际控制。默认角色链为主传输 → 规划 → 每任务新开发 → 冻结 → 一个新综合测试者 → 原规划收尾。子角色禁止派生。

## 启用边界

仅当前用户明确调用fpga-orchestrator并要求执行/恢复时启用本角色链，主入口Skill关闭隐式调用。普通问答、报错解释、资料讨论、技能引用/代码例子/转述、查看/比较/修改规则均不启动本链。已启动同run按原授权续接，状态/规则讨论不另开链；明确停止/退出时停止派发并给恢复入口。其他通用约束及技能/工具照常适用。本文件只约束启用后的执行，不安装MCP或修改全局配置。

## 范围与拆分

1. 一次需求本轮只做1个主要可验收目标，最多4个正式工作包，ready、blocked及依赖包都计入。仅两级：需求 → 工作包；包内操作是清单，不另建子任务或新代理。批准合批不会减少正式任务总数。
2. 每包一个主要可观察结果，通常围绕一个模块、接口或文档主题及必要相邻引用，最多5项语义实现步骤。出现两个可独立验收结果、无关接口改动或第6项语义步骤时拆窄。同步多份引用、读取、改一行、计算哈希、运行命令等机械动作不单独建包或代理。
3. 超过1目标、4包或两级时，规划在首次计划选依赖闭合的最小可交付切片（不超过4包）：先按用户明确优先级，再按已有依赖顺序，最后按需求出现顺序取舍。余项只留最多3条后续主题与原需求路径，不展开任务树，本轮不自动续做。无法形成小闭环时，只交1个范围/接口冻结包，其余待后轮；不能把范围冻结当作父目标已完成。
4. 只有用户明确给出本轮新的有限目标数、任务数或层数，规划才可在dispatch记录相应覆盖值及授权来源。“全部做完”、合批、时间宽裕均不是覆盖授权。禁止增大BATCH_SIZE、新run、自造子ID或重命名失败包绕上限。用户新需求改变边界时交原规划，主不选范围。
5. 默认BATCH_SIZE=1。只有用户明确大于1才由规划定义批；每批一个开发者顺序实现、一个综合测试者覆盖全批，逐任务判定和修复轮数分别记账。用户明确授权新角色之前，不因风险增大自动增加测试或审阅代理。

## 一个综合测试者按风险覆盖必要检查

三维是functional、engineering、system检查清单，由与开发独立的一个综合测试者统一核验。规划事先写适用项、G层、门槛与不适用理由；“独立”指测试者独立于开发，不声称三个独立视角。

| 范围 | 必要检查由规划按改动选择 |
|---|---|
| 文档/配置 | 语义、格式/入口/哈希、交接兼容性 |
| 模型/软件 | 针对性正反向与边界、可复现性及相关接口 |
| RTL/时钟/IP/存储/地址/板上行为 | 所需真实DUT、最终STA/CDC/资源及候选绑定，真实硬件、恢复、稳定性与性能检查 |

风险增大先增加必要检查或缩小工作包，不自动增加角色。必需工具/设备/资料/授权缺失直接blocked，综合判定FAIL；不能临时改不适用或放宽门槛求PASS。文档/模型不用无关硬件流程，纯配置PASS不证明RTL、时序、板测或完整调度行为已通过。

角色与上下文只用最小相关输入；综合测试按需读取旧领域清单，不要求一律读取三份。必要验证可复用同输入证据，须写依据并绑定当前manifest；一次检查避免重复重建。不得以节约成本免门槛，不承诺具体token节省百分比。

## 主只接收返回，不监控进度

主不轮询状态、不扫描目录或日志估计进度、不问进度或催促、不做超时后的反复盯控。仅接收返回事件、完成消息和明确元数据。Codex的wait_agent仅等事件，单次不超过60000ms；OpenCode默认前台subagent等最终返回，无独立wait_agent，不虚构timeout参数。等待无返回不产生检查、催促、故障或重试动作。调用差异见[宿主适配](runtime-calls.md)。

真实ID从当前宿主新建角色工具返回即时登记，并记录runtime，不预防性探测。ID失效以实际工具错误交原规划恢复；能续则续，跨宿主/OpenCode换父会话时按文件恢复并登记真实新旧ID/宿主映射，不假称resume、不重置计数。失联且无返回时，主不伪造blocked/PASS或称平台已自动终止。

## 子角色自行有界执行

- 每角色每次派发/续接默认最多30次实际工具调用；规划自我停止预算15分钟，开发/综合测试各45分钟。自己的命令轮询和worker调用也计入。规划可在派发前按必需构建或长稳时长冻结其他有限预算及理由；运行角色不能自行扩预算，更不能因此扩大需求上限。
- 单一未决问题最多3轮有目标的搜索/读取。同一失败命令最多首次加1次重试，且仅在有新证据或参数纠正时重试；不能换关键词、ID或目录绕计数。
- 缺资料、工具、设备、授权或额度直接blocked。DeepSeek/API错误不自动重试，根AGENTS完整规则继续有效。
- 连续2次工作循环没有新证据、实质产物变化、有效验证结果或可检查的假设收窄，主动停止并返回blocked。换措辞、记日志或重复同输入不算进展。达到工具/时间/搜索预算，或发现必须扩范围时同样停止。
- 返回须写原因、已做/未做、最后实际结果路径、最小下一步及准确恢复入口，交原规划处理。不能等待主催促才停止。

命令启动前落实工具支持的超时或可安全终止机制：读取/搜索默认deadline为60秒，局部静态检查/仿真5分钟，FPGA构建30分钟。规划可在派发前为必要工作冻结其他有限值。exec的yield_time_ms仅控制输出返回，不能冒充执行超时。不支持实际超时且无法安全控制时，不启动无界命令，返回reason_code=TOOL_CONTROL_MISSING（原因tool_control_missing）。

角色只跟踪自己发起的命令；达到deadline安全停止本角色拥有的进程，保留日志与退出信息并返回，不能杀他人进程。不要新建监控Agent、定时任务或常驻执行器。这些是提示词/角色执行合同，并非平台保证的硬时限，也不保证失联角色自动停止或自动回报。

## 收到重复问题后的有限机会

与实际实现修复轮数分账。子角色有问题时返回problem对象：

| 字段 | 要求 |
|---|---|
| problem_id | 同任务同根因稳定，例如task_id:INPUT_CONFLICT:manifest |
| reason_code | 下列固定枚举之一 |
| new_information | 布尔值，是否有新信息 |
| evidence_path | 最后实际证据的准确路径 |
| requested_action | 原授权范围的补充/整理动作，外部条件则写缺失条件 |
| resume_input_path | 准确恢复输入路径 |

reason_code仅用RETURN_FORMAT / INPUT_CONFLICT / SCOPE_CLARIFICATION / REPRO_DETAIL / TOOL_UNAVAILABLE / DEVICE_MISSING / PERMISSION_MISSING / API_ERROR / QUOTA / TOOL_CONTROL_MISSING / NO_PROGRESS / LIMIT_REACHED。资料缺失按实际问题归INPUT_CONFLICT或SCOPE_CLARIFICATION，保留具体缺项。

相同问题换措辞、修复轮次或转交角色不改problem_id；真正不同问题由原责任角色说明不同证据，主不读长文猜身份。主只在收到返回后，按task_id+problem_id登记最多2次续原责任角色机会。仅字段齐备、new_information=true、证据/恢复路径齐备，且requested_action为原授权范围补充/整理时可机械续接。信息真假、技术根因由责任角色核验，主只检查元数据。

new_information=false、字段缺失或矛盾、无法稳定归类，或已给2次机会后仍返回同问题，直接交原规划blocked/备条件。规划同样受该计数，不靠往返转交重置机会。到限后仅真实新增用户输入或工具设备条件变化可由原规划明确恢复，不能自行再试。

设备、工具、资料、权限、API/额度错误等明确外部阻塞不走机会循环，不自动重试或扩权。PASS/FAIL实际实现修复仍按round0首次验收、round1—3最多三轮实际修复；不能把修复改名“回答机会”绕三轮。机会仅用于返回内容补充/整理，不由主提供技术答案或监控兜底。

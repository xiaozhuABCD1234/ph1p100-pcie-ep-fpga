# HDMI 已知色端到端记录模板（B2）

> 2026-10-15。**只生成"期望值"，不产生位流、不访问硬件。** 现有参考色条探针只能回答"看到的颜色对不对"（主观、无仪器）；本模板把**期望的 10bit TMDS 码**算出来，使"已知输入 → 期望码 → 实际观测"三段可追溯。

## 一个必须先知道的陷阱：码字取决于**历史**

TMDS 的 DC 平衡是**有状态**的：同一个颜色，前面走过什么像素会改变它现在的码字。

实测（本模型自证）：

| 情形 | 白色 `FFFFFF` 的 ch0 | 红色 `FF0000` 的 ch0 |
|---|---|---|
| 从 disparity=0 开始（单色整屏） | `1000000000` | `1000000000` |
| 紧跟整屏白色之后（等于参考色条顺序） | `1000000000` | `0011111111` |

所以：
- **"只看几个像素"不足以证明编码正确**；
- 用本模板对照时，必须说明**起点条件**（本表是"每个颜色从 disparity=0 起"，适合单色整屏或每个色段的起点）；
- 若对照的是**参考色条（8 色连续）**，第 2 段之后的期望码要按整段序列算，不能直接用本表。

python parallel/tmds/known_color_record.py

### 期望码（每色第 1 拍，disparity=0 起）

| 色 | RGB | ch0 | ch1 | ch2 | clk |

| 白 | FFFFFF | 1000000000 | 1000000000 | 1000000000 | 1111100000 |
| 红 | FF0000 | 1000000000 | 0100000000 | 0100000000 | 1111100000 |
| 绿 | 00FF00 | 0100000000 | 1000000000 | 0100000000 | 1111100000 |
| 蓝 | 0000FF | 0100000000 | 0100000000 | 1000000000 | 1111100000 |

| 品红 | FF00FF | 1000000000 | 0100000000 | 1000000000 | 1111100000 |
| 黄 | FFFF00 | 1000000000 | 1000000000 | 0100000000 | 1111100000 |
| 黑 | 000000 | 0100000000 | 0100000000 | 0100000000 | 1111100000 |

（连续同色的第 2..4 拍会交替，见 CSV。）

## 怎么用（不要求现在做）

1. 上板显示对应颜色（现有参考色条探针即可）。
2. 目视或采集：该色是否被显示为该色（填 `observed_color` / `observed_ok`）。
3. **可选、更强**：用示波器/逻辑分析仪在 HDMI 的 TMDS 对上抓 4 条 lane 的串行位流，与期望码比对——这一步才能真正区分"编码正确"与"显示端把错色显示对了"。
4. 记录起点条件（单色整屏？色条第几段？）。

## 边界

- 本模板给出的是**本模型认为正确的期望值**；模型的正确性由 `tmds_ref.py --selftest` 与与 Project F 的交叉核对支撑（见 [TMDS 独立参考模型](TMDS独立参考模型_2026-10-15.md)）。
- **不证明**加密编码核正确（黑盒无法逐位对照）；它只是一个可用于对照的期望基准。
- 抓串行位流需要仪器与夹具条件，本次未做任何测量。

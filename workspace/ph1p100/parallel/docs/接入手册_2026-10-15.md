## 1. FPGA 侧

### 1.1 三种预处理：接测试台（最省事的接入点）

**端口契约（提案，接之前先确认一次）**

```systemverilog
module image_algo_dut #(parameter W = 16, parameter H = 12) (
    input  wire       clk, rst_n,
    input  wire       start,            // 单周期脉冲：开始一帧
    input  wire [9:0] raw_in,           // RAW10 样本，行主序，每拍 1 像素
    input  wire       raw_valid,
    input  wire       lut_we,           // HE 的 256x8bit LUT 装载
    input  wire [7:0] lut_addr, lut_data,
    output wire [7:0] y8_out,  output wire y8_valid,
    output wire [7:0] gau_out, output wire gau_valid,
    output wire [7:0] he_out,  output wire he_valid,
    output wire       busy
);
```

**步骤**
1. 把你的 RTL 起名 `image_algo_dut`（或改 TB 的例化名），端口对齐上表。
2. 在 `parallel/algorithms/run_algo_tb.py` 的编译列表里，把 `algo_tb_stub.sv` **换成**你的 RTL 文件。
3. 跑：`python parallel/algorithms/run_algo_tb.py`
   - 期望：`ALGO_TB_PASS pixels=192`；mutant 那一步是**故意注入错误**，它必须 FAIL（用来证明测试台有判别力）。

**语义必须与金参考一致**（不一致就会逐像素对不上）：
- 平均舍入 `(sum + n//2)//n`；8bit 截取是**截断** `>>(BITS-8)`；
- 去马赛克边界用**保色夹取**（夹回图像并保持 CFA 奇偶）；
- 绿色像素的 R/B 方向用**未夹取**的 `(x-1)` 奇偶判定；
- 高斯 `[1 2 1;2 4 2;1 2 1]` + `(sum+8)>>4` + 复制边界；
- HE 用**前帧** CDF-min LUT，首帧恒等，坏帧不发布，4-bank 合并。

### 1.2 帧打包器：实现这些字段

见 `docs/帧与元数据接口合同_2026-10-15.md`。最要紧的三条：
- 128B 小端；`magic="R10F"`；`header_crc32` 计算前**先把该字段清零**；
- `raw_bytes = stride*height`，packed 时 `stride = width/4*5`；`payload_bytes` 32B 对齐；
- CRC32 = IEEE 反射 `0xEDB88320`，init/final xor `0xFFFFFFFF`。
  **可直接沿用你现有的 `gray_frame_pack_guarded.v` 里的 `crc_byte`**——已自动核对一致。

对照向量：`parallel/evidence/frame_contract_20261015/`（8×4 与 64×48，含 hexdump 逐字节锚点）。

### 1.3 闪点受控实验（**需授权，别擅自做**）

- 说明：`docs/闪点受控实验_ROM方案_2026-10-15.md`；RTL：`experiments/tmds_pattern_rom.v`。
- 验证：`python parallel/experiments/run_tmds_pattern_rom.py`（需要 ModelSim）。

## 2. RK 侧

### 2.1 直接拿 C 参考（推荐起点）

`rk/frame_decode.c` 是**可编译、已与 Python 金参考逐字节比对通过**的帧解码参考：

```powershell
D:\MSYS2\mingw64\bin\gcc.exe -O2 -o frame_decode.exe parallel/rk/frame_decode.c
./frame_decode.exe <frame.bin> <out.y8> [out.pgm]
```

它做了：帧头解析 → 三种 CRC 校验 → RAW10 解包 → 3×3 双线性去马赛克（保色夹取）→ Y8。
**退出码**：0=OK，2=格式/CRC 失败，3=用法/IO。移植进内核/用户态时保留这套校验顺序。

跨语言一致性可复跑：
```powershell
python parallel/rk/run_c_cross_check.py     # 期望 C_CROSS_CHECK PASS
```

### 2.2 从真实 RAW dump 到可用帧

```powershell
python parallel/rk/ingest_raw.py --raw <dump.bin> --width 1920 --height 1080 `
    --format packed --phase RGGB --cam A --out parallel/evidence/real_frame_A
```
产出：`frame_camA.bin`（帧合同）+ `preview_y8.pgm/png` + `stats.json`
（含 A/B/C/D 四个 CFA 位置均值、min/max/σ、饱和率——与项目里白平衡统计口径一致）。
支持 `packed / u16le / u16be / raw12packed`。

### 2.3 立体闭环（标定 → 校正 → 匹配 → 深度）

先看现成的**整条流水线自检**（合成真值，深度反算误差 ≤0.7%）：
```powershell
python parallel/rk/run_stereo_pipeline_check.py    # 期望 STEREO_CHECK PASS
```
它示范了完整调用顺序，照它写到实拍数据上即可：
`stereoCalibrate` → `stereoRectify` → `initUndistortRectifyMap`+`remap` → `StereoSGBM` → `reprojectImageTo3D`。

实拍标定用：
```powershell
python parallel/rk/stereo_calib_template.py --left "L*.png" --right "R*.png" --cols 9 --rows 6 --square-mm 25
```

**必记的三个坑**（都是我踩过的）：
1. **右相机在 +X 侧**——放反了视差为负，SGBM 直接失效；
2. 合成/测试纹理**不能有强周期性**，否则块匹配会锁到相邻周期（真值 84px 却测出 111px）；
3. 标定输入要留**观测噪声**（角点检测本来就有 ~0.2px），否则是"精确拟合已知投影"的平凡情形，看不出问题。

## 3. 双方联调

### 3.1 第一件事：PCIe 固定块

```powershell
# FPGA 侧要发的内容（双方用同一份）
python parallel/pcie/first_test_data.py --emit <dir> --seq 1 --bytes 1024 --pattern counter
# RK 侧收到后校验
python parallel/pcie/first_test_data.py --check <收到的 block.bin>
```
块 = 32B 头（magic/version/seq/pattern/length/CRC） + 载荷。五个图样：`counter/prbs31/seeded/zero/ones`。

分包规则与端到端软件通路：
```powershell
python parallel/pcie/tlp_pack_ref.py --selftest      # MPS + 4KiB 不跨越 + 首末 BE
python parallel/pcie/run_e2e_soft_path.py            # 块→TLP→主机重组→校验
```
**注意**：单 DW 请求的 `Last DW BE` 必须为 0（PCIe 基规范），本模型已按此修正。

### 3.2 帧合同是唯一真相

- FPGA 打包、RK 解析都以上面的 128B 合同为准；任何一方改动字段必须**同时**改另一侧与 `frame_contract.py`。
- **压缩字段留给 F2**：`codec_id`/`block_count` 由 BPR1 定义；外层 `payload_bytes` **含** 32B 填充，内层 BPR1 的长度**不含**——RK 解析时按内层长度截断后再解码（详见 `docs/只读复核_接口与语义_2026-10-15.md`）。

### 3.3 量化报告要分开的量

采集/传输（原始 FS、有效帧、拒收/丢帧、RK 成功解码帧、各段 fps 与有效 MB/s）；压缩（原始/含头总字节、`1-S/R`、平均与最差、RAW 回退率）；延迟（各段分别定义测量点，时间基不同不能相减）；同步（测量对象、共同时间基、均值/最大/分位、失锁恢复）；深度（分辨率/fps、标定版本、极线误差、已知距离偏差、无效像素比例）；资源（实际 LUT/DSP/ERAM/PLL 与最终 STA）。

## 4. 三个"别做"

1. **别把软件自检当成硬件通过**——本轨道所有结论都标了证据等级，跨级引用就是造假。
2. **别在没冻结口径前各写各的**——尤其是去马赛克边界（保色夹取）、HE 的 LUT 舍入、帧头的 `payload_bytes`。
3. **别为了过测试放宽约束**——时序/STA 不过就停，这与 B3 文档里的门禁一致。

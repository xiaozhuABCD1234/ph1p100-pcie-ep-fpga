# 并行轨道进展汇总（2026-10-15 第二轮）

> 本条轨道（`parallel/`）的阶段性记录。**全部为离线软件产物**：未改生产 RTL/约束/位流、未访问硬件、未与队友冻结。本轮新增 PCIe 分包参考、RK 侧离线立体、跨模块一致性检查、闪点压力向量、统一回归入口。

## 1. 本轮新增

| 项 | 文件 | 作用 |
|---|---|---|
| PCIe C2H TLP 分包参考 | `pcie/tlp_pack_ref.py` | 给定载荷+地址，算出满足 MPS 与 4KiB 不跨越的 Memory Write TLP 序列（地址/长度/首末 BE/DW），含检查器与负对照 |
| RK 侧帧解码/灰度 | `rk/frame_io.py` | numpy 实现 packed RAW10 解包 + 3×3 双线性去马赛克 + 固定亮度映射；**自检断言与纯 Python 金参考逐像素一致** |
| RK 侧离线立体闭环 | `rk/run_rk_offline.py` | 合成阶梯视差双目 → 灰度 → StereoBM/SGBM → 视差误差 + PNG/JSON |
| 双目标定入口 | `rk/stereo_calib_template.py` | 真实标定板图片标定（需实拍图；本机只验证参数与无图错误路径） |
| 跨模块一致性检查 | `checks/cross_consistency.py` | 相位表/stride/长度对齐/位宽/参考色序/CRC 定义在四个模块间自动比对（含对 RTL 源码注释的真实核对） |
| 闪点压力向量 | `analysis/sparkle_stress.py` | 用 TMDS 模型生成**码级**图样（可 `$readmemh`），并给出每 lane 跳变密度/串行失衡 |
| 统一回归入口 | `run_all.py` | 一条命令跑完本轨全部自检，输出汇总与证据目录 |

## 2. 实测结果

**统一回归：本文件写作时为 12 项（纯软件）/ 14 项（含 2 个 ModelSim 项）全部 PASS**（`python parallel/run_all.py [--with-modelsim]`）。
> 后续状态：现为 **13 / 16 项**（新增 `tmds.known_color`、`b3.rom_serial`），见 `README.md` 与 `TODO.md`。以那里为准。

### 2.1 PCIe 分包

- 6000B @ `0x1F00`、MPS=256 → **24 个 TLP**，检查器 0 错误（含跨页截断：首块恰为 256B 到页边界）。
- 负对照（忽略 4KiB 的实现）在同一检查器下**被拒绝**。
- `addr=0x1002` 起 5 字节 → `first_be=0b1100`、`last_be=0b0111`、`dw=2`（非 DW 对齐起止已验证）。

### 2.2 RK 离线

- **灰度路径一致性**：numpy 去马赛克/亮度 与纯 Python 金参考在**四个相位上逐像素相同**（`frame_io` 自检）。
  → 结论：同一份帧合同向量，FPGA 与 RK 必须得到同一组 Y8；对不上就是实现差异。
- **合成双目**（320×240、`numDisparities=64`、左半真值 16/右半 48，避开中缝与边界统计）：

| 方法 | 有效比例 | bad2 比例 | RMSE |
|---|---:|---:|---:|
| StereoBM | 0.6975 | 0.0007 | 0.849 |
| StereoSGBM | 0.7812 | 0.0000 | 0.013 |

（合成数据，**不是** RK 实机性能，也不是实拍精度。）

### 2.3 跨模块一致性

全部 PASS，含：相位表在 帧合同/三算法/RK 三方一致，并与 `bayer565_capture.v` 的 RTL 注释 `Phase0=RGGB,1=BGGR,2=GRBG,3=GBRG` 一致；stride 公式（packed `w/4*5`、u16 `w*2`）；1920×1080 → `raw_bytes=2,592,000`、32B 对齐后 `2,592,000`；CRC 与现有 FPGA packer 写法一致。

### 2.4 闪点压力（码级）

| 图样 | 单 lane 跳变密度 | 串行失衡峰值 |
|---|---:|---:|
| 项目参考色条 | 0.1571 | 10 |
| 灰阶 ramp(0..255) | 0.4252 | 9 |
| 0x00/0xFF 交替 | 0.1000 | 10 |
| **0xAA/0x55 交替** | **0.4999（最高）** | 2 |
| 强制失衡图样 | 0.1567 | 10 |

**两点结论：**
1. 物理层的主要压力来自**跳变密度**（最高 ≈0.50），项目参考色条只有 ≈0.157——即"简单条纹/色条干净"并不能覆盖最坏数据模式，这与"高对比边缘才出彩点"的现象方向一致。
2. **TMDS 的 DC 平衡把串行失衡压住了**：我构造的"强制失衡"图样也只能到 10，无法人为制造巨大失衡。因此 AC 耦合基线漂移不是主要嫌疑，跳变密度才是。

**注意**：这只是"应发送的码"，**不含 RTL/位流**。要真做受控实验，需要把码流装进 ROM/计数器直接接 `hdmi_tx_phy_wrapper`（绕过加密核），那是一个**新位流**，需另行门禁与板测授权。

## 4. 建议主线采纳的顺序（若要用）

1. **帧合同 + 共享向量**：F1/F3 的输入，成本最低、收益最直接。
2. **三算法金参考**：写 RTL 的线需要它做逐像素验收（注意边界策略待冻结）。
3. **PCIe 分包参考**：F3 发送端的对照，先固定块正确再谈吞吐。
4. **RK 离线脚本**：队友的第一份可运行交付。
5. **闪点压力向量**：仅在决定做物理层受控实验时启用（需新位流授权）。

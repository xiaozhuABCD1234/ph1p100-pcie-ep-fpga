# CMP offer correction interface

All public ports and geometry/RAW/CRC/native AXI contracts are unchanged. The only behavioral RTL difference is a two-bit CMP offer register (valid plus slot). Once an offer is valid, the selected slot is held until cmp_valid&&cmp_ready. A pending offer's slot remains READY, so an ACK cannot free it; its identity/length/CRC/prep/pred arrays cannot be rewritten. Other-slot ACK and real encoder commit are independent.

On a take, only the presented slot changes to READING. An already-READY other slot can refill the offer on the same edge; the just-taken slot is explicitly excluded. A simultaneous commit not visible in pre-edge READY state is selected on the next cycle, with no lost ownership. Common reset clears the offer; no frame-sized memory or external protocol was added.

Source closure: candidate/a1_deflate_core.v and candidate/a1_frame_top.v retain frozen SHA; candidate/dual_aplus_scheduler.sv is the new isolated overlay. fixture/dual_aplus_scheduler_old.sv is the previous actual scheduler renamed only, never a production source. Generated tb_dual_old and tb_dual drive the same real-core/native-DDR reachable CMP matrix. No internal cs/held state is forced. The separate negative control forces only codec packed-input data to flip a byte at a crossing group, proving the existing content/CRC/release checks reject corruption.

The matrix legally creates slot0 READING plus slot1 READY/stalled, then ACK0 and encodes a third source into slot0. It covers reversed slot order, continuous take/refill, actual take+commit, legal ACK+commit, premature same-take ACK rejection, wrong camera/old epoch/wrong sequence ACKs, and two held CMPs blocking RAW. A293-bit assertion covers all CMP fields during stall.

### 4.3 缺陷 F1：marginal 的 LUT6/LUT4 少计 2,221 LUT6 当量

**期望**（TD 的 LUT6 口径）：`LUT6_total = 19,695 + 3,793(logic) + 2,077(ripple) + 144(DRAM_LUT) = 25,709`；`LUT4_equiv_upper = 2×25,709 = 51,418`；`LUT6_headroom = 71,680−25,709 = 45,971`；`LUT4_headroom = 129,024−51,418 = 77,606`。

**实际**（`dual-core-budget.csv` marginal 行）：`LUT6_total=23,488`、`LUT4_equiv_upper=46,976`、`LUT6_headroom=48,192`、`LUT4_headroom=82,048`；`resource-baseline.md` §4.1 写明“LUT6_total 用单链 routed LUT6 + 层次 logic-LUT 增量估算；ripple 走进位链、不按 LUT6 计，故不重复加入”。

**根因**：TD 的 `#lut6` 恒等式已证明 ripple 与 DRAM_LUT 都计入 LUT6 站点（§3.1 三源精确成立）；对第二链的 ripple 2,077 与 DRAM_LUT 144 不计入，导致 marginal LUT6 少 2,221（8.6%）、LUT4 上界少 4,442。开发自己的 CSV notes 已列出 `ripple 2077, dram_lut 144`，说明数据在手，只是没有汇总进 LUT 栏。**该错误不改变 fit 结论**（25,709/71,680=35.9%，51,418/129,024=39.9%，仍远低于器件），但它是规划门槛“LUT/…逐项可手算复核”和“LUT_total 必须注明 TD LUT6 / LUT4”要求下的错误必填值；`LUT4_equiv_upper` 也不再是正确上界。conservative 的 39,390/78,780 是完整 2×，不受影响。

### 6.5 缺陷 F3（system）：第二路 camera/CSI 清单与 routed 层次不符

- b6/b10/b11 三份 `routed_area.rpt` 的 `u_camera` 下都只有 **一个** `u_csi_a`（`mipi_csi2_rx_ph1p`），**没有 `u_csi_b` 层次行**；b10 `u_camera` 行 1,484 logic/505 ripple/2,232 seq/0 ERAM/1 PLL 的闭合也对应“单 CSI + HDMI + cfg_a/b + 其它”，不含第二个 CSI 的 ~773 logic/340 ripple/1,474 seq。
- 源文件 `r0/td/src/f9p_camera_display_core.v` 确实例化了 `u_csi_b`，但其数据输出未形成实际使用路径，routed 报告中未体现其资源；routed 是资源权威，故“已含 A/B 两路 CSI RX”**不被 routed 证据支持**。
- 影响：第二路 CSI RX 的 ERAM 为 0，**marginal 的 ERAM 146/231 不变**；但 if 第二路 camera 需要完整 CSI，marginal 的 logic/seq 至少少 ~773/1,474（另加 camera_a1_uart_top 包装 glue 338 logic/524 ripple/1,721 seq，若复制）；conservative 的 2× 完整链包含一份额外 `u_camera`，资源上界仍覆盖。报告必须把该项列为“复制/未实现/0 ERAM”的真实状态，不能写“已含 2 路、共享”。
- 另：b11 的 0.015 是 `ddr_user` 200 MHz 域，`clk_a1` 187.5 域为 0.059；报告若保留“b11 +0.015 < +0.05”应注明域，避免把跨域 WNS 当成 A+ 187.5 域结论。

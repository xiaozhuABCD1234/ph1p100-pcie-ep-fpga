所以除 **LZ77** 外，我提到的第二个是 **DEFLATE/GZIP（标准流/兼容格式）**。严格说：**DEFLATE 不是另一种“匹配算法”，它就是 LZ77 + Huffman 熵编码 + 标准容器**；GZIP 是 DEFLATE 外层封装。把两者并列时，真正的区别是“**私有自描述流**”还是“**标准 DEFLATE/GZIP 流**”。

补充（避免记忆混淆）：项目任务板 T04/T10 的历史记录里还有 **BPR1（Bayer 同色预测 + 有界 Rice）**——那是更早的候选路线，后来用户口径改为“LZ77 合规基线 + Bayer 优化，BPR1 转可选第二模式”。它不是我在上一条里说的“另一个”；但它是本项目里真实存在的第三个构件，本文会把它作为组合项之一评估。

## 3. 构件清单

| 构件 | 作用 | 备注 |
|---|---|---|
| Bayer 可逆预处理 | 相位重排（同色聚拢）+ 可选同色预测（A/B 开关） | 提升 LZ77 匹配率/Rice 残差集中度；可逆 |
| LZ77 匹配/字典 | 消除重复串（行/块间相关性） | 32 KB 窗口约 13 行；Bayer 重排后更有用 |
| DEFLATE/GZIP | LZ77 + fixed/dynamic Huffman + 标准容器 | zlib 可独立解码；合规性最好 |
| 有界 Rice（BPR1） | 同色预测残差 + 有界 Rice 编码 | 比率通常更高；私有格式，需自研解码 |
| RAW 回退 | 块级退回原长（或 DEFLATE stored block） | 最坏膨胀可控；stored block 仍保持标准流 |
| 颜色变换（可选） | 可逆 YCoCg/绿红蓝差 | 去相关，但增加可逆性与验证成本；本项目 RAW10 下优先级低于同色预测 |

## 4. 现提案 + 三个组合

### P0（现提案，格式未定）
**Bayer（A/B）→ LZ77 匹配/字典 → 固定/动态 Huffman/位打包 → 块级 RAW 回退**；输出“自描述或 DEFLATE/GZIP 兼容”二选一未定。

### 组合 A（标准兼容两级，推荐起步）
**Bayer 相位置排 + 可选同色预测（A/B）→ LZ77 + DEFLATE（fixed/dynamic Huffman）→ 整帧合法 zlib/gzip 流；块级 RAW 回退用 DEFLATE stored blocks（整帧仍是合法标准流）**。

### 组合 B（比率优先，BPR1/Rice 为主）
**Bayer 同色预测（BPR1 风格）→ 有界 Rice → 块级 RAW 回退**；LZ77 仅作为可选第二模式（自描述容器）。这是把历史 BPR1 重新扶正，但不作为唯一模式。

### 组合 C（自适应双引擎，上限最高）
**Bayer 预处理 → 统一块容器 + 块级模式选择 {LZ77+Huffman（deflate 子流）, 有界 Rice, RAW/stored}**；自描述容器 + 每块模式位；可提供“合规模式”只使用 LZ77/stored 子集。即 P0/A 与 B 的“多级管线 + 块级择优”。

## 6. 推荐

**推荐：组合 A 起步，容器按组合 C 的方式预留 Rice 第二模式位（“A+ 路线”）。**

理由：
1. **先把合规基线做出来**：组合 A 的整帧是合法 DEFLATE/GZIP 流（RAW 回退用 stored blocks 仍合法），zlib 可独立解码，规则风险最低；这符合你此前“LZ77 合规基线”的口径。
2. **比率有提升空间**：Bayer 相位重排 + 同色预测（A/B 开关）能把 LZ77 的匹配率拉起来；若实测比率不满意，再在统一容器里加 Rice 第二模式（组合 C 的扩展），而不是推翻重来。
3. **成本/进度可控**：BPR1/Rice 单独做主方案（组合 B）虽然有比率优势，但私有格式的规则接受风险最大，且与你已选的 LZ77 合规基线冲突；一上来做双引擎（组合 C）在当前时间窗内验证成本最高，容易拖累 T11 集成。
4. **不推荐项**：
   - **B 单独作为主方案**：规则接受不确定 + 自研解码独立性弱；只适合作为第二模式/扩展。
   - **C 一步到位**：资源与时序更紧（叠加后 LUT ~43–53k、ERAM ~212–224），双引擎+选择器+双解码的验收集合最大，当前进度下风险不划算。
   - **P0 继续“格式二选一未定”**：会直接造成返工；建议按 A 冻结“标准流优先”。

**一句话**：不是“LZ77 还是 Rice”二选一，而是 **“标准 DEFLATE（LZ77+Huffman）做主路径 + Bayer 可逆预处理提比率 + stored-block RAW 回退保底 + 容器预留 Rice 第二模式”**。

### S-2 跨源 ownership（源 descriptor 发送期间不被 writer 覆盖）——**FAIL（F1）**

**结论：冻结 RTL 中，相机 B 路的“发布即保护 + 唯一 release”所有权契约不成立；A 路 release 还会误清 B 路保护位。**

静态机制（对冻结文件逐行核对）：

1. `ddr_frame_pusher.v`：`par_valid = (ddr_base==BASE0)||(ddr_base==BASE1)`、`par_now = (ddr_base==BASE0)?0:1`；release 只在 `claimed_par_v = (!src_sel)&&par_valid&&push_en` 为真（ACK/CANCEL）或 pass 分支 `push_en&&!src_sel&&par_valid` 时产生（L378–387、L643–673、L709–757、L872–903）。
2. 顶层给 pusher 的 `BASE0/BASE1` 参数是 **A 路基址** `0x0010_0000/0x0090_0000`（top L109–112、L1681–1689），而 `ddr_base` 按 `cam_sel` mux：B 路实值为 `0x0110_0000/0x0190_0000`（top L299–301）。
   ⇒ 相机 B 时 `par_valid=0`、`claimed_par_v=0`、pass 分支也被抑制：**B 路已发布帧（无论被 claim 还是 pass）永远不会收到 release**，同时 `claimed_par` 被错算为 1。
3. `cam_ddr_writer.v` 的 `protect0/1` 在发布时置位（L851–855），仅由 `rel0_evt/rel1_evt` 清除（L762–763），写者**无相机身份**；而两根 release toggle 被 A/B 两片写者共享（top L1530–1531、L1589–1590）。⇒ **A 路每个 release 都会顺带清掉 B 路同索引块的保护位**（错误释放），B 路的“读窗口/写窗口互斥”论证失去依据。

定向仿真（本维度独立实现，不调用生产 TB 的判据）：`system-r0-evidence-t07/tb_t07_src_release_probe.v`，DUT 参数与顶层完全一致；用 `probe_run.ps1`（临时 ASCII subst + 与交付入口相同的 `compile_checked.f`）跑 ModelSim 10.5b，结果 `probe-vsim.log`：

| 用例 | ddr_base | 结果 |
|---|---|---|
| A 路对照（cam_sel=0） | `0x00100000` | claim→64 笔 MWr→门铃→HELD→匹配 ACK 全通过；release 共 2 次（未 ARM 发布帧的 pass-release 1 次 + ACK-release 1 次）⇒ “每发布帧恰好 1 次 release”成立 |
| **B 路（cam_sel=1）** | `0x01100000` | claim→64 笔 MWr→门铃→HELD→匹配 ACK 全通过（`st_err=0`），但 **rel0_cnt=0、rel1_cnt=0：全程零 release** |

即：B 路候选接口（CTRL bit8、RK 补丁 `ANLOGIC_CTRL_ARM_BITS_B=0x161`）虽然有正式入口，但**推完并 ACK 后源块不会被放行**；结合第 3 点共享 toggle，B 路发布块还可能在未 release 时被重写。这直接违反任务条目“源 descriptor 在发送期间不被 writer 覆盖；实现明确锁定/释放/CDC 握手”与 `change-report.md` §2 的“每个发布帧给且只给一个 release……读窗口与写窗口天然互斥”（该论证仅对单相机 A 成立）。A 路单相机路径自洽，故这是**跨源**缺陷。

影响：B 路正式 one-shot 推帧无法持续推进（claim 后保护位得不到对应释放）；A 路运行期间 B 路保护被错误清除（可能的并发覆写窗口）。修法与证据建议（供原规划者派发）：把 release 判定改为相机感知（per-camera base 比较/独立 release 通道，或写者按相机区分 protect），并补 B 路与 A/B 交叉场景 TB 后重新冻 manifest。

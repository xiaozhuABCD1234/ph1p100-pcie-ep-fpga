## 2. 主缺陷：默认 G1 入口在文档化调用下确定性中止（fail）

- **进程退出码为 0**（`-File` 下该 .NET 异常的传播方式所致；实测“exit 0”并不代表运行成功——判据必须是 `run.do`/`vsim.log`/完成标记，见 `independent/t9_flow_probe_result.txt`）。

**机制（独立验证链，全部可复跑）**：

1. 冻结 `run_sim.ps1` = UTF-8 **无 BOM**、**LF-only**（144 LF、0 CR）、含中文注释（SHA=`33399210…`，与 manifest 一致）。
2. Windows PowerShell 5.1 按 ANSI（ACP=936）解码该文件；.NET CP936 解码器把**行尾悬挂的首字节**连同其后的 LF 一并吞掉：`[Encoding]::GetEncoding(936).GetString()` 得 136 LF vs 真实 144（**吞 8 个换行**）；`Get-Content` 同样 136 行；`Parser::ParseFile` 视图里 `WriteAllLines` 位于第 116 行（源文件为 124 行）。逐行 diff 证据：`independent/cp936_view_analysis.txt`、`independent/t4_cp936_view.txt`。
3. 被吞的换行之一恰好把中文注释行（源 122 行）与 **`$doPath = Join-Path $outDirF "run.do"`（源 123 行）** 合并成一行注释 ⇒ `$doPath` 永不赋值。对脚本拷贝做字节级注入调试（ASCII 行，不改冻结文件）实跑：**`DBG doPathNull=True doPath=[]`** ⇒ `WriteAllLines($null)` 报“空路径名是非法的”（`msim-entry-repro/tb_inject/commands.log`）。

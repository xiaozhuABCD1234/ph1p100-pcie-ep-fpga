# FPGA ↔ RK 非压缩帧 / 元数据接口合同（草案）

> 记录日期：2026-10-15。**这是并行推进的接口工作：只定义非压缩帧头 + 载荷 + 传输契约，新增软件参考与共享向量，未改动生产 RTL/约束/位流，未下载硬件。** 状态是**提案**，需与队友冻结后才生效。证据等级：标准/代码事实 + 本轮软件自检；未做任何一侧的真实联调。

## 1. 目的与边界

- **目的**：把导师复核指出的接口空项（分辨率/stride/字节序/Bayer 相位/DMA 所有权/CRC 口径）落成**可实现、可逐字节对照**的固定布局，并给出**共享合成向量**，让 FPGA 侧打包与 RK 侧解析在联调前就能独立对齐。
- **本模块负责**：非压缩帧头、RAW10 载荷布局、CRC 定义、传输/缓冲契约、共享向量。
- **本模块不负责（留给 F2）**：压缩码流的 `codec_id` 取值、分块/字典/RAW 回退标记、块表与位流规则。帧头里保留 `codec_id`、`block_count` 两个占位字段；非压缩时 `codec_id=0`、`block_count=1`。
- 与既有草案一致：帧头沿用[整链路方案](../../docs/双目首版_整链路方案与团队交付.md)§6 的「128B、小端、保留清零」；字段命名对齐 D 盘旧草案 `interface_v1.md`（**不修改**该草案，本文作为可实现的细化）。

## 2. 总体约定

- 字节序：**小端（little-endian）**。
- 帧头固定 **128 字节**，`header_bytes` 字段自描述。
- 一个传输单元 = **帧头(128B) + 载荷**；帧头紧接载荷，`payload_bytes` 给出载荷实际长度（含 32B 对齐填充）。
- `raw_bytes` 只含**有效图像字节**（不含对齐填充）；两个 CRC 分别覆盖有效载荷与含填充载荷。
- 采集/处理两层约定（对齐[策略指引](../../docs/superpowers/plans/2026-10-15-fpga-remaining-strategy.md)§3）：本帧格式即「入口/缓存层」；处理层的 10bit 样本流由 `format_id`/`packing` 派生。

## 3. 帧头（128B，小端）

| 偏移 | 字段 | 类型/大小 | 含义 |
|---|---|---|---|
| 0x00 | `magic` | 4B ASCII | 固定 `"R10F"` |
| 0x04 | `version_major` | u16 | 主版本 = 1 |
| 0x06 | `version_minor` | u16 | 次版本 = 0 |
| 0x08 | `header_bytes` | u16 | = 128 |
| 0x0A | `camera_id` | u8 | 0=A，1=B |
| 0x0B | `format_id` | u8 | 0=RAW10 packed，1=RAW10 u16le，2=GRAY8，3=RGB565 |
| 0x0C | `codec_id` | u32 | **F2 负责**；0=无压缩 |
| 0x10 | `session_id` | u32 | 一次联合启动的会话号 |
| 0x14 | `capture_seq` | u32 | 每路采集序号（含随后失效/丢弃的帧） |
| 0x18 | `mode_id` | u32 | 相机/处理模式版本 |
| 0x1C | `width` | u16 | 有效宽（像素） |
| 0x1E | `height` | u16 | 有效高（行） |
| 0x20 | `stride_bytes` | u32 | 每行字节数（见 §4） |
| 0x24 | `roi_x` | u16 | ROI 起点列 |
| 0x26 | `roi_y` | u16 | ROI 起点行 |
| 0x28 | `bayer_phase` | u8 | 0=RGGB，1=BGGR，2=GRBG，3=GBRG（按**接收像素/行顺序**） |
| 0x29 | `bayer_dir` | u8 | bit0=X 镜像，bit1=Y 翻转 |
| 0x2A | `valid_bits` | u8 | = 10 |
| 0x2B | `packing` | u8 | 0=packed，1=u16 |
| 0x2C | `raw_bytes` | u32 | 有效图像字节数（不含填充） |
| 0x30 | `payload_bytes` | u32 | 载荷实际字节数（含 32B 对齐填充） |
| 0x34 | `block_count` | u32 | **F2 用于分块**；非压缩 = 1 |
| 0x38 | `exposure_code` | u32 | 曝光寄存器/值版本 |
| 0x3C | `gain_code` | u32 | 增益寄存器/值版本 |
| 0x40 | `sof_timestamp` | u64 | 采集 SOF 时间戳（tick） |
| 0x48 | `timestamp_hz` | u32 | 时间戳频率（Hz） |
| 0x4C | `flags` | u32 | 见 §5 |
| 0x50 | `raw_crc32` | u32 | 覆盖 `payload[0:raw_bytes]` |
| 0x54 | `payload_crc32` | u32 | 覆盖 `payload[0:payload_bytes]` |
| 0x58 | `header_crc32` | u32 | 覆盖整个 128B 帧头（本字段置 0 后计算） |
| 0x5C | `reserved` | 36B | 必须为 0 |

## 4. 载荷布局与 stride

- **RAW10 packed（`format_id=0`，MIPI CSI-2 打包）**：每 4 个 10bit 样本 → 5 字节：
  `P0[9:2] P1[9:2] P2[9:2] P3[9:2] {P3[1:0],P2[1:0],P1[1:0],P0[1:0]}`。
  要求 `width % 4 == 0`；`stride_bytes = width/4*5`（1920 → 2400B/行）。
- **RAW10 unpacked（`format_id=1`）**：每样本 u16 LE；`stride_bytes = width*2`。
- GRAY8：`stride_bytes = width`；RGB565：`stride_bytes = width*2`。
- 载荷总长 `raw_bytes = stride_bytes * height`；`payload_bytes = ceil(raw_bytes/32)*32`，填充字节为 0。

## 5. flags 位定义

| 位 | 名称 | 含义 |
|---|---|---|
| 0 | `BAD` | 帧被拒/中止（不得进入下游） |
| 1 | `CROPPED` | 使用了 ROI 裁剪 |
| 2 | `PARTIAL` | 载荷不完整 |
| 3 | `OVERSIZE` | 超过缓冲容量，已丢 |

## 6. 传输 / 缓冲契约（草案）

- 方向：FPGA 作 requester 发 **C2H Memory Write** 到 RK 驱动分配的 DMA 缓冲；BAR 只做控制/状态。
- 缓冲：主机用 Linux DMA API 提供 `dma_addr`、`capacity_bytes`、`cookie`；FPGA 校验地址宽度与容量，越界拒绝并置 `OVERSIZE`。
- 提交：一次一个连续 DMA 块，`header + payload` 连写；按 MPS 与 4KiB 边界分 TLP、处理尾字节（细节属 **F3**）。
- 所有权：缓冲在「完成通知被主机确认」前不得复用；完成信息不得先于数据可见。
- 这里的字段/单位用于双方对齐；具体 TLP/中断/复位策略以 F3 为准，本文不替代。

## 7. CRC 定义

- 算法：**IEEE 反射 CRC32，poly `0xEDB88320`，init/final xor `0xFFFFFFFF`**。
- 标准检查值：对 ASCII `"123456789"` 结果为 **`0xCBF43926`**（本轮已验证）。
- `header_crc32` 计算前先把该字段清零。
- **与现有 FPGA 打包器一致性（静态核对）**：`gray_frame_pack_guarded.v` / `ddr_display_read.v` 的 `crc_byte` 为 `v=c^b; 8×(v=(v>>1)^(v[0]?0xEDB88320:0))`，init `0xFFFFFFFF`、末取反——**与本合同定义逐位一致**（已用逐位复刻与 zlib 在 6 组样本上比对通过）。因此 FPGA 现成 packer 的 CRC 可直接沿用，不需要换算法。

### 8×4 packed 帧的逐字节对照锚点

帧头（前 96B）与载荷开头：

```text
0000  52 31 30 46 01 00 00 00 80 00 00 00 00 00 00 00  R10F............   magic/ver/header_bytes/codec
0010  01 00 00 00 01 00 00 00 01 00 00 00 08 00 04 00  ................   session=1 seq=1 mode=1 w=8 h=4
0020  0A 00 00 00 00 00 00 00 00 00 0A 00 28 00 00 00  ............(...   stride=10 valid_bits=10 raw=40
0030  40 00 00 00 01 00 00 00 00 00 00 00 00 00 00 00  @...............   payload=64 block=1
0050  E6 D2 7D 2D 2E 96 00 42 86 59 7C 25 00 00 00 00  ..}-...B.Y|%....   raw/payload/header CRC
0080  00 00 01 02 6C 03 03 04 FF EC 01 02 02 03 B1 04  ....l...........   载荷前 16B（row0 = 0,3,6,9,12,15,18,1023）
```

关键像素（合成规则 `value=(3x+5y)&0x3FF`，再置角点 0/1023/512/1）：
`px[0]=0, px[7]=1023, px[24]=512, px[31]=1`；首行 `[0,3,6,9,12,15,18,1023]`。
CRC：`raw_crc32=0x2D7DD2E6`、`payload_crc32=0x4200962E`、`header_crc32=0x257C5986`。

（这些数值来自合成图样，RK 侧解析后应逐样本一致；FPGA 侧打包同样的样也应得到同样的载荷字节。）

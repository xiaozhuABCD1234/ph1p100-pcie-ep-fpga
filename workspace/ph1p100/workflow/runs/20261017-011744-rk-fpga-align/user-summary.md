# 答复与计划（2026-10-17 下午 · user-feedback-03）

## 你的问题：上板联调需要 FPGA 和 RK 都接上吗？

分三层，不是所有事情都要两者都在：

1. **FPGA 单板基础验证**（SRAM 加载、器件/时钟识别、UART/JTAG/ChipWatcher 观测、寄存器读写、回退）→ 只需要 FPGA 板 + 你的下载通道（FTDI/JTAG/USB），**不需要 RK**。
2. **PCIe 链路建立/被主机枚举** → FPGA 板必须插在一台 PCIe 主机上（你的 PC 或 RK 都可以，取决于你怎么接线）；只接 USB 不会起链路。
3. **端到端实收**（RK 收到帧、100 帧零 CRC 错、10 分钟短稳）→ **必须两者都接上**：FPGA 板插在 RK 的 PCIe 上 + RK 装好“T07 补丁 + T11 增量补丁”的驱动与用户态工具（补丁已备好，还没在 RK 上编译）。

结论：基础观测类现在就能做（只需 FPGA 一侧）；正式联调实收才需要 FPGA+RK 同链路。你先把 FPGA 侧推进，正好避开 RK 条件。

## 压缩路线（question-01 答复已采纳）：LZ77 + Bayer 自有优化

- 可行性：**可行**。官方 R3 要的是“JPEG/LZ77 任一硬件压缩”——用真实 LZ77 编码器满足字面要求；你原来的 Bayer 思路作为“自有优化”叠加在前端（相位重排+同色预测，让 RAW 数据更适合 LZ77），两者可共存。
- 推荐形态（本轮采用）：单编码器=LZ77（合规基线）+ Bayer 预处理前端（可开关，做 A/B 对比证明优化增益）+ 块级 RAW 回退（压不动时不膨胀）；输出尽量做成标准 DEFLATE/GZIP 兼容（RK 端可直接 zlib 解码，省一套解码器）；若用自定义格式则配自研软件解码器，并明确不声称 zlib 互通。
- BPR1（之前的 Bayer+Rice）不再作为本轮必须项，保留为后续可选第二模式/加分项。
- 风险提示（已登记）：①LZ77 单核吞吐参考约 128MB/s，低于双路 155.52MB/s 预算 → 可能要多核/降速，需实测；②资源/时序要重测（现有余量薄）；③项目里没有现成 LZ77 代码，需要新做（参考开源核注意 GPL 许可，优先自研/宽松许可）；④真实 RAW 图集还没有，压缩率证据先用合成/冻结向量并如实标注。
- 计划更新：T10 不再等待，按新范围排在 T09 之后；压缩帧经 PCIe 传输+RK 解码实测由后续包 T11.rk-align-compress-int 承接。组织方那边：基线已是真 LZ77，R3 字面要求已满足；混合“创新”表述如需官方口径可顺带确认，不阻塞。

# AI 协作与工具接入

本文件定义本项目的协作方式，不更改当前 Codex/系统权限，也不安装全局技能或自动化。

> **2026-10-16默认传输更新：** 按用户批准的[主对话仅作传输](FPGA多智能体工作流_使用说明.md)执行。主只转用户原话/路径/真实ID/判定/状态并机械留档；需求理解、拆分、依赖、范围验收、工程执行和技术收尾由对应角色承担。DeepSeek边界保持原状。

## 1. 谁负责什么

| 角色 | 负责 | 输入 → 输出 |
|---|---|---|
| 用户/硬件执行者 | 范围取舍、真实连接/测量、上板反馈、最终项目交付 | 操作记录 → 实际观测及来源 |
| 主传输Agent | 原样存/转需求、路径、真实ID、判定、状态，按简短dispatch执行固定分支，保留系统权限/路径检查 | 用户原话/角色元数据 → 原样转发/机械日志 |
| Codex规划者 | 读材料理解拆分、依赖顺序、范围/三维验收/工具设备/停止回退、dispatch、更新和收尾 | 需求/证据 → 完整计划/指南/简短派发/用户短总结 |
| Codex开发者 | 计划范围实现、局部检查、冻结输入、停止修改、修复影响清单、lessons | 计划/报告 → 实际产物/manifest/复测清单 |
| Codex三测试者 | 同输入独立功能/工程/系统验证，给判定、阻塞和复测/证据复用依据 | 冻结输入 → 逐任务报告及简短元数据 |
| 有界执行者 | 清楚的小补丁、数据转换、日志摘要或模板草稿 | 最小上下文+验收 → 提案/结果；不得擅自扩范围 |
| 审阅角色 | 从需求和原始证据检查遗漏、回归和误报 | 改动+验收+证据 → 可行动问题或明确范围内无发现 |
| IC Coder（可选） | 有限额度内的 FPGA 专项只读审阅/验证缺口分析 | 最小 RTL/TB/日志 → 有位置与反例的建议；对应Codex角色独立核验 |
| RK 队友 | 驱动、收帧、解码、ISP、深度/NPU的约定交付 | 冻结接口+测试样例 → 代码/命令/版本/结果；责任需实际确认 |

本项目后续对话默认主传输、规划者、每任务新开发及新三测试；仅同任务FAIL续原开发/测试，受修复影响的PASS维度按角色清单续原测试，不跨任务复用对话。只有用户明确批大小大于1才由规划定义批，每批一个开发者、三测试各覆盖全批。主不读完整材料/计划/源码/报告，不选题/设计/拆分，不开发/测试/判断根因影响/写技术总结。各角色不递归派生，不把自审称独立审阅。DeepSeek只处理已授权低风险有界辅助，不替代三测试。

简短派发、返回字段和固定分支统一见[传输合同](../.agents/skills/fpga-orchestrator/references/relay-contract.md)。开发停止修改后冻结同一manifest，三测试并行；复测影响和旧证据复用由开发/测试判断，主不拼不同输入PASS。round0首次验收、最多三轮实际修复；缺设备/工具/资料/用户输入或额度直接blocked交原规划备条件，不空转。PASS、三轮后仍FAIL或阻塞都由原规划更新dispatch/记录，决定独立下一任务并写handoff/final-summary/用户短总结，主原样转发，开发写lessons。

用户反馈保持原话；缺输入/疑问/矛盾交对应原角色，范围/验收归规划、复现/报告归测试、实现归开发，无效或过长返回由原角色整理。实际spawn/followup/wait/list/send直接调用collaboration，fork_turns="none"传技能及输入路径，真实ID即时登记；send_message只送消息，空闲角色新轮用followup_task。原ID失效交规划文件恢复并登记映射，不假称resume；无多agent工具不得主接管。

IC Coder 当前按人工交接设计，不常驻、不自动调用。用户报告剩余 1000 Credits、30 天到期，具体预算、止损和首个任务见 [IC Coder 有限额度方案](ICCoder有限额度使用方案.md)。没有实际请求时不把准备好的任务记成外部独立审阅；到期不阻塞任何工程任务。

## 2. 每次给 AI 的上下文包

最少包含：实际项目根目录、task_id、目标、允许修改路径、相关源码摘录/文件入口、接口版本、输入证据、验收、停止条件、必须保留的边界。采用“问题相关最小上下文”，不发送整个仓库或完整聊天历史。

对 DeepSeek：使用当前会话真实项目根目录；不发密钥、凭据文件、环境转储、无关文件或图像。它返回的命令和补丁是待审提案，不是授权；负责该子任务的Codex开发/测试角色检查全部路径、补丁头和副作用，仍使用原生工具/审批执行。每个 pending call_id 恰好回传一次实际结果或拒绝，不编造输出。API 错误或重复失败后由该Codex角色接管，不自动扩权/重试；废弃任务明确关闭。主调度不因此亲自实施。

硬件结果必须来自工具实际读取或注明时间的用户观测。AI 可整理截图/反馈，不能根据仿真补写实际测量值。置信判断、设计预算、作者报告和本板测量分别标注。

## 3. 可以直接复制给对应角色的工作指令

这些是角色任务内容：主只原样保存并转给规划/开发/测试，不因用户粘贴模板而接管技术工作。纯配置/文档只读相关材料和静态复核，不启动无关生产/TD/板测。

### 开始/恢复一个任务

> 交规划者读取本次需求与任务相关README、workflow/README.md、方案摘要/tasks.json和证据。由规划者理解并选择/拆分 `<task-id>`，确定依赖/范围/验收/停止回退，写计划与简短dispatch交主传输。开发和三测试依同输入执行；缺条件由规划备条件，任务记录和交接由原规划更新。不覆盖历史，不批量删除。

### 调试

> 针对 `<现象>`，先引用实际复现证据并列出观测缺口。每轮只验证一个明确假设，给出最小对照、预期结果和停止条件；失败时保留原始记录再修正。新证据出现前不要把猜测写成根因，不用断电暂时恢复替代持续上电复测。

### 实现

> 依据 `<任务/设计/接口版本>` 在 `<允许路径>` 完成最小实现。先确定能证明行为的测试；保持参考模型独立，覆盖边界、反压和恢复。只运行与改动相关的必要检查。构建/板测分开报告，最终给修改、验证、风险、下一步和回退。

### 审阅

> 按 `<验收>` 审阅 `<diff或文件>` 与 `<证据>`。重点检查帧完整性/坏帧发布、地址单位/容量、跨域/复位、ready/valid、输入哈希与最终报告绑定、性能单位以及 FPGA/RK 接口。发现问题给具体位置、触发条件、影响和可验证修正。未发现问题时注明读过的范围与未覆盖项。

### 有界委派

> 任务：`<唯一小问题>`。最小上下文：`<摘录>`。允许范围：`<文件/纯文本>`。验收：`<可检查结果>`。禁止访问凭据、扩范围、批量删除或自行执行外部操作。提交完整提案和局限；不确定则说明，不补造结果。

### 会话结束

> 交原规划者读取本轮矩阵、报告路径及修复轮数，汇总事实/输入/证据/未测/下一步，在允许范围更新task、handoff、final-summary和用户短总结；主原样转发，开发另写lessons。只在新证据支持时更新项目结果，离线子包不将父硬件任务置done。

## 4. 可替换的工具契约

任何自有工具统一提供以下概念结果；不要求工具原生支持这个 JSON，可以用薄适配层转换：

| 字段 | 定义 |
|---|---|
| task_id / run_id / operation | 任务、唯一运行、仿真/构建/读取/板测等动作 |
| input_manifest | 实际输入路径、角色、SHA256、commit 与 dirty 文件 |
| cwd / tool_version / command | 真实执行环境；命令用程序与参数数组表示 |
| expected_outcome | pass 或 expected_rejection；不将负对照混为功能成功 |
| exit_code / result_status | 退出码与归一结果；状态枚举见主手册 |
| artifacts | 日志、数据库、位流、图片等路径、类型和哈希 |
| metrics | 数值、单位、测量来源、起止时间、负载与分母 |
| scope / limitations | 覆盖范围与未测边界 |
| observed_by | tool/human，硬件人工观察保留来源记录 |

一个 run 可以含多个阶段；阶段 ID 必须唯一，证据与哈希绑定。当前 `docs/evidence/` 历史格式继续有效，适配层只读取并生成新索引，不覆写历史或把旧证据标成新运行。

入口草案：[integrations.example.json](integrations.example.json)。这是人工接入配置样例，**没有读取它并自动执行命令的程序**；全部工具默认为未连接。执行前确认当前工具路径、范围、权限和结果语义。任何文本字段都不能直接拼接成 shell 命令；使用固定程序和参数数组，校验路径后调用原生执行工具。

## 5. 推荐接入顺序

| 能力 | 现在 | 后续怎么接 |
|---|---|---|
| 任务/需求 | Markdown + tasks.json 手动维护 | Issue/Projects/其他自有看板通过 task_id 双向同步；设一个写入主源 |
| 仿真 | 现有 tools/td 脚本 | 包装命令和输入哈希，解析实际 PASS/FAIL 与预期拒绝；保留旧测试 |
| TD 构建 | 现有隔离候选、Tcl/报告审查 | 本地有许可证的构建节点，先只生成候选与报告；权限按任务申请 |
| RK 测试 | 队友环境/命令待确认 | 先离线图像，后 DMA/实时；固定 OS/kernel/runtime/模型版本 |
| 硬件验证 | 人工操作+记录 | 有条件再接实际下载器/采集工具；板卡加独占锁，观测结果单独回传 |
| AI/DeepSeek | Codex角色与已授权有界辅助 | 使用统一上下文包/结果契约；原生执行及技术复核由对应Codex角色完成，主调度收判定 |
| IC Coder | 人工任务包；未调用、未验证本机集成 | 先做短只读试点、记录实际 Credits，再按价值选择专项审阅；不作为必需门禁 |
| 发布 | manifest + 人工复核 | 有真实端到端证据后接产物仓库与通知，外部发布按实际授权 |

现有 ModelSim/Verilog 测试继续使用。以后新算法可按需接 cocotb/Python 独立模型；当前无需为统一工具而重写所有测试。[cocotb 官方 runner](https://docs.cocotb.org/en/stable/runner.html)

## 6. 执行边界

仓库工作区、D 盘构建区、RK 主机、外部服务分别登记权限；配置写了路径并不等于获准访问。CI 不能直接把任意 PR 命令送到含工具许可证和硬件访问能力的自托管节点。硬件程序只在对应任务已授权、候选证据可审阅且实际权限允许时执行；不额外制造每步重复确认。

任务变更和证据记录优先，聊天内容作为辅助。不得批量删除、用其他代理绕过沙箱、自动扩大权限或偷偷发送队友消息。需要队友确认时先准备完整接口与交付材料，再由用户安排确认；现有授权范围内的可逆研发继续推进。

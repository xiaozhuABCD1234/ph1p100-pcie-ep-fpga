# 三维测试报告约定

默认每任务新建三个测试者；同任务FAIL和修复影响才续原测试。只有用户明确批大小大于1时每个测试者覆盖规划批全部任务。每任务一份报告，输出路径为`OUTPUT_DIR/test-reports/<task_id>-r<round>-<dimension>.md`。首轮round=0，修正轮1—3只计实际修复。同一文件只属一个测试者；后续轮次新建，保留失败报告。开发停止修改后，三者独立检查同一manifest。

第一行必须是以下之一，文件中只出现一条该判定标题：

```text
### 判定：PASS
```

```text
### 判定：FAIL
```

PASS/FAIL表示“本任务本维度预先要求的门槛是否满足”。缺设备、未运行和实际失败都不能写PASS，但详细G层结果必须区分`not_run / blocked / fail`，不能误报为DUT被实测判坏。

报告至少写：

- task_id、dimension、round、实际工作树/候选、冻结输入manifest路径及SHA256、工具版本。
- 本任务范围、必需G层和通过阈值；`pass/fail/not_run/blocked/not_applicable`逐层记录。不适用须引用规划时确定的理由。
- 实际命令、工作目录、退出码、完成标记、非空产物及原始证据路径。没有运行的命令明确标为建议，不能放进“实际执行”。
- 触发条件、期望/实际、可复现缺陷、影响范围。测试者不修生产文件，必要验证副本/变异输入独立保存。
- 新旧输入差异、证据复用依据；共享接口/顶层变化必须指出对其他维度的影响。
- 真实硬件观察者/时间/位流身份、未测项、下一动作及回退。纯离线任务说明上板层不适用的范围。

给主的返回仅含[传输合同](relay-contract.md)字段：`task_id、dimension、verdict（PASS/FAIL）、report_path、manifest_path、blocked、retest`。详细缺陷写报告，由原开发读取修复，原规划读取更新/收尾；主只登记元数据，必要时提取首条判定，不读完整报告或判断根因/复测影响。

复测维度/输入变化清单由开发和测试提供；旧证据复用由对应测试者明确依据并绑定当前manifest，不拼不同输入PASS。缺必需设备/工具/资料/用户输入或额度直接blocked交原规划，不空转三轮。过长/无效/缺字段返回由原角色整理；范围/验收疑问交规划，复现/报告归测试，实现归开发。用户反馈保持原话。三轮后仍FAIL保留⚠未通过，由原规划决定独立后续任务。

软件或文档工作包可在自己范围三维PASS，例如功能语义、工程可复现、接口兼容性均满足且G3明确不适用；这不证明RTL、实拍或整机通过。测试台回放stub、软件吞吐、旧位流照片不能分别充当真实DUT、硬件性能或新位流板测。

如果并行测试时发现输入已变，停止引用该次结果，登记漂移并要求重新冻结；不要以旧哈希新日志组装完整通过。最终STA失败、必要CDC问题、帧损坏、DMA越界或无法证明必需门槛，三轮之后也不能强制通过。

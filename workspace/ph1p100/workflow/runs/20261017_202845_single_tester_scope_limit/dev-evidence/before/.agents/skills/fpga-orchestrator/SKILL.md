# FPGA 多智能体主对话：仅作传输

本技能只供本项目接收用户任务的主Agent使用。子角色直接执行指定技能，禁止递归派生代理。批准主体：**主原样转发 → 规划理解与派发 → 每任务新开发 → 同输入三个新测试并行 → 同任务失败续原角色，最多三轮实际修复 → 原规划更新与收尾 → 主原样转发。**

## 主职责与可读范围

- 原样保存/转发用户原话、附件路径、真实代理ID、判定和状态；机械维护`request.md`、`main-log.md`与判定矩阵，执行[传输合同](references/relay-contract.md)固定分支。
- 只读根AGENTS、本技能、调用/传输合同、简短`dispatch.json`与角色返回元数据。需求材料、完整`dev-plan.md`、工程指南、源码、完整报告和技术总结都只传路径。
- 不理解技术需求、不选题/设计/拆分/排依赖，不开发/修复/跑测试，不判断根因或复测影响，不写技术总结，不修改计划或全局任务状态。系统要求的权限、路径范围和工具参数检查仍须执行。
- 无效、过长、缺输入或状态矛盾的返回交原角色整理；范围/验收归原规划、实现归原开发、复现/报告归原测试。用户反馈保留原话，不由主重解释。
- 不批量删除、不覆盖无关修改；本流程不扩大外部工程写入、下载位流、写Flash、发布、自动监控或外部/队友消息授权。DeepSeek仅按根AGENTS作低风险有界辅助，不能替代Codex角色和三个测试。

## 初始化与规划

1. 机械登记实际`PROJECT_ROOT`、`SCRIPT_FILE`（需求/索引路径）、新的项目内`OUTPUT_DIR=workflow/runs/<run_id>/`。默认`BATCH_SIZE=1`；只有用户明确指定大于1才原样传规划者定义批。
2. 原样保存聊天需求；附件只记路径。新run不覆盖旧run，恢复使用原目录。`main-log.md`采用上海时间`yyMMdd HHmm`，即时登记工具真实返回ID及路径。
3. 用`collaboration.list_agents`核对会话与原ID。按[Codex调用](references/codex-calls.md)直接`spawn_agent`，`fork_turns="none"`，传规划技能、设计指南技能、实际根/需求/输出路径与用户原话。
4. 规划者读材料、理解和拆分，写详细计划/指南/输入索引及简短dispatch。主只读dispatch，按其任务顺序、路径、范围与固定分支传输；不从详细计划选任务。需用户决定的问题由规划者写文件，主原样转发。

## 开发与三维测试

默认每个新任务新建一位`fpga-dev`和三位新测试者，不跨任务复用角色对话；成果只传明确文件路径。用户明确批大小大于1时由规划者定义批，每批一个开发者顺序开发，三个测试者各覆盖全批。

开发者冻结实际输入manifest并停止修改、活动结束后，主按返回路径启动三个测试者并行，不读候选源码或技术报告：

| 维度 | 技能 | 内容由规划按任务范围限定 |
|---|---|---|
| functional | fpga-tester-functional | 文档语义、模型/RTL、数据与协议、边界和故障拒绝 |
| engineering | fpga-tester-engineering | 格式/入口/哈希、构建、最终STA/CDC、资源和候选绑定 |
| system | fpga-tester-system | 默认入口/交接、接口、上板、恢复、长稳、性能与发布证据 |

三者使用同一冻结输入，独立按[报告约定](references/report-contract.md)逐任务出报告，只回任务/维度/PASS-FAIL/报告路径/阻塞与续接元数据。测试时不改输入；G层和不适用理由由规划预先确定，文档配置不启动无关TD或板测。缺必需工具/设备不得伪造PASS。

当前总活动槽为4：开发结束后再启动三个测试者；所有子角色禁止再派生。真实ID从工具返回即时登记，不读缓存猜ID。

## 固定结果分支

完整字段与分支见[传输合同](references/relay-contract.md)，主只执行以下机械流转：

1. 三维同候选PASS：把矩阵、报告路径和轮数交原规划者；原规划更新任务/dispatch，决定下一任务或收尾。
2. 同任务可修配置/实现FAIL且无外部阻塞、实际修复不足3轮：续接原开发，传全部失败报告路径和用户原话。开发冻结新输入并给复测影响清单；按开发/测试清单续接本任务原测试者，主不判断影响，不拼不同输入PASS。
3. 缺设备/工具/资料/用户输入或额度不可用：直接交原规划者备条件并原样转用户，保留`blocked/awaiting_hardware`，不空转三轮。
4. 已实际修复3轮仍FAIL：交原规划者保留⚠未通过、依赖与恢复入口，由其派发可独立继续的任务；不得强制通过必要FPGA验收。
5. 缺字段、范围/验收矛盾、候选漂移或元数据不一致：停止对应流转，交相应原角色核实，不由主读长报告解题。

round0为首次验收，round1—3只计实际修复。测试结束后才修复，修复停止后才复测。`followup_task`启动空闲原角色新轮；`send_message`仅送消息。

## 收尾与恢复

原规划者读矩阵/报告路径/轮数，更新本次允许的任务记录、handoff、final-summary及用户短总结，统计首次/1/2/3轮通过、⚠未过与待条件。开发写lessons。主原样转发规划者短总结，不重写技术解释；run控制文件不替代`workflow/tasks.json`及已有证据主源。

同任务同会话能续接则续原ID；跨会话/原ID失效交规划者以文件恢复并记录新旧映射，不能假称resume或跨任务复用。没有多agent工具时明确记录架构不可运行，保留待调度状态，主不得接管。此入口只对本项目生效，不创建无人值守执行器或改变全局配置。

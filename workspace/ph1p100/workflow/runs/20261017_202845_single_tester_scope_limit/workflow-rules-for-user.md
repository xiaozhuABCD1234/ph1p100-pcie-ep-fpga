配置已修改，并由一个与开发独立的综合测试者通过G0/G1静态验收。以下是本项目新的工作流规则正文。

1. **显式启动。** 复用项目内已有的`fpga-orchestrator` Skill，设置`allow_implicit_invocation: false`。普通聊天、报错解释、资料讨论，以及查看、比较、引用或修改工作流规则，都不自动启动这套角色链。只有明确调用这个Skill并要求执行或恢复才启动；仅提到名称、代码示例或选中技能但只要求解释，不算执行。

   新对话在本项目中使用：
   ```text
   $fpga-orchestrator 执行：<本轮明确需求>
   ```
   恢复旧任务使用：
   ```text
   $fpga-orchestrator 恢复：<原run绝对路径>；本轮目标：<目标>
   ```
   从技能选择器明确选择此Skill，再给出执行/恢复指令也可以。已经启动的同一run按原授权继续，中途问状态或讨论规则不另开角色链；明确停止/退出时停止继续派发，并留下恢复入口。

2. **使用项目Skill。** 这次需要的是可复用规则和明确启动条件，现有项目Skill足够；MCP适合提供真实可调用的工具服务，确有需要时再单独建设。本次没有安装MCP、创建重复编排器或修改全局配置。官方文档确认项目技能位置和关闭隐式调用后仍保留显式调用：[Skill文档](https://learn.chatgpt.com/docs/build-skills)；MCP连接其他系统的工具和信息：[MCP文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)。选择Skill是本次需求的判断，并非MCP不能编排。

3. **固定责任链。** 主Agent原样传输 → 规划Agent理解、有限拆分和派发 → 每任务一个新开发Agent → 开发停止修改并冻结输入 → 一个新综合测试Agent → 原规划更新和收尾 → 主原样展示结果。子角色不递归派生。规划决定范围、顺序、验收和取舍；主不读完整计划/源码/报告，不开发、测试或判断技术根因。

4. **需求和任务有上限。** 默认一轮只做**1个主要可验收目标、最多4个正式工作包、仅“需求→工作包”两级**；ready、blocked及依赖包都计入4包。每包一个主要可观察结果，最多**5项语义实现步骤**。出现两个可独立验收结果、无关接口改动或第6项语义步骤时拆窄；读文件、改一行、同步引用、哈希、跑命令等机械动作不单独建任务或代理。

   超大需求由规划取依赖闭合的最小可交付切片，优先顺序为用户明确优先级、已有依赖、需求出现顺序。余项最多记录**3条后续主题**及原需求路径，不继续展开、不自动续做。无法形成小闭环时，只交一个范围/接口冻结包，不冒充父目标完成。只有用户明确给出本轮新的有限目标数、任务数或层数才覆盖默认值；“全部做完”、合批、时间宽裕均不算。不得用新run、子ID或重命名失败包绕限。

5. **默认批大小为1。** 只有用户明确大于1才由规划定义批，每批一个开发者顺序完成、一个综合测试者覆盖全批。合批不减少正式任务计数，也不绕过任务总数或逐任务修复轮数。新任务不复用上个任务的开发/测试对话；同任务修复续原角色。

6. **一个综合测试者按任务选必要检查。** 功能、工程、系统是同一测试者的三类检查清单，独立性针对开发者。文档/配置查语义、格式、入口、哈希和交接；模型/软件查正反向、边界、可复现性和相关接口；涉及RTL、时钟、IP、存储、地址或板上行为时，保留所需真实DUT、最终STA/CDC/资源、候选绑定、真实硬件、恢复、稳定性和性能门槛。

   适用检查、G层、阈值及不适用理由由规划事先写明。风险增加时先加必要检查或缩小包，不自动增加测试/审阅代理；新增角色须用户明确授权。缺必需条件不能判PASS，也不能为省成本改成不适用。开发停止修改后统一测试同一冻结输入，每任务每轮一份综合报告，内部给三维结果。旧三个测试技能保留为按需参考的专业清单，不再单独派发。

7. **主Agent只看返回，不监控进度。** 主只原样保存/转发需求、路径、真实ID、判定和状态，按简短派发及返回元数据执行固定分支；不轮询`list_agents`、不扫描目录/日志、不问进度或催促。等待返回事件单次不超过**60秒**，等待超时本身不触发检查、故障判断或重试。角色失联但没有返回时，不伪造状态或声称平台已自动终止。

8. **子角色自己防循环。** 每次派发/续接默认最多**30次实际工具调用**；规划自我停止预算**15分钟**，开发和综合测试各**45分钟**。单一未决问题最多**3轮有目标的搜索/读取**；同一失败命令最多首次加**1次有新证据或参数纠正的重试**。连续**2次工作循环无进展**，达到预算、缺条件或必须扩范围时，主动停止并返回原因、实际证据、未做项和准确恢复入口。换措辞、记日志、重复同输入不算进展。

   读取/搜索默认deadline **60秒**，局部静态检查/仿真**5分钟**，FPGA构建**30分钟**。启动前必须落实实际超时或可安全停止机制；只停止自己拥有的进程。无法控制就返回blocked，不能把工具的输出等待时间当执行超时。规划可在派发前为必要构建/长稳明确其他有限预算和理由，执行角色不能自行扩预算或范围。以上是角色执行约定，不能保证平台对失联角色强制停止或自动回报；不新建监控Agent、定时任务或常驻执行器。

9. **重复问题最多2次补充机会。** 子角色返回稳定`problem_id`、固定`reason_code`、`new_information`布尔值、证据路径、请求动作和恢复输入路径。主只在收到返回后计数；字段齐备、有新信息且属于原范围补充/整理，才按规则续原责任角色。同一问题最多**2次**，换措辞、转交角色或改轮次都不重置。无新信息、字段缺失/矛盾或到上限，交原规划blocked/备条件，不继续往返。到限后须真实新增用户输入或条件变化才可明确恢复。工具、设备、资料、权限、API/额度等外部阻塞直接备条件，不走机会循环，不自动重试或扩权。

10. **补充机会与实现修复分账。** `round0`是首次独立验收；真实实现FAIL最多`round1—3`三轮实际修复，续本任务原开发/原综合测试。失败及受影响项复测；未影响证据由综合测试者明确绑定新manifest，不能拼不同输入PASS。外部阻塞不空转三轮，三轮后仍FAIL保持未通过，由原规划安排本轮范围内可独立继续的任务。不得把实现修复改称“回答机会”绕三轮，也不得借修复轮继续已耗尽的重复问题。

11. **恢复与作用范围。** 同会话原ID有效就续原ID；新对话或工具实际报告ID失效时，由规划读取原run计划、交接、manifest和报告恢复，并登记真实新旧ID映射，不假称resume。任务状态与G层结果分账，离线子包完成不把父硬件任务置done。规则仅对本项目、且显式启用后的工作流生效；删除禁令、完整DeepSeek约束和其他通用项目约束继续保留。配置不新增外部工程写入、硬件下载/Flash、发布、外部消息或全局配置授权。

本次通过的是配置合同、文件/差异/链接/白名单/哈希绑定及流程静态一致性。尚未实跑客户端选择器加载、普通聊天触发分支或完整工作流；没有进行生产RTL、TD、时序、板测、长稳、MCP服务或发布操作。角色数量减少不承诺具体token节省百分比。

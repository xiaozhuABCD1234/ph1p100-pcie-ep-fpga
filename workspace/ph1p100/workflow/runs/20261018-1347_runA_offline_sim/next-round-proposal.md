# next-round-proposal.md — FPGA 侧验证：可立即开始的方案（面向用户）

依据 `user-input-03.md`（用户原话：“PCIE没接，这个通道先不验证，先严格把验证限制在fpga侧，现在我回来了，能开始干什么”）。
边界：只做 **FPGA 侧**（板 + JTAG/串口线缆，不依赖 RK/PC 主机）；仅 **SRAM**、不写 Flash、不推送；用户在场（可做物理断电/接线/相机确认）。本文件只给方案与建议，不派发、不触硬件。

## 2. 推荐顺序与下一轮范围建议（1 主要目标、≤4 包、batch=1）

**目标**：FPGA 侧读通道成立 + 读到身份/写者基线/CSI 计数（G3 部分）；全程无 PCIe、仅 SRAM、不写 Flash。

1. **P0（离线，可立即开始）**：A0 手册/命令语义核实 + **诊断位流方案冻结**（CWC 探针清单、调试字库地址表、读回流程与判据）。
2. **P1（离线）**：诊断位流 RTL/约束实现 + G1 回归（8 TB + 新 TB 如涉）。
3. **P2（离线）**：**G2 重建**（TD 单会话 ≤30 min）+ 新候选冻结（新 bit 与 `e81d353b…` **并列**：旧候选=回退，不混拼、不删除）。
4. **P3（表单，用户在场）**：SRAM 下载诊断 bit + CWC 读回（身份/基线/计数）；相机确认后（可选）延伸到采集统计 → 为 B2 取证；断电/重上由用户执行。

**bit 影响说明（重要）**：该路径**会换 bit**——读通道只能靠调试核/串口镜像（需重建）；`e81d353b…` 保留为回退（重下即恢复、SRAM 易失、不写 Flash）；新候选需新的 manifest/复测记录，避免与旧候选混拼。若首轮只做 P0，可不换 bit。

## 3. 现在就能做的最小动作

- **我方**：从 P0 开始离线推进（手册核实 + 方案冻结），不触硬件。
- **你（用户）**：①确认是否授权重建“调试诊断位流”并临时替换板上 SRAM 位流；②确认相机是否已接（单 A）；③如遇 DDR 校准异常需断电 10 s 重上，由你执行。

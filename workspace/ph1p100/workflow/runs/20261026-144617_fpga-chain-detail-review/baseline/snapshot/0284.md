### 4.5 R3 sink 分析（不得判 G0）

- 实测导出每帧 2,594,706 B（= `exp_bytes/4`，含 44 B 头）；冻结 sink 为 2 `clk_a1`/B ⇒ 串行导出 5,189,412 cycles = 27.68 ms = 33.33 ms 的 83.0%。

- **生产 sink 需求单列**（不使用 93.75 冒充）：导出流 2,594,706 B/帧 ⇒ **≥77.84 MB/s**（G0，33.33 ms）/**≥103.79 MB/s**（25 ms 稳健）；冻结 TB 上限 93.75 MB/s < 103.79 ⇒ "同内容 + ≥103.79" 的严格实验在本白名单内**不可行**，保持 `not_proven`，交后续（新 TB/导出 RTL/PCIe）。

## 10. 偏差、观察与未测项

### 10.1 非全尺寸预检以 `pass=0` 结束（已披露，不影响判定）

`sim/logs/chk_raw.log` 是开发在 4 个全尺寸 run 之前的 1 帧/2,000,000-cycle 预检，**故意**用远小于所需的 cycle 上限（完整 4 帧需 ~20.5M）来只验证 `CONTENT=2` 的 raw40 加载与 `SS_RAW_MATCH`。因此它按设计撞 `MAX_CYCLES`，打印 `B11_FULL_RESULT pass=0` 并 `$finish`（tb 第 167 行）；它的 `SS_RAW_MATCH bad=0 checked=518400` 在超时**之前**已产生，达到预检目的。该 run 在 manifest/`result-r0.md`/`DIFF.md` 中均标注为"预检（非全尺寸），不计入四轮"，未用于任何 `S_ss` 结论。**观察**：报告正文只写了"预检 86 s"，未明说该 log 内含 `pass=0` 标记；建议后续文档显式写出，以免他人误读为失败 run。**不构成判定缺陷**。

### 10.2 写范围外 1 个只读调试脚本（已披露）

`C:\Users\czz\AppData\Local\Temp\opencode\dbg_comp.py`（653 B，11 行，只 `import pathlib,hashlib,zlib,sys`，无任何写调用，仅打印 comp hex 的 SHA/CRC），mtime 落在本任务窗口内，位于声明的 `write_scope`（`.../T10.ss-4run-matrix/**` 与 `%TEMP%\opencode\ss-4run\**`）之外一层。开发在 manifest `notes` 与 `result-r0.md` §6 主动披露，删除时被环境 `Permission denied` 拒绝。
- 影响评估：不读写候选/内容源/受保护件，不参与证据；受保护 SHA 与内容 SHA 全部复算无漂移。
- 判定处理：记为**已披露的单一非符合项**，不改变 engineering 结论（其余写范围证据 0 例外），但**不是**对 §11.6 "写范围外 0 文件" 的静默豁免——若规划要求绝对口径，这是唯一需记账的条目，且无法通过修复轮消除（删除被环境拒绝）。

### 10.3 测试预算

本轮测试者工具调用约 45 次、墙钟约 55 min，**超出** dev-plan §11.7 的"≤35 calls / 60 min"中的调用数（墙钟在限内）。原因是强制的 1 次全尺寸控制重跑（22 min）+ 首次启动的 `-do` 参数引号缺陷（vsim 在 elaboration 前即报 `vsim-4004` 退出，未产生任何仿真结果，属测试者 harness 问题，非 DUT）+ 覆盖 68 artifacts/内容映射/P1–P3 绑定所需的多次只读核对。该超预算只影响测试者自身资源记账，**不影响**验收结论；已在此披露。

### 10.4 未测/不外推

- 内容：仅合成 C1（grad）/C2（rand）与 P3 comp 代理；无自然图像、低照、噪声、全内容、最坏内容语料。
- sink：93.75 MB/s 是冻结 TB 上限（2 `clk_a1`/B）；生产 sink ≥77.84 / ≥103.79 MB/s **未实现**，`transport=not_proven`；真实 115200 UART 仅 11.52 kB/s。
- DDR：行为级 256-bit 单拍模型，无 MC/刷新/行切换/多客户争用；sustained 未证。
- 实现：单核单路 187.5 MHz；无 TD/综合/布线/时序/资源/bitgen/CWC/下载/Flash/板卡/COM/JTAG/RK；双核共享 PAXI、Routed 时序、资源余量 `unproven`。
- pacing：R2 strict-serial 的差值是上界（含相机串行化），不是纯 tail 成本；生产 slot-free 实现未做 RTL 改动。
- `xform_crc`（C1/C2）未由测试者独立重实现变换，仅核到与开发 `content-map.json` 期望一致；`raw_crc` 已独立复算。R4 的 raw/xform CRC 与 P3 冻结值相等，属跨包独立绑定。
- 结论仅覆盖 P4 声明的 scope；**不**改写 P2 的系统级 headline（`not_proven`），也**不**构成 G2–G4 证据。

# 本轮角色规则摘要（因 .agents/skills 当前缺失而由主机械重建，供本轮子角色使用）

> 说明：本项目 `.agents/skills` 目录在当前工作树中已不存在（路径整理中），角色技能文件不可读。
> 主对话按 AGENTS.md 的既定主体与本轮用户授权重建最小规则摘要，不新增权限、不改变验收门槛。
> 子角色以本文件 + 需求文件为准，禁止递归派生代理，不得尝试恢复/删除项目目录。

## 主体

主原样转发 → 规划理解/有限拆分/派发 → 每任务新开发 → 停止修改并冻结 manifest → 一个独立综合测试者 → 同任务 FAIL 续原开发/原测试（最多三轮实际修复）→ 原规划更新/收尾 → 主原样转发。

## 范围与拆分

1. 本轮 1 个主要可验收目标、最多 4 个正式工作包、两级（需求→工作包），每包最多 5 项语义实现步骤。ready/blocked/依赖包都计入 4 包。
2. 每包一个主要可观察结果。超过边界时选依赖闭合的最小可交付切片，余项最多 3 条后续主题 + 原需求路径，不自动续做。
3. 默认 BATCH_SIZE=1；每包一个新开发、一个新综合测试者，不跨任务复用。同任务修复续原 session。
4. 机械动作（读文件、算哈希、跑命令、归档）不单独建包。

## 综合测试（一个测试者，三维是检查清单）

- functional / engineering / system 由同一个与开发独立的测试者统一核验；规划事先冻结适用项、G 层与门槛，并写明不适用理由。
- RTL/存储/地址/板上行为：所需真实 DUT、STA/CDC/资源、候选绑定；真硬件门槛不得因节约取消。缺工具/设备/资料 → FAIL + blocked，不伪 PASS。
- 每任务每轮一份 `<task_id>-r<round>-integrated.md`，首行唯一判定标题；报告写依据，返回只给元数据。
- 失败与受影响项必须复测；未影响证据由同一测试者绑定当前 manifest 并写明复用依据。不得拼接不同输入的 PASS。

## 修复轮

round0 首次验收；round1—3 最多三轮实际修复。测试结束后才修复，停止修改后才复测。三轮后仍 FAIL 保留 ⚠，由规划决定本轮独立后续。

## 有界执行

- 每次派发/续接默认最多 30 次工具调用；规划 15 分钟，开发/综合测试各 45 分钟。
- 单一未决问题最多 3 轮有目标搜索/读取；同一失败命令最多首次 +1 次有新证据的重试；连续 2 次无进展主动 blocked。
- 读/搜 60 秒 deadline，局部静态/仿真 5 分钟，构建 30 分钟；命令启动前落实可执行超时或安全终止。
- 缺工具/设备/资料/授权/额度直接 blocked，写明原因、已做/未做、最后证据路径、最小下一步与恢复入口。

## 本轮硬件与写域边界（用户原话）

- 生产源码在 `upstream/ph1p100-pcie-ep-fpga` 受控写树内开发；不 fork、不与其它线共享写树、不覆盖未提交改动。
- 0207/0212/2117 历史 run 与旧冻结输入只读；派生新候选，不直接改旧 T11 manifest。
- 不接 PCIe/RK 实机、不改 RK 驱动、不做真实双路、G4 长稳/热态、深度/NPU、发布材料或 C；不推送、不写 Flash、不联系队友。
- 如涉板仅 SRAM；本轮最多 1 次下载，下载前冻结同一候选与完整采样方案。用户当前不在现场，板级步骤默认后置为 awaiting_user/awaiting_hardware，不尝试上板。
- 禁止批量删除；不修改全局配置、不安装工作流、不新建监控。
- 本轮优先做无需用户在场的离线部分（RTL、测试平台、参考解码、真实输入参数与 RAW 样例准备、仿真与静态检查）。

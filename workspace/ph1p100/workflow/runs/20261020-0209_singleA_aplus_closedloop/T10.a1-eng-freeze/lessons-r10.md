# lessons — T10.a1-eng-freeze r10

1. **读地址寄存确实生效，但只是把瓶颈推到下一段**：p3_r 让 r9 的 8 级地址/加法链不再是最大路径，WNS 只动 0.016 ns，因为新瓶颈是 `pos - hent_pos` 减法 + hit/阈值使能（7 级、4 ADDER、5.716 ns）。局部优化要看次临界段，不能只看单条路径。
2. **`pos` 是超扇出寄存器（1062–1224）**：任何以 pos 为起点的运算（+3、-hent_pos、比较）都会带长 net。要真正降 WNS，应先把 pos 派生的量寄存化，而这会改变 S_SCAN 行为契约，属结构性变更。
3. **subst 驱动器是跨脚本全局状态**：跑 run_*_rN.ps1 前必须 `subst W:/X:/Y: /D` 并确认 `subst` 输出为空；脚本内 `subst /D` 失败不会报错，会静默把新版仿真写进旧轮目录。
4. **复制轮次脚本必须逐条核对路径锚点**：`\\r9\\pX` 与结尾的 `\r9"` 是两种形态，前者替换成功不代表后者成功；漏掉 `$r3dir` 就会“仿真写 r9、验证读 r10”，表现为全部 case “missing run output”而不是仿真失败。
5. **验证失败的定位顺序**：先看 `runs/<case>` 里有没有 `out.hex/stats.txt`，再看 `exitcodes.txt` 的输出路径，最后看 `subst`——比读 verify 日志快。
6. **行为等价的廉价证明**：r10 P2/P3 的 1080p cycles=4,677,945 与 stream sha 和 r9/r8 相同，即可判定无吞吐/语义漂移。

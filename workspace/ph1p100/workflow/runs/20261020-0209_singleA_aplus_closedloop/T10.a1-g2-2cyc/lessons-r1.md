# lessons — T10.a1-g2-2cyc r1

1. **把“+2 再比较”改成“预存 lim2 再比较”能直接闭合时序**：`s1_ok = (s1_pos_r + 13'd2 < blk_n)` 的 13 位加法段约 1.6 ns；在 S_WAIT 预存 `lim2 = (sel_len>2)? sel_len-2 : 0` 后 `s1_ok = (s1_pos_r < lim2)` 只需一次 13 位比较，综合 WNS 从 r0-c 的 -0.156 变为 **+0.134 / TNS 0.000**。等价性注意用 `<` 配 `blk_n-2`（不是 `<=`），并对 `blk_n<=2` 夹到 0 避免 13 位下溢。
2. **时序闭合 ≠ G2 通过：这是一个 LUT-RAM 容量问题**。综合后 `#slice* 72904/71680 = 101.71%`、`#lut 107906`、`#eram 4/300 (1.33%)`、`#dram lut 8432` → 存储几乎全在 LUT/DRAM，packing 后 83,072 slice 直接 `PHY-9053` 退出。r0-c 在同一 top 上已达 73,461 (102.48%)，说明这是 a1_eng_top 既有缺口，不是本轮 RTL 回归。
3. **布线前先看综合资源**：`QOR-3001 HIGH LUT utilization 101.71%` 在综合日志里已经明确预警，phy 必然溢出；以后 TD 流程应在 syn 后先读 `#slice*`/`#eram` 再决定是否布线，可省一次 25 min 布线。
4. **G2 门槛要分两张账**：时序（WNS/TNS≥0）与容量（资源在器件内）都要过。r1 拿到了时序账，容量账需要把 bm_a/bm_b/htab/cmem（以及 frame_top 的 smem）改成可推断 ERAM 的同步读/寄存输出风格，或使用面积导向 map 设置（需授权），或换器件。
5. **盘符约定更新（2026-10-22）**：TD 用 `T:`（当前 td 目录）+`Y:`（项目根），仿真脚本用 `P:`/`W:`，`X:` 保留给 TD 且禁止映射到项目根；打开 TD 前用 `tools/td/open_td.ps1`。本次仍用旧 X: 启动，虽然未影响结果（失败原因是容量），但后续必须切换。
6. 证据技巧仍有效：`result.json` 的 `stream_sha256` + `stats.run_cycles` 与 r10 逐用例 diff（本次 `diffs=[]`）能在改动后快速证明零语义漂移。

# T10.b17-paxi-native — 用户小结（规划冻结，2026-10-26）

**一句话**：这次不再继续调“读重试”，而是回到 DDR 接口的最底层，把三件已经证实不对的事一次改对：**地址少乘了 8、写整字的 mask 用反了、读写命令可以同拍发**。同时把仿真模型改成“真的会检查这些错误”，并加一版能记住失败地址的状态包。

## 为什么还要改

b15 在板上已经证明：相机、crop、发布都正常，`cap_frames/raw_pub` 每帧都在涨；但 A+ 读每帧固定超时 3 次、重试 2 次、放弃 1 次，`enc/exported=0`，而且 `ar−r = 尝试数`——每次读都恰好有 1 个 AR 永远没有 R 回来。

b15 的仿真一直是绿的，但审计发现模型把三个真实差异都忽略了：

1. **地址单位**：bridge 发的是 256-bit 字下标 `0,1,2`；厂商原生参考对应 `0,8,16`，中间少了一个 ×8。
2. **写 mask**：bridge 一直发全 1；厂商的原生完整写是 **0**（mask 0 才写整字）。模型不管 mask 是什么都写整字，所以它当然能过。
3. **命令同拍**：bridge 的读、写引擎可以同一拍都握手；原生参考是单命令仲裁，每拍只选读或写。

这三项不是 CRC、压缩核或重试次数能修的；所以本包先把接口合同改对，再决定要不要查 DDR 控制器内部。

## 这一包具体做什么

- **只在 bridge 的 PAXI 输出做一次地址转换**：`{word_index[23:0], 3'b000}`，AW/AR 都做；内部槽仍然是 256-bit 字单位，不在 store/arb 里重复乘 8。地址范围检查到 424313。
- **`paxi_wstrb` 改成 0**（写整字）；仿真模型必须按“0 使能该字节、1 保持原值”真实执行，不能再忽略 mask。
- **默认单命令**：AW/W 和 AR 互斥，不允许同拍；保留一个 `ALLOW_CONCURRENT` 参数，只给以后做对照，这次上板固定关闭。
- **先做 16 个字的小实验**：写 16 个不同图样 → 停写 → 逐字读回比对。模型必须看到地址是 0,8,…,120、mask 全是 0、没有低 3 位/越界/同拍错误。小实验不过，不跑整帧。
- **再跑整帧、两帧、故意丢 1 个 R**，以及原来的 P1 三黄金（压缩字节必须逐字节不变）。
- **状态包升级到 v6**：新增最近一次 AR 地址、超时锁存的 AR 地址和低 3 位、AW/W/AR 同拍握手计数、在途状态、诊断标志。包长 273 B、67 字段、版本 6；旧 v5 包仍能解析。
- **重新构建**：Routed 0 违例，WNS 目标 ≥+0.05；薄余量按 b13 口径接受但标“非量产签核”；1 次 bitgen + 1 次 CWC。
- **上板**：先下载，再开 COM8 150 秒。目标是 `timeout/retry/giveup` 增量全 0、`enc/exported` 增量 >0、至少 1 帧四 CRC + zlib 全过。若还是缺 R，就把 v6 里的失败 AR 地址/低 3 位/同拍/在途证据留下，**立刻停，不下载第二次**。

## 怎么算过

- 16 字小实验 16/16 逐字一致，地址步长 8，mask=0，无低 3 位/越界/同拍。
- 整帧 `ar=r=rlast=210,685`、两帧 `421,370`；丢 R 用例 `timeout=1 retry=1 giveup=0` 且最终整帧 CRC+zlib 通过。
- P1 三黄金压缩字节与 b15 基线逐字节一致。
- 构建 0 违例、1 bitgen+1 CWC；板级 150 秒内 `timeout/retry/giveup` 增量为 0、`enc/exported` 有增量、至少 1 帧四 CRC+zlib。
- 若板级仍失败，不假装通过；保留 v6 证据，交回规划决定是否查 MC/IP。

## 需要你做什么

**不需要回答任何问题。** 唯一外部条件是板子/FTDI 在位：

- FTDI `0403:6042` 不在位 → 只算 `board=blocked`，不会下载、不会开串口；离线仿真 + 构建仍然有效，不是失败。

## 预算

开发 **150 min / 70 calls**；TD 3 会话、综合 ≤3、布线 ≤2、bitgen 1、CWC 1、下载 1；不写 Flash、不 PCIe/RK、不批量删除。

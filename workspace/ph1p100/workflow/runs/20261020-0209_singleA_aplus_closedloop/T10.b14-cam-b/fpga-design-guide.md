# T10.b14-cam-b — fpga-design-guide（冻结）

本文件冻结本包的接口、数据语义、时钟/CDC、缓冲、构建与证据约定。开发按此实现；发现冲突先交规划，不自行改协议。

## 1. 一句话

A 路“有 MIPI 包/VSYNC、无有效像素”已反复复现；B 路前端（MIPI/I2C/引脚）本来就使能，只是从未接进 A+。本包把 B 的 tap 引到核外，在板级顶用**编译期常量** `CAM_SEL=1` 选中 B，走同一套 crop(972/556, 1920×1080)→raw→A+→export，用 v5 既有的 `pix/line/frame` 字段记录 B 的计数；A 路径保持可回退（`CAM_SEL=0`）。

## 2. 已核实事实（不是设计选择）

| 事实 | 证据 |
|---|---|
| B I2C 已实例化且自动启动，无 enable 门控 | `f9p_camera_display_core.v` L228–239；`ui_cfg_imx415.v` `WAIT_START→PREPARE` |
| B MIPI 已复位释放、RX 使能 | 同文件 L182–205：`I_rst_n(r_rst_n)`、`I_rx_en(r_rst_n)` |
| B 的 pixel/valid/line/frame/vsync/byte_clk 已存在 | 同文件 L141–145；`w_b_*` 已用于调试计数器 |
| B 的 frame/CRC 状态当前悬空 | 同文件 L204 |
| B 引脚已分配（不是 disabled） | `board_p2.adc` L39–48、L64–67 |
| B 与 A 共用 MCLK/XCLR、共用 tap 46 | 核 L115–116、L128–129、L190–191 |
| SDC 只有 A 的 generated byte clock | `p2_board.sdc` L22、L38–39 |

因此本包**不做**“使能 B / 改 I2C 表 / 改 MIPI 配置 / 改 tap 扫描 / 改 crop 几何”。

## 3. 接口合同（新增端口，全部 output wire）

### 3.1 相机核 `f9p_camera_display_core`

- B tap：`o_b_pixel[39:0]`（4 px RAW10/beat，与 A 同形）、`o_b_pixel_valid`、`o_b_in_line`、`o_b_in_frame`、`o_b_vsync`、`o_b_byte_clk`。
- B 诊断：`o_dbg_b_cfg_done`、`o_dbg_b_bus_err_lat`、`o_dbg_b_nack_cnt[31:0]`、`o_dbg_b_lane_sticky[3:0]`、`o_dbg_b_delay_tap[5:0]`、`o_dbg_b_delay_done`、`o_dbg_b_rst_out`、`o_dbg_b_sync_wait`、`o_dbg_b_pkt_tgl`、`o_dbg_b_vs_tgl`、`o_dbg_b_clk_tgl`、`o_dbg_b_in_frame`、`o_dbg_b_vsync`、`o_dbg_b_good_frames[31:0]`、`o_dbg_b_bad_frames[31:0]`、`o_dbg_b_crc_errors[31:0]`、`o_dbg_b_header_errors[31:0]`、`o_dbg_b_last_wc[15:0]`、`o_dbg_b_last_lines[15:0]`。
- 实现约束：端口只做 `assign` 到已有 `w_b_*`/`r_b_*`；`B_GOOD/B_BAD/B_CRC/B_HDR/B_WC/B_LINES` 是 `u_csi_b` 新接的内部 wire；不新增 reg/always/状态机。
- `CAM_B_IDELAY_TAP = 6'd46` 只作用于 `u_csi_b`；A 用原 `CAM_IDELAY_TAP=46`。
- A 的端口、`u_csi_a`、HDMI/TPG、I2C A、`dbg_uart`、`cap_*` 空连接语义全部不变。

### 3.2 板级顶 `p2_a1_board_top`

- `localparam CAM_SEL = 1'b1;`（0=A，1=B）。**只允许编译期常量**；不新增端口，不做运行时切换。
- 选择必须用 `generate if (CAM_SEL)` 直连；综合后时钟是 B 的 BUFG 输出，不是 LUT mux。
- 选择对象：`clk_cam`、`i_a_pixel/pixel_valid/in_line/in_frame/vsync`、`i_dbg_tap/delay_done/rst_out/sync_wait/pkg_tgl/vs_tgl/clk_tgl`、`cfg_done/bus_err_lat/lane_sticky/nack_cnt`。
- `camera_a1_uart_top` 实例化的参数/端口除上述输入外不改；`u_a1.clk_cam` 由 `a_byte_clk` 改为所选 `cam_byte_clk`。
- `cam_sysstat[20] = CAM_SEL`；`[19:0]` 与 b13 完全相同（`lane_sticky[3:0]`, `3'd0`, `cfg_rst_n`, `pll_locked`, `xclr_n`, `bus_err_lat`, `cfg_done`）。
- A 核仍实例化（B 选中时不进 A+）；B 的 `o_dbg_b_*` 未进包者允许悬空。

### 3.3 状态包

- 仍为 **v5：`A5 5A E1 05` + 59×u32 + XOR8 = 241 B**，VER=5、LEN=241、XOR 覆盖 0..239；字段顺序、单边沿快照、只在 exporter idle 发、不插帧内全部不变。
- `#3 pix_beats/#4 line_rises/#5 frame_rises/#6 frame_falls/#7 last_frame_cycles/#8 crop_roi_frames` 记录**所选相机**；`#12 phystat/#13 sysstat/#14 nack_cnt` 也是所选相机；`#13 bit20=cam_sel`。
- 不新增字段、不改 `a1_uart_export.v`、不改 `parse_status_v5.py` 的长度/字段数（只加 bit20 打印与标签）。

## 4. 数据格式与几何

- B 与 A 同为 IMX415 4K RAW10、4 lane；`CAM_W=3864`、`CAM_H=2192`；每 beat 4 px，每行 966 beats；每帧 2,117,472 beats。
- ROI 仍 `ROI_X=972, ROI_Y=556`，输出 `1920×1080`；`a1_raw_crop` 的 group=4 px、2×2 对齐、行/帧语义不变。
- RAW 帧字节数 `2,592,000`；压缩/44 B 头/四 CRC/zlib 合同不变。
- 合成 B 向量必须用上述精确几何；不得用 3840/2160 或其它尺寸“近似”。

## 5. 时钟/CDC/复位

- 两个 MIPI 字节时钟各自独立：`mipi_a_byte_clk`（已有 generated clock）与 `mipi_b_byte_clk`（本包新增）。`CAM_SEL=1` 时 A1 相机侧全在 B 字节时钟域。
- 禁止用 A 时钟采 B 的 pixel/line/frame；禁止把 B 的多比特计数直接异步采到 clk_a1。
- 既有跨域结构不变：`cam_diag_mailbox`（clk_cam→clk_a1，toggle + 2FF + 稳定窗）、`u_dbg_sys_mail`（sys50→dhi_clk）、`u_dbg_sys_mail_a1`（dhi_clk→clk_a1）、`capture_async_fifo`（Gray 指针）。
- `CAM_SEL` 常量在综合时确定，无运行时时钟切换，因此不需要 BUFGMUX 切换序列/glitch 处理。
- B 字节时钟停振时：`clk_cam` 域保持、邮箱保持、clk_a1 状态包继续；不得拉全局复位、不得回切 A 时钟采样。仿真需显式初始化停振域的寄存器（硬件上电为 0）。

## 6. SDC（只加 2 处，别的不动）

在 `p2_board.sdc` 的 A generated clock 之后加：

```tcl
create_generated_clock -name {mipi_b_byte_clk} -source [get_ports {mipi_b_clk_hs_p}] -divide_by 4 [get_pins {u_camera/u_csi_b/u_rx_phy/u_hs_clk_div.clkdivout}]
```

并把既有异步组从：

```tcl
    -group {mipi_b_clk_hs}
```

改为：

```tcl
    -group {mipi_b_clk_hs mipi_b_byte_clk}
```

- 这是**为新时钟域补约束**，不是 false path/multicycle/放宽；其它 `create_clock/rename_clock/set_path_skew/set_false_path` 行逐字节不变。
- 若新域出现违例，按 dev-plan §6 处理（先一次“只减 B 调试观测”，不得动 SDC 语义）。

## 7. 构建合同

- 复制 `T10.b13-ddr-retry/r1/td/**`（`src/`、`01_build.tcl`、`02_bitgen.tcl`、`03_cwc.tcl`、`a1_board.al`、`p2_board.sdc`、`board_p2.adc`）到 `T10.b14-cam-b/r0/td/`；不复制 `a1_board_Runs/`、`cw/`、旧 bit/CWC/大报告。
- `01_build.tcl` 与 `a1_board.al` 的 11 个 changed-src 路径统一改指 b14 `r0/changed-src/`，其中 `f9p_camera_display_core.v` 从 `./src/` 改指 changed-src 副本；Tcl 流程/参数/seed/策略组不变。
- 综合 ≤3、布线 ≤2、bitgen 1、CWC 1；Routed 0 违例、hold ≥0、period 正、ERAM+CWC≤300；WNS 按 dev-plan §6 预裁决。
- bit/CWC/BID 与 `cw/compiled.bit` 哈希自洽并冻结；1 bitgen + 1 CWC 后不再重建。

## 8. 证据合同

- 每个 changed-src 文件记 SHA256；`rtl-diff-r0.patch` 必须只含：核的新端口/assign/1 个 localparam、p2 top 的选择逻辑/连线/注释、SDC 2 处、Tcl/al 路径。
- S1 必须给出精确计数：`pix_beats=2,117,472`、`line_rises=2,192`、`frame_rises=1`、`frame_falls=1`、`crop_roi_frames=1`、`crop_groups=518,400`、`raw_len=2,592,000`、`enc=1`、`exported=1`。
- S2 必须给出三黄金压缩字节 SHA256 与 b13 基线的逐字节比较结果。
- S3 必须给出 241 B/59 字段/VER/XOR 与 `#13 bit20`。
- 板级证据必须包含：连接确认原话/时间、FTDI 预检原始输出、下载日志、150 s 原始 bin、v5 解析 JSON/TXT、帧四 CRC+zlib 结果；若 blocked，写清 `board_blocked_reason` 与 0 下载。
- 不得把“B 无像素”写成 PASS；也不得为了出图改 crop/帧格式/tap 表/寄存器表。

## 9. 不变式（评审必须逐条检查）

1. `CAM_SEL=0` 时 A 分支连接与 b13 逐线一致（静态对照表）。
2. `CAM_SEL=1` 时 A+ 只吃 B tap；A 核仍存活但不进 A+。
3. v5 长度/字段/顺序/快照/帧内边界不变；`#13 bit20` 是唯一新增语义。
4. P1 三黄金逐字节不变。
5. B 的 pixel/line/frame/vsync 只在 B 字节时钟域被采样；无跨域多比特直接采样。
6. 不发布半帧、不覆盖 READY 槽、不改 44 B 头/CRC/压缩字节。
7. 板级下载 ≤1、Flash 0、B 未确认则 0 下载。

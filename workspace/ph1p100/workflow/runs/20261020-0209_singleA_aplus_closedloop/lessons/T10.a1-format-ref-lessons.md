# T10.a1-format-ref — lessons

1. **格式冻结必须把“未写明”的地方也写死，否则 P2/P3 会各自发明。** guide 没规定变换域字节打包与预测器跨块行为。本轮冻结为“平面样本连续 4 样本组、5B/4px、组可跨平面不跨块”和“每块每平面重置预测”，并给出长度不变证明（xform_len==raw_len）。P2 若按别的打包实现，会产生“流合法但逆变换错位”的隐蔽失败。

2. **块粒度算术要在冻结时复核，而不是等到容量检查。** guide §2 同时写了“1 block=1 个 2 行对”“1080p 270 块”和 §3“block_count=540”。1080/2=540，最坏 stored 是 2,594,706 B，不是 2,593,356 B。这个 1,350 B 差异不影响单块规则，但会让 P4 的 buffer 上界少算 1,350 B。以后凡是“块数 × 每块开销”的数字，冻结时就用脚本算一遍并与几何定义对齐。

3. **“独立解析器”最容易在 Huffman 位序上假独立。** DEFLATE 位流是 LSB-first，但 canonical Huffman 码按 MSB-first 解释；直接把 peek 到的 LSB-first 整数当码表 key，会得到看似随机但偶尔能解的流（本轮 retry1 现象：距离巨大/首字节就越界）。修复是 peek 后按实际可用位数做位反转，再按 MSB-first 前缀匹配。独立实现要专门测 `literal / len 3 / len 258 / dist 1 / dist 2048 / EOB` 的位边界，不能只测普通文本。

4. **负例必须“外科手术式”变异并修复外层校验。** 坏 `stream_len` / 坏 raw/xform CRC 如果不同时重算 header CRC，会先被 `E_BAD_HEADER_CRC` 拦截，测试看似通过但根本没测到目标字段。本轮对这三个负例重算头 CRC，才让拒绝原因落在目标 reason code。负例的价值在于“拒绝原因正确”，不只是“拒绝了”。

5. **测试头的 CRC 范围有歧义时要显式冻结并留痕。** guide 写 `0x00..0x1B` 又说“本字段置 0”，而字段在 `0x1C`。本轮选择对 28 B 计算、字段不参与，并在 format/result 里写明“这是措辞歧义，不是数据冲突”。如果 P4 需要整头 CRC（含零字段），必须另立版本，不能静默改。

6. **不可压缩向量的价值是验证上界，不是验证压缩。** 1080p 随机帧 540 块全部 stored，流长精确等于 2,594,706 B，这同时验证了块数、每块 5 B 开销、zlib 6 B 包装和 stored 对齐规则。以后 P2/P3 的 stored 回退测试应复用这个“精确上界”断言，而不是只看“能解开”。

7. **合成 A/B 比率不能拿来说 Bayer 收益。** 1920×4 重复图案上 `prep=1,pred=1` 的 ratio 反而低于直通（56.47 vs 75.00），因为重排打散了原始字节重复；这只说明“小合成帧 + 块内 2KB 窗口”下的字节统计，不说明真实 RGGB 图像的收益。报告必须把 `synthetic` 和“声明相位”放在比率旁边。

8. **P1 的边界要写死“不做什么”。** 本轮没有 RTL/ModelSim/TD/吞吐/真实 RAW；`ready_for_test` 只代表软件格式层可复核。把 P1 PASS 写成“A+ 闭环通过”会直接违反需求里“模块小顶 PASS 不代替组合版 PASS”的约束。manifest 里同时列代码、向量、日志、输入 SHA，测试者才能把 PASS 绑定到唯一输入集。

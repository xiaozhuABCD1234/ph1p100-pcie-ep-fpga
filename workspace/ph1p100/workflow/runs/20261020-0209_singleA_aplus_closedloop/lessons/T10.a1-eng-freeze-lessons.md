# T10.a1-eng-freeze — lessons

日期：2026-10-20｜run：`20261020-0209_singleA_aplus_closedloop`

1. **TD 把顶层端口当封装 IO。** `a1_frame_top` 的 7×32-bit test-only 状态总线让 IO 计数超过 PH1P100SBG484 的 286 上限，综合直接 `SYN-8228` 失败。块级小顶必须先做端口裁剪/wrapper，状态总线用 XOR 折叠而不是直接暴露。折叠后 IO=121。
2. **`wait_run` 之后不能直接 `report_area/report_timing`。** 会话没有 import netlist，会报 “Design is unavailable / Cannot find top model”。真正可用的是 run 目录里的 `*_gate.area`、`*_gate.timing`、`*_gate.ts`；构建脚本应显式 `open_run` 或直接归档 run 目录报告。
3. **先看综合 STA，再决定是否花布线预算。** 本次综合 Fmax 84.717 MHz（WNS -6.471 ns），已明确不可能满足 187.5 MHz；第 3 次 30 min 布线会话不会改变判定。按“有新证据才重试”的原则及时停止，比盲目跑满 3 次更符合预算。
4. **功能仿真全 PASS 不等于可综合频率。** P3 的 20 例、0 mismatch 都成立，但 `cmem[4096×16]` 的组合读被推断成 5,240 个 DRAM LUT，形成 6.5 ns 违例路径。大深度查找表必须同步读或映射 ERAM，否则功能正确但时序不可用。
5. **资源小 ≠ 能收敛。** 11k LUT / 2k FF / 4 ERAM 只占 14% slice，但关键路径仍是组合 mux。G2 必须同时看资源和 WNS，不能用“资源在器件内”代替时序。
6. **中文路径要用 subst + 正斜杠。** `td_commands_prompt.exe X:\00_all.tcl` 会被 Tcl 把 `\00` 当转义，报 `couldn't read file "X:.._all.tcl"`；必须传 `X:/00_all.tcl`。
7. **TD 会话超时要有可执行终止。** 本次 phy 在 30 min 被 shell 超时终止，保留了 `phy_1/run.log` 到 global placement Phase 4 的进度；没有 Routed 就不写 Routed。
8. **单时钟 CDC 结论要分清“结构结论”和“工具报告”。** 本次 STA Clock Summary 只有 `clk0`、CC-From/To=no，可写结构单时钟；但 `report_cdc` 未执行，必须写 not_run，不能混写成 CDC PASS。
9. **吞吐结论要带内容与帧长。** 1080p 整帧 101–104 MB/s，16 行帧 88.9 MB/s，20×5 仅 ~44 MB/s；97.2 只对已测整 1080p 帧成立，且只有 2 帧连续数据，不能外推长稳。
10. **冻结包要区分候选与 build-only。** `a1_eng_top.v` 只用于 TD 端口折叠，不属于候选 RTL；manifest 必须标注 role，避免测试者把 wrapper 当成被测设计。

## r1 追加（2026-10-20，T10.a1-eng-freeze 有限修复）

11. **同步读要区分“寄存器地址”和“组合地址”。** 只把 `htab_raddr` 打成寄存器，会在地址更新与读数据之间多一拍，导致每个 position 的首个 lookup 用旧表项，P2 立刻报 `expected real matches missing` / `max dist != 2048`。正确做法：用**下一窗口的组合 hash**驱动内存地址，读数据在下一 cycle 有效；再对同地址写加 write-first bypass，才能保持 distance-1 语义。
12. **cmem 的同步读可以吸收在 replay 等待态里。** 新增 `S_REPLAY_RD` 只让 1080p p1d1 多 100 cycles（4,677,841→4,677,941），因为输出 FIFO 掩盖了单 word 延迟；不要把“多一个状态”直接等同于吞吐下降。
13. **修完内存读后，关键路径会转移到算术链。** r1 的 WNS 从 -6.471 改善到 -3.816 ns、Fmax 84.7→109.3 MHz，但 `dist_r → pos_reg[*].ce`（`pos+len_r`、`stored_bits` 比较）成为新瓶颈。下一轮应在 `S_MLEN`/`S_MDIST` 分段寄存，而不是继续动内存。
14. **预算内停止比“再跑一次布线”更有价值。** 综合 WNS 已为负时，按 stop condition 在 132 s 的 TD 会话后停止，保留 Fmax 与新关键路径；没有第 4 次会话，也没有用 bitgen 掩盖未收敛。

## r2 追加（2026-10-20，最终有限修复）

15. **流水要切在“最长的那条”，不是“看起来最复杂的那条”。** r2 把 `dist_r → dval/dtot → pos.ce` 切开后，WNS 只从 -3.816 改善到 -3.792 ns；关键路径转到 `S_MLEN` 的 abort 预测 `pos → (blk_n-pos-len_r)<<3 → cand_bits`。说明 r1 的 `dist_r` 路径只是 13 级中的一段，真正的组合链是“剩余长度预测”。
16. **`S_MLEN` 的 abort 检查本身需要一级状态。** 只在 `S_MDIST` 前加寄存器不够；`S_MLEN` 仍在同一 cycle 做 13-bit 减法、移位、32-bit 加法和比较。下一轮应加 `S_MCHK`：`S_MLEN` 只锁存 `pos_next/rem_next/cand_after_len`，`S_MCHK` 再比较并决定 `S_MDIST/S_DECIDE`。
17. **综合 WNS<0 时不要布线。** r2 的 TD 会话 461 s 完成综合后按 stop condition 停止，未浪费 30 min 布线；Fmax 109.589 MHz、关键路径 `pos_reg[5]→cand_abort_reg.d` 可直接作为下一轮输入。
18. **每轮都要重新冻结、不得拼接。** r2 的 P2/P3 是在新 hash `585664de…` 上重跑的；r1 的 PASS 不能用于 r2。r0/r1/r2 三个 manifest 并存，回退路径清晰。

## 4. F1–F6 closure

### F1 — final-word pending abort (fixed)

The r1 RTL gates `out_last` with `!killed` (`a1_frame_top.v:155`) and keeps `frame_commit` gated (`:156`). The independent TB holds `out_ready=0` exactly while the final word is pending, asserts abort, and observes:

```
PENDING_LAST valid=1 last=1 keep=1 slen=117 stream_len=117
AFTER_ABORT valid=1 last=0 frame_abort=1 commit=0
RESULT saw_pending_last=1 last_while_pending=1 last_after_release=0 commit_after_release=0 frame_abort=1
ABORT_LAST_EOP_CLEAN
```

So the pending final word is held with `out_last=0`; no eop and no commit. The dev TB's `bp_mode=3` auto-releases when `out_last` deasserts, which is why its `p2_valid_after_abort` reads 0; that does not contradict the fixed-ready TB. The third frame (`p3`) commits and independently decodes 0 mismatch; `abort_last` stats: `p2_pending_last=1`, `p2_last_after_abort=0`, `p2_commit_after_abort=0`, `p2_last_after_release=0`, `p2_commit_after_release=0`, `p2_valid_after_release=0`, `p2_abort_lvl=1`.

### F2 — 9 unconnected core stat ports (fixed)

All nine `stat_*` outputs are connected in `a1_frame_top.v:206–214`. All 20 case logs have **`vsim-3017=0`, `vsim-3722=0`**; `vlog`/`vlog -lint` 0/0. Residual 13 `vsim-PLI-3691` per case are TB `$value$plusargs` style warnings from ModelSim ASE, not RTL and not port/width warnings.

### F3 — smem out-of-bounds / time-0 X index (fixed)

The combinational array read is replaced by a registered read + 2-stage prefetch with a clamped index (`a1_frame_top.v:269–271`). All 20 logs, including all four 1080p cases, have **`vsim-8233=0`**. The pipeline adds one cycle per block: 1080p p1d1 cycles 4,677,841 vs r0 4,677,301 (+540), still 103.894 MB/s. Independent decode is 0 mismatch, so the pipelining did not drop or reorder samples.

### F4 — illegal geometry/config and I_DEAD (covered; reset-only policy)

- `neg_wmod4` (18×4, W%4!=0), `neg_h1` (20×1, H<2), `neg_oversize` (1924×4, 2×stride=4810>4800): `p1_abort_lvl=1`, `p1_commit=0`, `p1_busy=0`; reset clears `frame_abort` (`after_rst_abort=0`); a second illegal drive after reset again aborts (`p2_abort_lvl=1`, `p2_commit=0`).
- `neg_pred0prep0` (prep=0, pred=1): first frame aborts, no commit; reset; valid recovery frame (prep2=1, pred2=0) commits, 142 B stream, 0 mismatch.
- Policy is explicitly **reset-only** for `I_DEAD`; a new sof without reset is not accepted. This is documented in the dev notes and is a safe policy, but it is not a "new sof recovers without reset" behavior.

## 5. New-problem check

- **core_flush semantics:** the P2 core leaves `enc_busy` set after its last block; the frame top emits a one-cycle `core_flush` (ORed into the core abort) after commit. The P2 core source is unchanged (`6cd35881…`). `multi1080p` frame 2 and `abort_last` frame 3 both commit and decode 0 mismatch, so the flush does not corrupt the next frame or deadlock. This remains a workaround for a P2-core quirk that P4/integration should either fix at the core or document; it is not a new P3 functional failure.
- **Frame-to-frame state:** two-frame multi (both 540-block streams, identical 81,707 B) and abort_last third frame both pass; recovery cases p2 pass. No stale bank/CRC/bit-pack state observed.
- **Latched config:** `prep_r/pred_r` are set at frame start and used in the input and drain paths; the live `prep_en/pred_en` are only used for the start-time legality check/latch. All prep/pred combinations pass. No mid-frame config-change test; latching is verified by code inspection, not by a toggling test.
- **Output integrity:** all committed streams are exact, no trailing bytes, 0 mismatch; `bp_equivalence=True`; `stall_abort` `stab_err=0`; the aborted final word is held with `out_last=0` in the independent fixed-ready TB. The `sdata/skeep` registers are only written when `core_out_valid && core_out_ready` and `core_out_ready=!svalid`, so a pending word is not overwritten.
- **Residual verifier issue:** `a1_p3_verify.py:74` uses `len(zout) ^ len(xform)` for the zlib mismatch message; this only affects the error-message count, not the PASS/FAIL decision (the code still appends a problem on any mismatch). Non-blocking; the independent verifier does not use it.
- **Residual TB warnings:** 13 `vsim-PLI-3691` per case from `$value$plusargs`; ModelSim ASE quirk, not RTL. The targeted F2/F3 warning classes are zero.

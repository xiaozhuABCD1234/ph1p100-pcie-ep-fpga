# 队友新提交对照：您该更新什么（2026-10-17 增量）

> 本次只做只读对照：已把队友两个仓库拉到最新（fpga `2a4b253`，driver `a0215c5`），没有改您的代码/工程，没有跑他们的脚本。详细依据（逐条 diff、commit/文件记账、代码行引用）在 `pcie-unified-path-addendum-20261017.md`。

## 一、队友这两个晚上改了什么（一句话版）

**FPGA 端**：把"相机 4K 整帧直接写 DDR3"做成两条新通路（A/B 相机各一条，写口按突发仲裁），**删掉了旧的 640×480 片内缓存→DDR 通路**；顺手把**推帧 TLP 计数器位宽**按最大帧长自动推导（**我们上次提的 12 位问题他改了**）；寄存器表更新（新增 B 路握手/诊断、推帧选 A/B 路的 bit8；旧的 bit4 收回）。
**驱动端**：**代码没改**（只改了注释/文案），README 补了两篇操作说明——**"板子 rootfs 预装厂商 ko 会被顶掉、要覆盖安装"**和**"4K 收帧怎么设参数"**。

## 二、对您的影响：三类

### ① 已解决——您不用再提的（上次评估里挂着、他已改）
1. **推帧计数器 12 位不够 1080p** → 已改，换几何不会撑爆（用新推帧引擎即可）。
2. **4KB 尾块问题** → 他定成硬规矩：**每帧字节数必须是 4KB 的整数倍**（不做尾块）。
3. **多路采集** → A/B 两路各有自己的双缓冲、握手字和诊断，写 DDR 有仲裁；旧 640×480 缓存通路已删。
4. **仿真** → 他新模块有 iverilog 测试台（以前说"没有仿真器"已过时）。

### ② 新增——您这边要跟着更新的
1. **寄存器表按新版更新**：bit8 = 推帧选 A/B 路；新增 B 路握手 `0xE0~0xEC`、诊断 `0xD0/0xD8/0xDC/0xF0/0xF4`、B 路 IDELAY `0xD4`；`0x80/0x84` 的 bit15 变成"丢过像素"标记；旧 `bit4`（相机写源）作废。
2. **1080p RAW10 帧要补零到 4KB 整数倍**：我们的 R10F 帧 128+2,592,000 = 2,592,128 字节 → **补齐到 2,592,768 字节**（尾部 640 字节零，头里的长度字段为准）。驱动侧 `frame_slot_bytes` 和几何参数要跟这个数一致（他文档里也写了"驱动报的几何和 FPGA 帧字节数必须一致、且都是 4KB 整数倍"）。
3. **双路"同时推"还没有**：他的推帧引擎只有一份，靠 `bit8` 选 A 或 B——同一时刻只推一路。我们双路 1080p30 要么让他加第二份推帧引擎（或做轮换），要么我们定一个轮换方案。**这条建议列为与队友的第一优先问题。**
4. **上板装驱动要先覆盖厂商版**：板子 rootfs 里预装的厂商 ko 会在开机时把手动 insmod 的版本顶掉（症状：只出现 `_control/_user`，没有 `_frame` 节点）。按他 README：拷到 `/usr/lib/modules/$(uname -r)/updates/` → `depmod -a` → `rmmod && modprobe`，并确认 `_frame` 出现；CMA 要够放一帧（4K 8.29MB / 我们 1080p 2.59MB）。
5. **联调别再用 0x4C 当相机帧号**：新设计里 `0x4C` 是测试图源的计数；相机帧号看 `0xA0`（A）或 `0xE0`（B）。他的 `link_ctl retrig` 判据可能要跟着改（已作为小问题列入）。
6. **上板注意链路状态**：热重配后主机 BAR 会读全 F，要重启 RK 重新枚举才恢复 Gen2×2；他文档还提到"Gen2 ×1 也有 500MB/s"，我们 155.52MB/s 预算够，但板测要记录实际速率。

### ③ 仍然开放——他没动、我们上次提的
1. **推帧目标地址 +16 字节未对齐**（会让每 4KB 有一笔 128 字节的写跨界，规范不允许）——驱动没改；建议仍按"像素区起点改 128 字节对齐"（驱动小改，FPGA 不用动）。
2. **"主机真的收到并验过整帧"的证据**——他 README 还留着"收帧等 FPGA 接通后再验"的旧句；4K 的"推帧错误寄存器=0"只是引擎侧指标，`frame_grab` 取帧逐字节验证的记录还是建议向他要一份。
3. **1080p/Raw10（10bit）**：他那边只做 4K 8bit（RAW10>>2）；我们的 RAW10 packed + R10F + 后面 BPR1 还是自己做。
4. **DDR 配置定案**（他 800E/AXI，我们 1600/1333 PAXI）、RK 环境信息（内核/IOMMU/MPS/BDF）、他 A/B 双路同时推、槽头长度支持压缩变长等——同前。

## 三、一个必须上板前处理的新发现（重要）

**他的 FPGA 新代码把 CTRL 的 bit4 收回作废了，但驱动还在等 bit4 置位**：驱动的初始化会写 bit4 并回读校验，新 FPGA 的 bit4 恒读 0 → 驱动会打印"使能位没置全"、把 `armed` 记成 0（`link_ctl` 会显示"**未初始化**"、可能给退出码 4）。实际使能位（bit0/5/6）还是写进去了，通路大概率仍能用，但驱动状态和工具判读会误报。**建议让队友把驱动的初始化位去掉 bit4（或他明确怎么兼容）**，我们联调前确认这一条已修——详见对照报告 §4 F1（带代码行）。

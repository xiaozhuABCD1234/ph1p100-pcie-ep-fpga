### F1（阻断，engineering/input binding）— R0–R3 的 TB 不是冻结 TB，R3 自检 `bad=0` 不在同一 run

- 冻结 manifest 的 `src/tb_ss_g0.v` SHA256 为 `A565C6F2…`；但 `manifest.notes.tb_versions.r0_r3_tb_sha256=89948303…`，R0–R3 原始 log 均用 `89948303…` 生成（R0–R3 的 `$finish` 行指向 `tb_ss_g0.v(445)`，冻结 TB 的 `$finish` 在 447 行；旧 TB 在 445 行）。旧 TB 存在于 `C:\Users\czz\AppData\Local\Temp\opencode\ss-g0\tb_prefix.v`（SHA256 `89948303BE…`），**不在 manifest artifacts 中**，只靠 TEMP 目录保存（不可长期冻结）；测试者已把它复制到 `test-reports/T10.ss-g0-closure/evidence/tb_prefix_89948303.v`（SHA256 `89948303BE78DA2B4E2CBCCBB70935D26825B518620C679BA9D959D3C950008E`，23,894 B）作为报告证据，但不改变候选 manifest 的绑定。
- 我逐行比对旧 TB 与冻结 TB：差异仅 4 行 `if (vn0/1/2/3 == 2'd3)` ↔ `2'd0`（自检分组）和帧 1 后一条 `SS_VEC_MATCH` 早打印；**无 DUT 驱动/端口/几何/时钟/复位改动**。因此数据面等价；我用冻结 TB 独立重跑 R0，stats/dec 逐字节相同（§2）。
- 但 R3 的 `bad=0` 证据来自冻结 TB 的 v1 check-only（2M cycles 截断），R3 timing 来自旧 TB；两者是**不同 TB 版本**。按“同一冻结 manifest / 不得拼不同输入 PASS”的合同，当前不能正式 PASS。
- 复现：`Get-FileHash tb_prefix.v` / `src/tb_ss_g0.v`；`sim/logs/r3.log` 第 74 行 `bad=691132`；`sim/logs/v1.log` 第 46 行 `bad=0 checked=518400`；`evidence/p1_to_p3_tb.diff`；`evidence/verify_g0.json` 的 `diffs.p1_to_p3_tb` 与 `computed.r3_header`。
- 修复选项（二选一）：**A** 用冻结 TB `a565c6f2…` 重跑 R0–R3（至少 R3），使 G0 run 自身 `bad=0` 并重新冻结 manifest；**B** 把旧 TB `89948303…` 复制进任务目录、加入 manifest artifacts，并由规划书面接受“TB-only 等价”的绑定（仍建议至少重跑 R3 以消除跨 run 拼接）。

- `src/DIFF.md` 自述的差异中，以下不在 plan §10.4-2 的 ①–⑧ 白名单内：
  - `WD_LIMIT 8,000,000 → 12,000,000`（P1 TB 为 8M；P3 plan 未列 watchdog 门限改动）；
  - `CAPTURE=1` 的 `.dec` 格式 `%0d → %02x`（P1 的 `.dec` 文本格式被改变；`cap_bytes` 计数未变，文件字节数 721,583 → 641,248）；
  - `CAPTURE=0` 额外写 `+HDR` 前 256 B（白名单 ④ 写“仅计数”）；
  - `SS_META`/`SS_STATS` 追加 `content/pacing/sink/capture/vec_bad/vec_checked/drv_groups` 字段，新增 `SS_MODE`（白名单 ⑧ 写“沿用 P1 协议”）。

### F3（非阻断数据/文档）— `out/content-proxy.json` 的 `in.meta` 元数据错误

### F4（scope 需规划确认）— fast sink 实测 93.75 MB/s，不是 plan §10.9 字面要求的 ≥200 MB/s

- 关键判断：R3 payload 25.47 MB/s@33.33 ms、G0 raw 77.76 MB/s，均低于 93.75；tail 恒定且 <0.5·`S_ss`，`sink_limited=false`，所以**当前 G0 不是 sink-limited**，93.75 MB/s 足以支撑该代理的 G0。但 plan §10.9 的 scope 字面条件是“≥200 MB/s sim sink”，当前 scope 写“measured export ~93.8 MB/s”，不满足字面。需规划接受“实测 93.75 MB/s、非限速”的 scope，或要求真正的 ≥200 MB/s sink 后重跑 R3。

### F5（已披露的未测）— R4 未运行，触发条件其实已满足

# user-request-commit.md — 需要你帮忙做一件小事（一次性，约 1 分钟）

（本文件=给用户的“人话版”请求，供主原样转发。日期 2026-10-18。）

## 一句话背景

调试读回程序的所有改动**都已写好、检查也通过了**，只差最后一步“登记盖章”——把这次改动记录进项目本地的版本历史里。我们用的工具在“盖章”这一步被**安全权限连拒两次**（工具层限制，不是代码问题）；所有改动原样暂存着，一个字都没丢。下一步“编译新程序包”要用这次盖章产生的编号（commit SHA）作为“父版本”来冻结候选，**没有这个编号我们不敢往下走**（否则以后说不清用的是哪一版）。所以需要你二选一：

## 选项 A（推荐，约 1 分钟）：你亲自盖一次章

打开 **PowerShell**（普通窗口即可），把下面三条**逐条复制粘贴**执行：

```powershell
cd "C:\Users\czz\OneDrive\桌面\实验室\竞赛\嵌入式\FPGA创新设计赛道\upstream\ph1p100-pcie-ep-fpga"
git commit -m "T11.runB-debug-rtl: dbg_bank 9-word read-only mirror + debug-only CTRL default enable + debug top/entry + new TB (offline, no bitstream)"
git log -1 --format="%H %s"
```

- 说明：改动**早已暂存好**，不需要运行 `git add`；第二条命令打印刚生成的编号（40 位十六进制）+ 提交说明。
- 预期结果：第一条显示类似 `7 files changed, 619 insertions(+), 6 deletions(-)`；第二条显示 `c89ab75…` 之外的**新编号** + `T11.runB-debug-rtl: …`。
- 再验证一下（可选，复制粘贴）：`git status --porcelain` —— 预期**没有任何输出**（干净）。

请把 `git log -1 …` 和 `git status --porcelain` 的**输出原文**粘贴回给我们（下一条消息即可）。

**请注意：不要执行 `git push`**（我们全程不推送）。这条命令只在本机登记一次改动，不联网、不碰板子、不删任何文件。

## 选项 B：给环境放行权限，我们自己做

如果你更希望由我们完成：请把本工作环境里 shell 的 **`git commit` 权限放行**（当前被权限层拒绝），并告诉我们一声。我们会续收——只做一次 commit + 回填编号，不推送。

## 做完之后会发生什么

你把输出发回后，我们（规划）会：核对新编号 → 用它回填冻结清单（manifest）→ 交给独立测试者验收 → 随后进入下一步“编译新调试程序包”。**在你回话之前，后续步骤保持在“等待条件”，不会硬跑；板子完全不受影响（现在跑的还是原来的程序）。**

## 如果出错

任何一步出现红色报错（例如提示需要设置 git 用户名/邮箱、或仍然被拒），**把报错原文发回来即可**，我们再看怎么处理；不要反复重试、不要用管理员强制手段、不要动其他文件。

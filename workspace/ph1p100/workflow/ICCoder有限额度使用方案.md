## 定位：可选的 FPGA 专项审阅者

IC Coder 的官方扩展说明覆盖 RTL、TestBench、日志/波形分析，以及 TD、ModelSim 等工具交互，同时明确实际工具/版本/器件和执行范围取决于发布版本与项目配置。[官方扩展说明](https://marketplace.visualstudio.com/items?itemName=ICCoderAgenticVerilogPlatform.iccoder)

因此可以加入我们的工作流，但当前只按 **VS Code 中的人工任务交接**设计；本轮未安装扩展、登录、调用模型或消耗其 Credits。未核实可供本项目直接调用的 CLI/API/MCP，也没有证明 PH1P100、TD 6.2.2 和本机 ModelSim 的实际适配。

建议把它用在 G0/G1/G2 的专项检查：现有 RTL 是否有边界缺陷、测试是否漏场景、有限的时序/CDC 报告能支持什么结论。主助手仍负责架构、任务排序、复杂调试、实际执行和最终核验；专业工具是否更有价值由试点结果决定，不预设它必然更准确。

IC Coder 不作为任务 done 或项目验收的必需依赖。到期或额度不足时，所有任务继续走原流程。

## 一次调用的固定流程

1. **主助手准备任务包。**指定关联 task_id、唯一问题、最少文件/相关代码、固定输入哈希、期望输出、禁止动作和停止条件；先去掉我们自己已能确定的问题。
2. **人工提交。**在实际安装的官方扩展中提交任务包，明确只读；仅提供有权提交的相关源码。若只能在原工程操作，核对工具的文件/命令权限，不把提示词当隔离机制。
3. **保存原始答复与消耗。**结果写入 `workflow/records/<task-id>/ic-<request-id>-result.md`，引用源版本；消费记入下面台账。没有实际调用就保持未执行。
4. **主助手逐条复核。**对发现补独立可复现用例或读实际路径/约束。接受后才进行最小修改，运行相关测试；不直接采信 PASS、器件能力、时序或板测结论。
5. **回到同一任务。**任务 ID、证据和状态仍沿用现有工作流，不另开一套重复项目管理。无有效发现也可记录覆盖范围，但不能视为验证通过。

输出建议最多 3 个有证据的发现，每个给位置、触发条件、影响和最小测试。没有发现就报告审阅范围/局限，不强行凑问题。原始日志先用本地工具定位首错，只交必要片段；波形先裁剪到关键时窗和信号，不能假定裁剪内容覆盖全部原因。

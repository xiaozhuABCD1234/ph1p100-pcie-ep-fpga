- **A 的出口必须有本地消费者。** RAW writer 发布后保护帧槽，原链路的释放主要关联 pusher 消费；没有 RK 时，不能只关掉发送就期待持续采集。应为 A/B 两路接入或适配本地 DDR 读回/CRC 检查器，正确读取并完成后释放对应槽，失败时按明确策略回收或保护。由此形成“采集→完整帧发布→本地读回核对→释放→下一帧”的 FPGA 内部闭环。
- **D 交付独立 RTL。** 包括 A/B 完整帧描述符队列、帧级公平调度、RAW 槽所有权、R10F 载荷读取/256 bit 到 packed RAW10 40 bit 适配，以及编码完成/失败后的释放。先用冻结单 A+ 核、native DDR 模型和本地输出校验 sink，验证交错两路图案能够完整编码还原；单核分时不承诺双路 1080p30 实时。
- A/D 先约定发布描述符、接纳/拒绝、读所有权和释放接口；本地 CRC 消费者与编码调度器互斥选择，不能对同一 RAW 槽分别发释放。
- **E 可作为后续 FPGA 包。** 同一已发布 RAW10 帧可以分别进入三算法和 A+ RAW10 无损分支；算法的 32 bit Y8 输出不能直接接 A+ 的 40 bit packed RAW10/Bayer 输入。若要求压缩算法输出，需要另行定义输入格式、长度、变换和 CRC，不能用接线替代适配。
- F 的恢复移植与 b11 修改重叠，先保留差异映射/独立补丁，最终迁入等 b11 停改并冻结。

### A 的关键迁移点

- 同步模块进入真实工程源集合，不能只保留仿真 overlay。
- b11 相机配置器已有掩码读回、超时、standby/start；同步覆盖层配置器是另一版本。保留现行读回能力，初始化/读回完成后保持 standby，再交给同步控制器独占事务；不能整文件覆盖。
- AE/配置/同步启动明确 I2C 所有者，旧响应不能跨 reset/session 计入新事务。
- 可先在新命名 adapter 和独立候选中实现；不要求先完成双核 A+ 才推进 RAW 双路同步。

### B/C 的关键合同点

- 旧 R10F v1 是 128 B 头、codec0、packed RAW10；A1U1 是 44 B 头的 A+ 内容。不能塞入压缩数据后仍标 codec0。承载选择需匹配双方实际入口。
- b11 桥接是 256 bit 单拍 PAXI；旧 pusher 使用 AXI 读口，需要适配，不能直接接线。
- 共用解码模块应检查头/码流/变换域/RAW 四 CRC、精确长度和严格解压 EOF，并完成逆变换；复用现有算法，不重写 codec。
- 177 B v3 和 225 B v4 状态包按版本分流；不能截取 v4 前 177 B 按 v3 校验。
- A1U1 本身没有完整 A/B/session 元数据。外部描述符必须携带明确身份；目前没有真实共同时间戳时写 unknown。

## 3. 值得提前处理的系统问题

### 双路不能直接外推单核结果

- RAW10 1920×1080：每帧 2,592,000 B；单路 30fps 为 77.76 MB/s，双路为 **155.52 MB/s**。
- b6 指定向量核级结果为 **81.067 MB/s**，其他向量速度不同。既不能保证所有场景实时，也不能由单核单路通过推导双路通过。共享引擎服务不足时，增加队列不能消除长期积压。
- 当前 RAW store 每 256 bit DDR 字存 4 个 40 bit 组，即 **20 B 有效数据占 32 B**。单帧实际 RAW 槽占 4,147,200 B；双路 30fps 原始写流量为 **248.832 MB/s**，还未加 RAW 读、CMP 写读、预览和仲裁损失。
- 旧整链方案多处仍按 RAW12 预算，不能当当前 RAW10/A+ 的最终预算。
- T09 原生产候选 ERAM200/300，b6 板链 ERAM102/300。两套顶层有共享逻辑/IP，不能直接相加，也不能认定合入一定容纳；统一候选必须重新核算资源、STA/CDC。

### 同步观测还没有传到底

T08 overlay 的 `skew/pair_seq/timestamp/miss/relock` 等部分输出悬空；现行 R10F writer 的 SOF timestamp 与 timestamp_hz 写零。可在 A/C 内提前接通采样快照、元数据和宿主记录。接收 SOF 的偏差是链路观测，最终曝光同步仍须传感器同步信号或外部测量证据，同序号不能替代。

### 本地历史 RK 示例要局部修审

10/17 raw 候选的 `frame_grab.rs` 按 `width×height` 分配图像缓冲，却按 DMA 传输长度执行 `copy_nonoverlapping`。1080p RAW10 的 DMA 2,592,768 B 大于 2,073,600 B 分配，存在越界写风险；该示例也不能直接当作已完整实现 ARM/held/ACK 的连续运行器。

这是**本地历史副本**的静态问题，不是对队友当前成功程序的判定。复用该源码前做小范围修复和回归；不直接替换队友成功工程。部分旧 run 主源路径未找到时，先核对归档与 manifest，再取补丁。

## 5. 当前推荐排法

1. **OpenCode 继续 b11**：读路径、现候选构建/板测由原责任角色完成。
2. **新增主线 A**：生产 RAW 双路同步迁入候选，保留现行 I2C 读回/超时能力，接出同步观测，并补齐两路本地读回 CRC 消费及槽释放。直接推进当前双路终点，不依赖 RK。
3. **新增主线 D**：双路描述符、RAW/CMP 所有权与帧级 A+ 调度；先交付独立小顶和真实核离线闭环，之后再接统一生产 DDR 口。预算计算作为实现输入，不单独充当主要成果。
4. **后续 E/F**：E 先明确 RAW10 与 GRAY8 分支边界；F 等 b11 冻结后统一迁入，避免多个责任人同时修改同一 top。G 的数据工具可轻量准备。

若当前只新开两个正式包，建议选 **A + D**。B 的 FPGA PCIe 发送端本身仍可用仿真接收器开发，但当前后置；B/C 的 RK 端软件和实机联调不列为本地并行主线。H 随交付整理。R3 旧响应跨复位定向仿真作为次级风险项保留。

各包只写独立目录，冻结输入、独立仿真库与日志；共享 TD/盘符/板卡操作串行。正式 G2、下载、曝光测量和实机持续吞吐不能由离线产物代替。

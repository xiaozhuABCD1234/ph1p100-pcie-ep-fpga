## 3. 预期现象

| 观察项 | 正确现象 | 能支持的结论 |
|---|---|---|
| 显示器 | 1080p60可见真实灰度图，移动物体时画面更新 | 本版HDMI选择DDR取数；尚非每个像素/性能量化实测 |
| D37 | 持续闪烁 | DDR ready后的用户时钟心跳仍在 |
| D38 | 最终保持亮 | 至少一次读显示源帧的CRC与元数据检查通过 |
| D39 | 保持灭 | 尚未触发已接入的CRC/原生读协议/像素欠载粘滞错误 |
| D40 | 保持亮 | A路相机配置流程完成，不能单独证明MIPI数据无误 |
| 灰度、细节与流畅度 | 与原预览近似，960×540内容2倍放大到1080p60 | 相机仍4K30采集；显示60Hz会重复源帧，不是采集60fps |

D39新增了显示欠载汇总：亮后即使下一帧恢复也保持亮，需重新下载/复位清除；不要仅凭当前画面恢复就记为无错误。D38通过是至少一次，当前LED不能给出持续通过帧数。重复完整旧帧是设计允许的行为，所以还要用手移动确认采集持续更新。

## 4. 异常时如何反馈

| 现象 | 先记录什么 | 本轮判定 |
|---|---|---|
| 黑屏，D37不闪 | 下载成功界面、供电状态、四灯状态 | DDR初始化/用户时钟或下载身份未确认；先停在此处反馈 |
| 显示锁定但全黑，D37闪 | D38/D39/D40，以及等待时长 | 可能尚无完整帧或读显示握手异常；不能只归因相机 |
| 有图，D39亮/偶发黑帧 | 亮灯前后现象，是否持续更新、是否滚动/错位 | 已记录错误；下一步读具体计数/ILA，不盲目改时钟 |
| 频率超范围 | 显示器提示与本次bit路径 | 本版固定60Hz，不恢复30Hz测试；检查下载身份/本版发送路径 |
| 只有绿色闪点仍在 | 闪点是否仍只集中在突变区域 | 原未决问题仍在，不能判定DDR一定损坏或已修复 |

本次反馈只需包含：**下载成功与否、有没有动态真实图、D37/D38/D39/D40四灯、约1分钟是否黑帧/冻结/错位**。若异常，先保留该现象再讨论下一项。

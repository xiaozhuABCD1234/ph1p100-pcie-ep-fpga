## 1. 域 A — b9 RTL 审计（三项缺陷 + 三项风险）

### 1.1 结论
**三项主缺陷（B9-01/02/03）全部在源码中被严格确认，无误报。** 三项风险（R1/R2/R3）机制真实存在，但 B9-R1 的行号引用有偏差。

### 1.2 B9-01 状态包 / 帧出队互锁 — 确认
- `a1_uart_export.v` L299 `if (sts_tick) sts_want <= 1'b1;`
- L302–303：状态启动条件含 `(dq_cnt == 2'd0)`；
- L335：帧出队条件含 `!sts_want`。
- **死锁链**：第一帧发送中 → 第二帧描述符入队 → 状态定时到期 → `sts_want=1 && dq_cnt>0` → 状态等队列空、队列等状态消失，双方都不前进。后续 tick 不能解锁（`sts_want` sticky，仅 L312 状态真正启动时清）。
- **额外发现**：L294 `tx_valid_r` 清除与 L299/L302/L335 同拍调度，board 模式下 `STS_DIV>0` 使 `hb_en` 为 false，heartbeat 不能与 status 同拍；但 `STS_DIV=0` 时 status 不能启动，两者靠配置互斥——**仅在这些模式守卫下安全**，不是结构安全。

### 1.3 B9-02 描述符队列指针越界 + 同拍计数覆盖 — 确认
- L138 `reg [255:0] dq [0:1];`（容量 2）
- L139 `reg [1:0] dq_wr, dq_rd, dq_cnt;`（指针 2 位）
- L279/L344 自增可达 2/3 → 越界索引；
- L280/L345 同 always 中分别非阻塞赋值 `dq_cnt`，同拍 push/pop 时后者覆盖前者；
- L273 满队列拒收只计数，不生成 loss-abort， rejected push 形成孤儿槽风险。
- **建议修法**：1 位环绕指针 + 集中计数更新 + 明确满队列同拍出入策略。**只移植适用逻辑，不能整文件覆盖**（Codex 隔离候选没 b9 的 status v3 扩展）。

### 1.4 B9-03 1080p 四槽地址重叠 — 确认
- `W=1920/H=1080`、`RAW_WORDS=129600`、`CMP_WORDS=81085`、`RAW_BASE=0`、`CMP_BASE=131072`。
- RAW1 [129600,259199] 与 CMP0 [131072,212156]、CMP1 [212157,293241] 均重叠。
- 提案 `CMP_BASE=262144`：CMP0 [262144,343228]、CMP1 [343229,424313]，与 RAW1 结束 259199 不重叠，余量 2944 字。`CMP_BASE >= 2*RAW_WORDS=259200` 满足。
- **额外发现**：`a1_ddr_slot_store.v` L150/L160 用 `SLOT_WORDS` 作完整槽步长，布局与地址数学内部一致；但 `a1_ddr_slot_store.v` 读 FSM 进入 `R_HOLD` 等 `rd_close`，**无超时/恢复**，close 丢失则槽不释放。

### 1.5 B9-R1/R2/R3 风险 — 确认，但 B9-R1 行号有偏差
- **B9-R1**：审计引 top L273–283 为 FIFO 拒收决策；实际 L273–283 是相机域 abort-hold/溢出计数器，**clk_a1 域的接受/拒收决策在 L340–348**。L397 `if (e_last) raw_active <= 1'b0;` 在 LAST 进入 skid 时清 `raw_active`，而 store 可能还没消费 skid——机制真实，行号引用错。
- **B9-R2**：bridge L154–168 `wf_pop` 注册在 DDR 域，FIFO pop 延迟一拍；地址/数据直接取 FIFO 读数据；A1 侧要求 AW+W 同时 valid。风险结构真实。
- **B9-R3**：`ar_pending` 仅在 AR 握手置位、`paxi_rvalid && paxi_rready` 清除；响应 FIFO 16 深度可容纳超单 AR 的响应，清位条件依赖 FIFO 写就绪而非 A1 消费者 `s_rready`。旧/迟到响应可清掉新事务的 pending。风险真实。

### 1.6 其他 RTL 细节（审计新增）
1. `camera_a1_uart_top.v` L485 压缩 store 实例化 `ddr_ready(1'b1)`，**假设 DDR 永远就绪**，与 raw store 使用 `i_ddr_rdy` 不一致。
2. board top 不向下传 `STS_DIV`，使用默认 `187500000`；`HB_DIV` 传了但 `hb_en` 要求 `STS_DIV==0`，board 模式下 heartbeat 关闭——LED0 是自由计数器，**不能作业务复位/DDR 就绪指示**。
3. `p2_ddr_bridge.v` 单一 `rst_n` 跨两时钟域，FIFO 各有复位同步器；stale 响应跨复位隔离风险真实。
4. `a1_ddr_slot_store.v` 无 close 超时/恢复。

### 1.7 严厉结论
三项缺陷是**代码已确认、离线已复现**的问题，不是"怀疑"。但：
- **板上根因仍未确认**：LED/计数器不能替代寄存器/波形；"零字节窗口"与"150s 有效 v3 窗口"是不同时段，不能混用。
- **b10 r1 尚未开跑**：final-summary 明确 `r1 未启动`、G2/G3/G4 `not_run`、下载 0/2。任何"b10 已修"的表述都是虚假进度。

## 4. 域 D — RK 软件基线与 PCIe 集成

### 4.1 r10f_strict.py 自测
- **实跑结果**：`{"checks": 38, "failures": 0, "marker": "CONTRACT_VECTORS_OK"}` — **与 README 声称一致**。离线向量自检通过。

### 4.2 RK 基线 README 的八项要求
README 列出八项必须固定的字段（环境、FPGA 数据来源、驱动、接收/解码工具、输入与传输、图像与字节合同、成功样例、性能与通过标准）。**但 repo 中没有任何 `baseline/rk-image-v1/` 目录或 `actual.json`**——README 是"操作指南"，不是"已完成的基线"。目前只有指南，没有冻结的 RK 基线。

### 4.3 frame_grab.rs 缓冲区越界写 — 确认
- 代码：`npix = width * height`（1920×1080 = 2,073,600），分配 `img` 为 `npix` 字节；`copy = hdr_len`（= slot_bytes = DMA 长度）；`copy_nonoverlapping(src, img, copy)`；仅事后 `if copy < npix` 警告，**无上界检查**。
- 对 1080p RAW10：DMA = 2,592,768 B > npix = 2,073,600 B → **堆缓冲区溢出**。进度文档的"越界写风险"描述准确。
- **注意**：这是**历史副本**的静态问题，不是队友当前成功程序的判定。复用前必须小范围修复并回归。

### 4.4 证据现状
- **"RK 真实收图解码已通"** 仅有用户反馈，repo 中无日志、样例、版本、命令。RK 基线 README 明确："没有在队友机器执行，也没有代填其版本"。
- `tools/pcie_integration/` 与 `upstream/` 目录存在（r10f_strict.py 通过），但 RK 成功入口、驱动版本、DMA 连续帧/序号/吞吐/恢复均无证据。

### 4.5 A+ 压缩帧 vs R10F RAW10 合同
- R10F v1.0：codec0、packed RAW10、stride 2400、raw 2,592,000 B、content 2,592,128 B、dma 2,592,768 B。
- A+ 压缩帧：44 B A1U1 头 + 连续 stream_len 字节压缩载荷，CRC + zlib。**不能塞入压缩数据后仍标 codec0**。
- B/C 工作包正确指出："不能用接线替代适配"——A+ 输出是 32-bit Y8，不能直接喂 A+ 的 40-bit packed RAW10/Bayer 输入。需要另行定义输入格式、长度、变换、CRC。

### 4.6 严厉结论
- RK 侧的"已通"是**用户反馈，不是证据**。在 RK 基线冻结（版本/命令/样例/SHA）之前，任何"RK 已集成"的表述都是超前。
- PCIe 侧的"连接成功"是**单次枚举/链路**，不是连续 DMA/吞吐/恢复。`frame_grab.rs` 的越界写必须在复用前修复。
- **A+ 压缩帧与 RK 端的合同尚未对齐**：需要新配对版本，旧软件基线保留。

证据链**基本完整但有 7.4% 断链**，主要集中在已删除/迁移的 run 与顶层目录。**断链本身不是造假，但会让"证据可追溯"的承诺落空。** 建议做一次证据链修复（不删除历史，只修正引用与归档）。

## 7. 域 G — b10 两项补充仿真与 R1 反例

### 7.1 连续三帧 — PASS（小几何）
- 3 帧 ID 1/2/3，源 seed 111/222/333，每帧 RAW/变换 640B + 666B zlib；四 CRC + 严格 zlib 结束全部正确；状态包仅在帧间；覆盖有排队帧时状态先发、后续帧继续的行为。
- **边界**：64×8 ROI、FIFO 深 4、合成相机、行为 DDR；**不证明 1080p、真实 DDR/PHY、板速、STA/CDC、真实板故障根因**。

### 7.2 R1 — 有效 FAIL（故障反例）
- FIFO 满且拒收包含 LAST 的 3 组 → 释放背压 → FIFO/skid 空但槽仍 WRITE；观察至 151559 个 A1 周期，恢复包 0、begin_deny=2、raw_abort_cnt=0。
- **不是**"仅丢 LAST 单拍"，**不是**"所有未来输入永久无法恢复"——是"规定窗口内槽未回收、后续好帧未恢复"。
- 机制与源码一致：冻结 top 在 FIFO 拒收时仅计数，无 loss-abort；LAST 未到达后 writer 保持；后续 SOF 因 `raw_active` 被拒。
- **源码注释中的历史 R1 修复描述不代表实际逻辑已包含**——当前候选 FIFO 拒收仅计数，与反例一致。
- **首轮相机过快导致 clean 本身溢出（INVALID_CONTROL）** 已保留并分类，最终改 5MHz 相机/4 深 FIFO，仅改 TB。

### 7.3 严厉结论
R1 反例是**项目中最有价值的新证据**：它把"未覆盖"推进为"有有效反例，尚未修复"。但：
- **不能**把 R1 反例写成"b10 已通过"或"b10 已修复"；
- **不能**把 3 帧 PASS 扩大为 1080p/整机 PASS；
- 修复方向明确：FIFO 数据丢失 → 有序 abort → RAW/skid/槽回收 → 后续 SOF/好帧恢复；**只加计数或扩大 FIFO 不能宣称恢复通过**。

## 8. 跨域问题：冗余、纰漏、优化空间

### 8.1 冗余（Redundancy）
1. **叙事冗余**：同一事实（b6 吞吐、RK 已通、b10 未闭合）在 3 份整合文档 + README + tasks.json 中重复出现，且版本不同步（C-2 数量级错误就是例证）。
2. **任务冗余**：T05/T12、T03/T07 重叠；T09 done 与 T06/T10 生产接入记录重叠。
3. **证据冗余**：`final-summary.md` 有字节完全相同的副本 + 不同版本的副本，无权威标记。
4. **"PASS" 词冗余**：G0/G1 pass、round0 PASS、"首次独立综合 round0 PASS" 等在 4 份文档中反复出现，极易被引用时剥离 "隔离/非生产合格" 限定。

### 8.2 纴漏（Loopholes / Gaps）
1. **没有统一 manifest**：b6 core + b9/b10 修复 + Codex 恢复 + 同步覆盖层 + RK 配对，从未合为一体。任何"整机通过"表述都无依据。
2. **板上根因未确认**：LED/计数器不能替代寄存器/波形；"零字节窗口"与"有效 v3 窗口"是不同时段，不能混用。
3. **RK 基线未冻结**：只有指南，没有 `baseline/rk-image-v1/`。
4. **同步观测未接到底**：skew/pair_seq/miss/overrun 悬空，A+ 无法消费。
5. **frame_grab.rs 越界写**：复用前必须修复。
6. **tasks.json 失真**：snapshot_date 过期、latest_run_id 指向不存在 run、state 与 blocker 矛盾。
7. **证据断链 7.4%**：主要是已迁移 run 与顶层目录。
8. **下载预算未核账**："剩 1 次"仅是截图记录，未在文档中作为现行额度确认。

### 8.3 优化空间（Optimization）
1. **任务板整编**：修正时间戳、run 引用、state 语义，新增 A/D 任务条目；拆分 T05/T12、T03/T07 边界。这是最低成本最高收益的动作。
2. **证据链修复**：修正 README 断链、run 引用、归档孤儿 run、去重 final-summary、补 T08 overlay SHA。不删除历史。
3. **统一 manifest 试点**：先做 "b6 core + b9 三项修复" 的最小合并候选，绑定 SHA，跑受影响路径。这是 b10 r1 的自然延伸。
4. **RK 基线冻结**：按 README 八项要求，队友在无 FPGA 的情况下先完成环境/命令/样例/耗时，再配对。
5. **同步观测接通**：先连 timestamp（不改格式），再评估 skew/pair_seq 是否需要格式变更。
6. **frame_grab.rs 修复**：加上界检查（copy <= npix），小范围回归。
7. **板上根因定位**：用 ChipWatcher/CWC 映射 `estate/sstate/sts_want/dq_cnt/raw_wr_state/raw_rd_state/a1_busy`，不能只看 LED。
8. **文档去重**：建立单一权威版本（顶层 final-summary），其他为 `_archived`。

## 11. 严厉导师的最终寄语

# RK 软件与解码基线：队友无需连接 FPGA 板

日期：2026-10-24；状态说明于2026-10-25复核。**FPGA 板由用户在本地调试；队友负责 RK，目前无法连接该 FPGA 板。用户已明确确认 RK 真实图像接收和解码已通。** 本文以队友当前实际成功的软件为起点，先固定文件输入的 RK 解码基线。没有在队友机器执行，也没有代填其版本或宣称已冻结；本次 A+ 兼容和实机连续链路需另有配对证据。

## 目标

当前交付应说明：给定哪份输入文件、哪个版本的 RK 解析/解码程序、什么依赖和命令，能够还原什么结果，长度/CRC/像素是否一致，离线解码耗时多少。

| 谁负责 | 当前产出 |
|---|---|
| 用户及 FPGA 助手 | 继续板上调试；导出后提供原始数据、格式说明、参考还原 RAW/CRC、样例 SHA 和候选身份 |
| 队友及其 AI | 固定 RK 软件/依赖与命令，用收到的文件解析、解码、比对并返回结果；无需操作 FPGA |
| 双方后续联调 | 硬件连接具备时再验证 PCIe DMA 实收、连续吞吐/丢帧与恢复 |

实际协议从程序和配套样例确认，不强制套用较早规划。真实 FPGA 样例尚未取得时，先用现有且格式匹配的合成向量验证软件并标明 synthetic；环境/源码/命令记录照常完成，不因缺少 FPGA 板停下。

## 一、必须固定的八项

| 项目 | 最少记录内容 | 从哪里取得 |
|---|---|---|
| RK 环境 | 板型、系统发行版、内核版本、架构、PAGE_SIZE；实际用到的编译器/Rust/Python/解码依赖版本 | 运行机器；不要猜本机环境等于队友环境 |
| FPGA 数据来源 | 有真实样例时记录用户提供的 bit SHA/协议/相机模式；标 real_fpga 或 synthetic | 用户随文件提供；队友无需确认现场 SRAM，无真实样例时此项 pending，不阻塞软件记录 |
| 驱动 | 保存现有源码/构建版本和配置（若有）；离线解码不要求加载模块 | 当前工程；实际加载和 DMA 行为留到联调，无条件时写 not_run |
| 接收/解码工具 | 源码 commit/必要 dirty 快照、可执行文件 SHA、构建命令、运行工作目录、完整参数/配置、必要依赖版本 | 当前成功入口；只记 HEAD 不足以覆盖未提交改动 |
| 输入与后续传输 | 当前固定文件类型、入口参数和解析规则；BDF/设备节点/ARM/ACK等实机字段留到联调 | 文件与当前程序；未连接 FPGA 时硬件字段写 not_run，不作为本阶段前提 |
| 图像与字节合同 | A/B 身份、尺寸、ROI、RAW/GRAY/RGB、有效位宽、packing/端序、stride、Bayer/方向、头/载荷/DMA长度、版本/codec、CRC覆盖和序号语义 | 实际程序+真实原始文件；自动曝光/增益策略及可取得的设置也记录；物理 Bayer 相位未验证则标 unknown |
| 成功样例 | 原始输入、参考 RAW/图像、头字段/长度/CRC、SHA和来源；先有合成样例也可验证对应软件范围 | 用户提供或现有共享向量；PGM/PNG alone 不足以验证传输字节，合成与实拍分开标注 |
| 性能与通过标准 | 固定输入的解析/解码结果、逐像素/字节差异、离线耗时 | RK 本机文件测试；PCIe吞吐/采集fps/丢帧/恢复写 not_run，不能由离线速度推导 |

“固定”是保存一个准确可追溯的组合。同一份冻结文件重跑，应得到相同解码 RAW/像素和校验结果；新场景/协议登记为新样例。BDF等硬件动态字段留到联调，不要求队友现在填写。

## 二、队友 AI 第一次怎么做

### A. 找到当前成功入口，先记录

在队友的实际工程根运行。先读当地 AGENTS.md/README，定位操作者当前成功使用的脚本、终端命令或启动配置。不要用本地旧参考工程替换成功工程。

可使用以下只读命令获取基础信息；工具不存在就记录缺项，不自动安装/升级：

```bash
uname -srmo
cat /etc/os-release
getconf PAGE_SIZE
git rev-parse --show-toplevel
git rev-parse HEAD
git status --short
```

先核对 Git 返回的根目录确实对应当前源码仓库；子目录可能回落到父仓库，不能把父仓库 HEAD 冒充独立 driver 提交。无独立 Git 身份时记录实际父仓库路径及该源码子树快照/文件 SHA。

对必要源码、程序、配置和样例使用 `sha256sum <明确文件>`。PCIe枚举、链路速率和已加载模块检查留到联调，不在队友当前无FPGA阶段执行。

工作树有修改时保存构建相关源码/补丁和 SHA；排除密钥、.env、个人信息及无关文件，不导出整个环境或全部系统日志。

### B. 从文件复现一帧

使用当前软件实际支持的文件输入命令，记录工作目录、参数、配置、返回码和日志。保存输入 SHA、解析字段、解码 RAW/图像，与用户提供的参考做字节或逐像素比对；PNG编码文件的哈希不能代替像素比对。

核对输入来源、尺寸/长度、解码结果、协议支持的 CRC 和参考还原数据。session/seq 按样例核验，不要求离线重跑生成新相机帧。没有参考 RAW、CRC 或真实样例时分别列缺项，不伪造校验通过。

若现有程序只支持实时设备，没有文件入口，先记录源码/依赖/命令并列出“缺文件输入适配”的具体位置；本次不自动改驱动或硬件控制，也不要求队友连接 FPGA。后续可单独安排小范围文件输入适配。

### C. 测量离线解码耗时

先确认一帧正确，再记录工具能够区分的文件读取、解析校验、解压/逆变换和输出耗时。现有工具支持重复离线运行时可有界重复同一冻结样例，记录次数、预热和计时范围；无需新写持续 DMA 控制。

- 离线解码 fps = 成功解码次数 / 对应秒数；重复同一文件不是接收新相机帧。
- 离线 MB/s 标明统计输入码流还是还原 RAW 字节；它不是 PCIe DMA 吞吐。
- 固定样例/程序/配置和计时范围；没有分段计时就只报总耗时。
- 真实采集帧率、传输丢帧、硬件恢复与端到端延迟写 not_run，留到联调。

### D. 保存最终复现入口

在队友工程中新建专用目录，例如 `baseline/rk-image-v1/`，不覆盖旧文件：

```text
README.md              文件输入步骤、适用范围与版本
baseline.actual.json   上述八项实值、动态字段规则及文件 SHA
commands.md            本次真正运行成功的完整命令、工作目录与退出码
samples/               冻结输入、参考数据与解码输出，标明真实/合成
logs/                  环境摘要、文件解码与离线耗时日志
result.json            各项结果、计数、性能、缺项
SHA256SUMS             必要文件及样例的 SHA256
```

状态用 `pass/fail/not_run/blocked/not_measured`；分别报告环境记录、合成样例解码、真实FPGA文件解码、实机传输四项。缺FPGA硬件只影响最后一项；缺真实文件不阻塞环境与已有合成向量检查。离线通过不称完整收帧或稳定性通过。

有了 actual.json 和 commands.md 后，后续 AI 先比对版本/配置/文件 SHA，再执行记录中的成功命令；出现变化就标为新候选，旧基线保留。无须每次重新探索工程。

## 三、本项目能复用的离线检查

以下路径以我方 `D:\fpga\ph1p100` 为仓库根，转交队友时保持相对结构。记录并复现其现有链路只需本文与队友当前工程；若要使用本节我方离线检查，另提供 `tools/pcie_integration/r10f_strict.py` 和 `upstream/ph1p100-pcie-ep-fpga/docs/protocol/rka1-r10f-v1/` 中的 contract/artifacts 文件。缺少这些文件时标为未执行，不让 AI 凭空重写一个校验器后称为同一基线。

**只有实际样例确认为 R10F v1.0、codec0、packed RAW10 时，才应用本节严格校验。** 其他格式使用队友当前匹配解析器并保存规范，不为通过本检查而修改数据。A+ 压缩帧要用它自己的配套解码器。

```bash
# 离线：标准库 Python 3，检查共享合成向量及负例，不访问硬件。
python3 tools/pcie_integration/r10f_strict.py selftest \
  --run-dir upstream/ph1p100-pcie-ep-fpga/docs/protocol/rka1-r10f-v1

# 离线：文件必须恰好从 R10F 头开始，包含 dma_bytes；不能混入 host 槽前缀。
# 替换真实样例和独立确认的会话/尺寸后再执行。
python3 tools/pcie_integration/r10f_strict.py check samples/actual-frame.dma \
  --session <实际授权会话> --width <实际宽度> --height <实际高度> \
  --json-out logs/actual-frame-check.json
```

R10F v1.0 的 1920×1080 packed RAW10 参考值：stride=2400，raw/payload=2,592,000 B，内容头128 B，content=2,592,128 B，dma=2,592,768 B，尾零640 B。host 槽偏移是另一层，不能把两层128 B混为一谈。此处是已知合同，不代表队友现用格式已确认。

我方本轮在 Windows/Python 3.11 执行上述 selftest：**38 项、0 失败**。这是离线向量自检，不是 RK 真机复测。

本地 driver 的 `app/rs/src/bin/frame_grab.rs` 当前描述的是灰度 PGM 导出；不得仅因名字相同就视为队友正在用的 R10F/A+ 接收器。实际使用的程序以队友成功入口为准。

## 四、执行边界

本轮只在队友 RK 记录软件并从文件复现解码；不需要接入或操作 FPGA。不要自动 pull/覆盖源码、升级系统/依赖、卸载驱动、重启、下载 bit、改 PCIe 参数或寄存器。实机采集和驱动生命周期验证留到后续联调。

禁止批量删除或用清理脚本删除目录；输出写新目录。失败保留完整返回码和最小相关日志。无法完成的项写具体原因，不无限重试，不把合成图当真实图。

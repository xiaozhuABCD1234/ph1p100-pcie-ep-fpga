## 1. 这次改了什么

链路为 IMX415 → 现有软D-PHY → CSI-2/RAW10解包 → 960×540灰度预览 → 1920×1080p60 HDMI。

| 环节 | 本次状态与定位 |
|---|---|
| 相机 | 保持4K30、RAW10、4lane 891Mbps/lane、27MHz MCLK；寄存器、I2C和接收tap未改 |
| 时钟 | 新增手写 `uisrc/01_rtl/raw10_display60_clocks.v`，复用未改的生成PLL底层包装；输出148.5/742.5/27MHz |
| 发送 | `uisrc/03_ip/alip/ui_HDMI_TX/lane_lvds_10_1.v` 的PH1P分支使用HR_OSERDES DDRX5；位序、像素域复位与已成功的独立诊断一致 |
| 顶层 | `uisrc/01_rtl/f9p_imx415x2_top.v` 实例化新时钟；VTC总长2200×1125保持，频率变为60Hz |
| 工程清单 | `fpga_prj.al` 已登记新时钟和camera_startup，保留旧run元数据；CLI构建脚本也显式添加它们 |
| 图像存储 | 仍为原ERAM预览，224块；没有DDR、完整帧交换或PCIe |

显示60Hz与采集30fps分开记录；此版本不增加相机独立帧数，不恢复彩色。ERAM并发读写仍可能撕裂，DDR完整帧队列是下一步。

2. 等待相机初始化。观察是否有真实灰度图像；遮挡镜头或移动物体，确认画面响应。固定条纹不能算视觉通过。

UART中STAT的配置/错误、lane锁定状态与CNA/CKA一起判断。CNA/CNB是每0.5秒窗口内事件数量，正常时可保持近似恒定，不要求逐次递增；sticky pkt/vs只证明曾见到事件。CKA正常数量约1699/1700是翻转双边沿统计的估算，不能直接当精确频率测量。ERA是错误状态采样累计，不能当独立NACK次数。定义以顶层遥测代码为准。

## 3. 软件证据与限度

`syn_display60_20261011_174231` / `phy_display60_20261011_174231`：最终setup WNS +0.008ns、hold +0.020ns，TNS均0，覆盖99.79%，异常目标报告为空。裕量较小；后续任何RTL修改都需重新跑STA。报告：[timing](evidence/raw10_display60_timing.rpt)、[ignored](evidence/raw10_display60_ignored.rpt)、[机器记录](evidence/raw10_display60_20261011.json)。跨时钟例外没有因本次改动放宽，STA不能替代CDC与完整帧一致性验证。

本轮回归：生产串行器三相位、每相位2400bit/两次复位；像素域复位释放；两种预览读模式逐帧序列；DE/RGB/HS/VS包装对齐，均通过。原语功能模型关闭timingchecks并保留厂商告警，测试频率100/500MHz；不等于集成148.5/742.5MHz硬件验证。PLL检查是有效参数审计，不是实际输出频率测量。

首轮综合因实际D盘工程清单缺少camera_startup而失败，已补登记并创建新run完成构建；失败run与日志保留。独立代码审查发现镜像工程未登记新时钟，已修复。

当前板独立1080p60测试成功来自用户反馈。原HRIO输出规格、LVDS33_E约束和1485Mbps板外速率边界仍按[显示路线记录](60Hz显示主线与真实RAW10接入_2026-10-11.md)保留；可见画面不代表额定电气性能、长期稳定性或协议认证。

# 相机写入DDR：本轮操作与预期

本轮把真实相机的960×540灰度图写入DDR，再读回全部图像字节校验CRC32。上一轮已经通过的是内部测试图案；这一轮换成真实相机数据。HDMI仍从原ERAM读取，所以这是相机→DDR存储验证阶段，下一步再接DDR→HDMI。

## 本轮用户反馈

用户报告“呈现的都是列出的现象，都实现了”，同时明确绿色亮点仍出现在像素突变区域。对应本轮225520候选，记录相机灰度画面、D37闪、D38亮、D39灭、D40亮的用户验收反馈；至少一个完整真实灰度帧通过DDR CRC/元数据读回。没有独立下载日志、持续计数或观察时长，不扩展为每帧通过、长时间稳定或DDR显示已完成。绿色亮点按用户要求后续再定位。

下一实现步骤是DDR读出→显示FIFO→垂直消隐换帧→1080p60 HDMI。当前无需重复下载本候选；以下步骤保留作复测说明。文件保留及手动清理入口见[清单](文件保留与待删除清单_2026-10-11.md)。

## 你需要做的操作

1. 保留现在已工作的A路相机、VID006、HDMI、板卡电源与JTAG连接。显示器继续使用1080p60链路。无需连接香橙派，也无需重新生成PLL。
2. 在BitWriter中选择上方 **225520目录** 的`camera_ddr_capture.bit`，下载到FPGA SRAM。确认下载成功后保持供电；本轮不写Flash。
3. 等待约10秒，让DDR初始化和相机配置完成。HDMI应重新显示相机灰度画面。与上一轮没有HDMI输出的独立DDR程序不同，这次应该有图像。
4. 按下面表格观察D37、D38、D39；再看D40相机配置状态。不要用电源灯代替这些状态灯。
5. 缓慢移动镜头前的物体，观察画面能否跟随变化，再观察30–60秒，记录错误灯是否曾点亮。绿色闪点仍是待定位问题，本轮没有加入去噪或掩盖处理。
6. 回传一句结果即可：`画面有/无；D37闪/不闪；D38亮/不亮；D39灭/亮；D40亮/不亮`。暂时不用改相机参数、接收tap或时钟。

| 位置 | 正常预期 | 说明 |
|---|---|---|
| HDMI | 有相机灰度画面，移动物体时画面变化 | 显示仍走原ERAM，输出1080p60；采集仍为4K30 |
| D37 | 持续闪烁 | DDR处于ready，用户时钟心跳运行 |
| D38 | 点亮并保持 | 至少一帧真实灰度图完整写入DDR，全部读回字节CRC与帧号、长度校验通过 |
| D39 | 保持熄灭 | 未观察到CRC/元数据或后端协议错误的保持标志 |
| D40 | 点亮 | A路相机配置完成；它单独亮不代表图像DDR校验通过 |

灯均按低电平点亮设计。D38是保持标志，不能凭它一直亮就声称每一帧都通过；连续稳定性和丢帧率还需后续观察计数器。

## 如果现象不符

| 现象 | 本次先做什么 |
|---|---|
| D37一直不闪 | 保留供电和下载结果，报告D38/D39状态；先定位DDR初始化 |
| D37闪、D38不亮 | 报告是否有画面及D40状态；先定位真实帧进入DDR或回读检查环节 |
| D39点亮 | 保留现场，报告灯何时亮及画面现象；不要通过反复重下掩盖错误 |
| D38亮但HDMI没图 | 报告显示器提示及D37/D39状态；DDR校验与显示路径分开定位 |

## 这一步通过以后

将HDMI读源切到DDR，增加显示域取数FIFO、垂直消隐换帧和欠载处理，再验证运动画面。该阶段才形成相机→DDR→HDMI闭环。当前测试通过不等于双路同步、原始RAW完整帧、CSI包CRC、PCIe图像传输或RK链路已经完成。

CRC在相机侧对灰度字节计算，DDR侧读回后重新计算，作用是检测存储传输前后是否一致；它不能证明传感器像素本身准确，也不是无碰撞的证明。

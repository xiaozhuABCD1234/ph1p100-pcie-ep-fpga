## 2. 怎样判断一个工作包真的完成

每包至少留下源码/参数版本、验证结果和下一步。你负责理解功能、执行实物操作并回传现象；Codex负责资料定位、实现/测试支持和结果核对。

| 证据 | 记录什么 |
|---|---|
| 仿真 | 测试名称、实际PASS/FAIL、失败波形或错误位置 |
| 工具实现 | 器件、顶层、约束、实际综合/PnR/STA、未约束路径及资源 |
| 硬件 | 实际bit、连接/模式、读回或帧数据、错误计数、运行时长 |

这些不是要求每个包先补一堆表格再开工。调试时保存真实输出，结束用几行写清结果即可。

重点验证五类问题：相机不ACK/读回错误；接收停钟/失步；CSI尾拍/错误包；下游停顿/缓存所有权；连续帧与双路对应关系。各包在下文安排对应检查。

## 3. 哪些能独立做，哪些必须等联调

| 你可以独立推进 | 需要RK/队友参与才可最终验收 |
|---|---|
| 相机控制、MCLK/复位、ACK/读回 | PCIe实际枚举、RC配置 |
| PH1P前端、CSI/RAW12、真实帧检查 | C2H写入真实DMA缓冲与驱动生命周期 |
| 本地DDR读写、图像检查出口 | 实际PCIe持续吞吐和恢复 |
| 三算法、压缩参考/RTL/解码对照 | 实拍双目标定、RK匹配/深度及NPU整合 |
| FPGA端BAR/C2H激励仿真、统计寄存器 | 最终双方帧协议和交付日期冻结 |
| 双路接收、同步信号/帧元数据准备 | 端到端性能和最终演示 |

“FPGA独立”表示当前工作不被RK等待阻塞，不表示整队任务取消，也不表示DMA可以绕过RK驱动独自验收。

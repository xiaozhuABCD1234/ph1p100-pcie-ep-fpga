# 串口回环验证 · 详细操作（D1 步骤 3 第 2 项）

> 目标：下载 `02_uart_loop.bit`，用**串口助手**验证 FPGA 的 UART 收发正常。

---

## 一、先搞清这条链路是怎么走的

```
┌────────────┐   Type-C 线    ┌──────────────────┐              ┌─────────────────────┐
│  PC 串口   │◄──────────────►│ 板载下载器模块    │  UART        │  FPGA (PH1P100)     │
│  助手      │   USB 虚拟串口  │ YCM-J01 (FTDI)   │◄────────────►│  uart_top (回环)     │
└────────────┘                │ A=JTAG  B=UART   │  R17 / P16   └─────────────────────┘
                              └──────────────────┘
```

**要点**：板子的 **Type-C 一根线**同时承载 **JTAG（下载）** 和 **UART（串口）**，所以插上 Type-C 后电脑上应该能看到**两种设备**。

---

## 二、已核实的关键参数（来自工程源码 + 官方手册）

| 项 | 值 | 出处 |
|---|---|---|
| 下载的 bit | `D:\TD\work\bits\02_uart_loop.bit` | — |
| **波特率** | **115200** | `uart_top.v`：`BAUD_DIV = SYSCLKHZ/115200-1` |
| **数据格式** | **8 数据位 / 无校验 / 1 停止位（8N1）** | `uiuart_tx.v`：`UART_LEN = 10`（1 起始 + 8 数据 + 1 停止） |
| **流控** | **无（None）** | 源码里没有 RTS/CTS |
| 系统时钟 | 50 MHz（引脚 H4） | `fpga_pin.adc` |
| **FPGA TX** | **R17**（LVCMOS33） | `fpga_pin.adc` + 硬件手册 p16 |
| **FPGA RX** | **P16**（LVCMOS33） | 同上 |
| 行为 | **回环：收到什么就发回什么** | `uart_top.v`：`uart_wreq = uart_rvalid; uart_wdata = uart_rdata` |
| 复位 | 上电后延迟 32768 拍（≈0.65 ms @50MHz）释放 | `rstn_cnt[15]` |

> ⚠️ **注意**：工程里 `fpga_pin.adc` 中 `O_uart_tx=R17`、`I_uart_rx=P16`。
> **如果怎么试都没回显，第一件事就是把 TX/RX 理解反过来想一遍**（但按官方定义就是上面这个）。

## 三、驱动：COM 口能不能出来（这步最容易卡）

**官方说明**（《米联客-安路FPGA TD软件快速入门课程.pdf》p15~p17）：

> 安装驱动前，需将开发板上的下载器模块用 Type-C 与 PC 连接。
> AL-LINK-FT(Local Host) 又名 OneCable，需安装驱动 **winusb**。
> 打开驱动安装软件 **UsbDriverTool**（需管理员权限），找到 **`USB Serial Converter A`**
> —— 它实现 **USB 转 JTAG** 功能，**VID/PID = `0403/6042`**（FTDI 芯片）。
> 右键 → **Install WinUSB**。
> 工具下载：**https://www.uisrc.com/t-6233.html**

### 插上 Type-C 后，去「设备管理器」看什么

按 `Win + X` → **设备管理器**，展开：

1. **通用串行总线控制器 (Universal Serial Bus Controllers)**
   预期看到 `USB Serial Converter A`（可能还有 `... B`）
2. **端口 (COM & LPT)**
   预期看到 `USB Serial Port (COMx)` ← **这个 COMx 就是你要在串口助手里选的口**

### 三种情况怎么办

| 你看到什么 | 说明 | 怎么办 |
|---|---|---|
| ✅ `端口(COM&LPT)` 下有 `USB Serial Port (COMx)` | 正常 | 直接用，记住 COM 号 |
| ⚠️ 只有 `USB Serial Converter A/B`，**没有 COM 口** | 缺 FTDI 虚拟串口(VCP)驱动 | 装 FTDI VCP 驱动（见下），或到 https://www.uisrc.com/t-6233.html 下载米联客的驱动包 |
| ❌ 有**黄色感叹号**的未知设备 | 无驱动 | 右键 → 更新驱动 → 浏览到驱动目录 |

### ⚠️ 一个常见坑
如果你用 `UsbDriverTool` 把 **WinUSB 装到了整个设备**（而不是只装 Channel A），
**UART 那个通道也会变成 WinUSB 设备 → COM 口就不出来了**。
→ 此时要在设备管理器里**只对 `USB Serial Converter A` 装 WinUSB**，让另一个通道保留为串口。

> 驱动包位置参考：`D:\downlaod\driver\al-link\`（安路 AL-LINK）、`D:\downlaod\USBDriver\`
> 米联客驱动/工具统一下载页：**https://www.uisrc.com/t-6233.html**

## 四、串口助手怎么设

### 推荐工具
| 工具 | 说明 |
|---|---|
| **米联客推荐工具** | https://www.uisrc.com/t-6233.html 页面里的"测试工具" |
| SSCOM / 友善串口调试助手 | 国内常用，简单 |
| VSCode 串口监视器 | 你已有 VSCode |
| PuTTY / MobaXterm | 也行 |

### 参数（照着填）

| 项 | 值 |
|---|---|
| 串口（Port） | 设备管理器里看到的 **COMx** |
| **波特率（Baud）** | **115200** |
| 数据位 | **8** |
| 停止位 | **1** |
| 校验位 | **None（无）** |
| 流控（Flow Control） | **None（无）** |
| 接收/发送 | 都不要用 HEX 之外的模式干扰（先默认文本模式） |

### 操作步骤
1. 板子**上电**（12V 适配器），Type-C 连 PC
2. 先用 TD 下载 `02_uart_loop.bit`
3. 打开串口助手 → 选 COMx → 设 115200-8-N-1-None → **打开串口**
4. 在发送框输入 `hello`（或任意字符）→ 点**发送**
5. **接收区应该立刻出现 `hello`**（原样回显）

### 验收标准
- ✅ 发什么，回什么，一字不差
- ✅ 连发多次都稳定
- ⚠️ **建议发送间隔 ≥ 10ms**：这个例程没有 FIFO，收 1 字节立刻发 1 字节，**发太快会丢**

## 五、常见问题排查表

| 现象 | 原因 | 处理 |
|---|---|---|
| 串口列表里**没有 COM 口** | 驱动没装好 | 见 §三 |
| 打开串口报"**拒绝访问**" | 别的软件占用了该 COM | 关掉其他串口/TD 的串口监视 |
| 发出去**没有回显**，接收区全空 | ① 波特率不对 ② 板子没上电 ③ bit 没下载成功 ④ 复位还在拉 | 逐个查；先确认板子 LED 有反应 |
| 接收区全是**乱码** | 波特率不匹配 / 时钟不对 | 确认是 **115200**；确认 bit 是给 F9P（50MHz）的 |
| **偶尔丢字** | 发送太快（无 FIFO） | 加大发送间隔到 ≥10ms |
| 收到的是**自己的输入但错位** | 校验/停止位设错 | 改成 8-N-1-None |
| TD 里**下载成功**但串口无反应 | DONE 灯/现象没看 | 对照《开机测试》p5 看 LED 现象 |

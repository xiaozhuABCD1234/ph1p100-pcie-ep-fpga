## 1. 为什么先改相位再做白平衡

140836原先按相位0将A/D用于红蓝。用户白纸、红色、蓝色实物的原始统计如下，均为518,400个采样、`raw_stat_valid=1`。这些是原始RAW位置的总和，未经过相位映射、白平衡或RGB565量化。

| 场景 | A | B | C | D |
|---|---:|---:|---:|---:|
| 白纸 | 71,678,429 | 48,632,641 | 45,434,359 | 71,626,612 |
| 红色实物 | 31,261,203 | 27,567,227 | 32,360,382 | 31,282,085 |
| 蓝色实物 | 38,512,781 | 34,423,486 | 29,493,615 | 38,519,670 |

白纸A/D均值只相差约0.0723%，符合两绿位置的候选特征。将C/B比值除以白纸的C/B后，红色为1.256504，蓝色为0.917100：红色相对增强C，蓝色相对增强B，支持**相位3（收到的2×2顺序为GBRG）：R=C，G=(A+D)/2，B=B**。这是本硬件原始统计对映射的支持，最终还需新位流显示红蓝实物确认，不能只用传感器标称RGGB或跨平台驱动来定论。

来源、原位流与CWC哈希、六张截图本地路径及证据边界见[原始测量JSON](evidence/white_balance_stats_20261014.json)。用户确认普通室内照明下白纸基本铺满且未过曝；本轮没有直方图，无法由总和证明每个像素均未剪裁。

## 2. 本次固定白平衡如何算

原程序的相机配置ROM写入`30E2=32h、30E3=00h`：

- 原冻结ROM：`D:/TD/work/csi2/prj/camera_rgb565_20261014_140836/camera/uisrc/03_ip/ui_imx415_cfg/ui_imx415_reg.v:115–116`。
- Sony原文：`D:/TD/08_MLK-CAM005-IMX415/02_hardware/IMX415-AAQR-G_E_Datasheet_E19505D2X.pdf`，物理PDF第42页BLKLEVEL寄存器、第68页RAW10推荐032h=50DN。

50是**标称配置黑电平**，尚未做暗场测量或I²C寄存器读回。计算时以50为基准，而不是把包含黑电平的白纸总和直接相除：

```text
N = 518400
Gwhite = (Awhite + Dwhite) / (2*N) = 138.21859664
Rwhite = Cwhite/N = 87.64343943
Bwhite = Bwhite/N = 93.81296489

Rgain = (Gwhite-50)/(Rwhite-50) = 2.34353178 → Q10 2400
Bgain = (Gwhite-50)/(Bwhite-50) = 2.01352720 → Q10 2062
Ggain = 1
```

RTL对红蓝分别执行：

```text
delta = raw - 50
scaled_magnitude = floor((abs(delta)*gain_Q10 + 512)/1024)
balanced = clip(50 + sign(delta)*scaled_magnitude, 0, 1023)
```

保持输出黑电平基准；负方向也按幅值四舍五入，半值远离零，再做两端饱和。绿通道维持原有两绿求和量化。最后截取RGB565各分量，原始A/B/C/D统计保持未缩放，方便后续比较。默认增益1024、黑电平0保持原行为。

这是本次照明下的固定增益，**不等于自动白平衡、完整黑电平校正、Gamma或颜色矩阵**。换照明、过曝或暗场仍可能偏色，低亮度量化和暗部层次也未校准。先验收相位及白色/红蓝，再决定是否增加下一项处理。

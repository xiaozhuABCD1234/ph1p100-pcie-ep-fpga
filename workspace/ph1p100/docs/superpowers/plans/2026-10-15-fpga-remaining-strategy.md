## 1. 执行原则与现有起点

- 双路 1920×1080、每路 30fps 是首个完整研发目标，非赛事所有场景指标已满足的结论；4K 提升不挤占提交前闭环。
- 相机当前仍为单 A 的 4K30 RAW10 接收，960×540 RGB565 调试预览经 DDR 显示；B 路未完成验收，不能由顶层有两个实例推定双路可用。

- 不重做已经会的安装、点灯和基础例程；不重写已有 CSI CRC/头错/超时计数。优先补真实读取、几何约束与未闭环的数据面。
- 相机不能反压；溢出必须拒绝整帧并计数。有效帧只有通过原始帧结束裁决后才可发布。
- 保留现有回退候选，新增独立工程验证；禁止批量删除文件或目录，不覆盖其他任务正在修改的文件。
- 11-04 提交，10-31 目标冻结，11-01～03 材料与视频。日期作为检查点，未过门槛必须重排。

**当前最重要的策略：把“真实数据可用、压缩可逆、RK 能收”放在颜色精修之前。** HDMI 保留为调试出口；颜色和闪点仍需记录，但不阻塞独立压缩、三算法与固定数据 DMA 的准备。

## 3. 数据面先统一：避免各模块做完却接不上

建议正式帧沿用 RAW10，先在当前已知相机模式上明确 1920×1080 ROI 的形成方式；选定起点后记录其 Bayer 相位、方向和视场。不能把预览插值为 1080p 冒充正式像素，也不贸然切换可能改变线上格式的 sensor binning。

建议两层接口：

1. **入口/缓存层：** RAW10 packed 字节和完整帧描述符，适合与 CSI/DDR/PCIe 字节计数对应。
2. **处理层：** 明确有效像素数的 10bit 样本流，供预测/三算法；使用 ready/valid 时，停顿必须保持 data 与全部 sideband，不丢掉行列/Bayer位置。

CSI 原有四像素输出不意味着压缩器必须从第一版就四像素并行。可以先整帧入 DDR，在可反压的处理域按确定速度消费；是否能持续跟上，由输入吞吐和总 DDR 负载决定。不要直接在不可暂停的相机流上接可变长度编码器而没有最坏情况缓冲。

最小帧元数据统一包含：`version / session_id / camera_id / capture_seq / format / width / height / stride / ROI起点 / Bayer相位 / 原长 / 载荷长 / codec版本 / 时间戳及频率 / 错误标志 / CRC`。首版必须冻结精确字节布局、大小端、长度/CRC范围；本策略不冒充已经完成二进制协议评审。

## 4. Bayer 预测＋熵编码：先做小而可验收的首版

### 4.1 技术路线

```text
RAW10 packed → 10bit样本 → 块内同色预测 → 有符号残差
            → 可逆整数映射 → 有长度上限的 Golomb-Rice
            → 位流打包 / 块头 / 原始块回退 → 压缩帧
```

RK 顺序反向执行，恢复原来的 10bit 样本，再按约定重新打包。首版必须无损，不截位、不量化、不把 RGB565 输入当 RAW10 的无损压缩。

**建议第一版只做水平同色预测：** Bayer 同一行相隔 2 个像素通常同色，使用 `x(row,col-2)` 预测当前样本；块内没有可用前值时发送完整锚点。行/块边界重置规则由格式明确，不跨相机、不跨坏帧、不偷偷引用上一帧。

这比起步就做 YCCC 颜色变换、二维自适应预测、16像素并行更容易说明创新原理和验证。后续仅在实测收益不足且时间允许时加入同色上一行/二维预测；新增模式必须使用新的 codec/mode 标识，不能让 RK 猜。

10bit 样本在 0～1023，残差范围为 −1023～1023，至少需要 11bit 有符号表示；可逆映射建议 `u=2e`（e≥0），`u=-2e-1`（e<0），最大值 2046。后续 RTL 必须明确运算扩位和 signed 语义，不能让 10bit 减法先回绕再扩位。

### 4.2 块与 Rice 参数的首版取舍

- 以**一条有效图像行为独立块**作为首选候选：1920 像素原始 packed 数据为 2400B，便于 predictor 重置、坏块定位和 RAW 回退。若改为更小分段，也必须固定起点、相位和锚点规则。
- 软件先支持逐块显式指定 `k`；第一版硬件可以使用固定/配置的 `k`，由真实图集选取。只有收益不足时才加逐块硬件选 k；不要一开始叠加多种自适应预测与参数估计。
- 普通 Rice 的 unary 部分可能很长，**必须定义码长上限和 escape 格式**；具体上限、标记和逃逸负载位宽在 F2 冻结，先由软件向量证明无二义性，再写 RTL。
- 块压缩不划算时发送 RAW10 packed 原始块，块头显式标记。回退需要保留原块输入或能安全重读，不能写完一半压缩数据就覆盖正在发送的缓冲。
- 位流打包按一次输入的最坏输出位数设计，不能只按“平均可以压小”定 FIFO 深度；末尾 valid_bits/填充规则必须使解码器精确停止。
- 块回退后整帧可能比原始数据略大，因此“有硬件压缩器”和“真实图集有足够节省”分别验收。

### 4.3 压缩验收与创新证据

- [ ] F2：纯软件往返对照，覆盖全0/全1023、交替极值、渐变、随机、四相位、首尾像素、奇数小尺寸/非法尺寸拒绝、截断流、错误k/长度和复位边界。
- [ ] F2：冻结真实图集，包括纹理、平坦、暗场噪声、标定板与亮暗突变；合成图只证明功能，不能当实拍压缩比。
- [ ] F5：RTL 输出由独立软件解码，恢复样本逐个相等；比较有效位流/填充规则，禁止仅比最终图像“看着一样”。
- [ ] F5：测试连续块、回退交替、输出反压、最坏残差、块边界/停启和最后不足输出字的尾部；错误输入拒收、无越界写。
- [ ] F5/F7：记录输入 Mpix/s、packed 等价 MB/s、输出 MB/s、周期分布、最差服务时间、FIFO高水位、资源和最终STA。
- [ ] 创新对照：同图集比较 RAW、简单字节压缩软件基线、当前预测＋Rice；补一个不使用同色预测的对照，说明结构的实际收益。软件基线不作为 FPGA 性能证据。

软件/算法参考可以借鉴[作者论文](https://pmc.ncbi.nlm.nih.gov/articles/PMC11510722/)和[OMLS参考实现](https://github.com/joej970/OMLS)，但不要假定其40Gbit/s可在本板复现，也不要假定公开软件仓库包含完整可移植RTL。借鉴与本项目新增部分分别记录。

## 5. 其余 FPGA 工作包怎样推进

### F1：可靠 RAW 数据——复用接收层，补板上几何和导出

- [ ] 读取并保存实际 DT/VC/WC、原始行数/帧结束、CRC/头错/超时/好坏帧、实际fps；使用已有完整性模块。
- [ ] 依据实流核对记录区、OB/EBD、裁剪坐标；再冻结严格几何检查，不凭默认值猜传感器包结构。
- [ ] 打通正式 RAW10 packed 帧到 DDR；检查尾拍、行边界、地址高位及完整尺寸。
- [ ] 导出至少一张真实完整 RAW 帧和元数据，用独立解包/可视化检查相位、方向、尺寸、黑白电平。调试导出可以慢，正式实时传输仍走 PCIe。

**验收：** 完整帧字节数与几何一致，错误计数和输入版本可追溯；注错/缺行/超时帧不得发布。预览显示正常不替代该验收。

### F3：PCIe——先搬数据，再搬图像

- [ ] 确认实际 RK 枚举、链路速率/宽度、BAR、总线主控与驱动环境；不重新从“点亮link”算完成。
- [ ] 先用固定计数/随机源做 C2H Memory Write，轮询完成即可，暂不做复杂环形队列或 MSI。
- [ ] 驱动提供合法 DMA 地址/容量；FPGA 检查范围与地址宽度，按 MPS、4KiB 边界、尾字节和 credits/ready 约束分包。
- [ ] 验证超时、复位/掉线、重复提交、忙时改配置、实际长度；完成前禁止复用缓冲。

**验收：** RK 数据逐字节/CRC一致、长短块和边界正确，测到持续有效吞吐；固定块正确后再接 DDR 合成帧、压缩帧、最后真实相机。

### F4：三算法——固定定义，避免重复建设 ISP

- [ ] 保留灰度、高斯、前帧 HE 三分支并行计算；选路在帧边界锁定，结果带 mode_id。
- [ ] 正式算法输入使用明确几何和相位的像素，不能默认复用低分辨率 RGB565 预览并把结果标为全分辨率。
- [ ] 灰度首版选固定、可复现的 Bayer→亮度路线；若复用已有定义则沿用双线性→RGB→Y8，缩放/边界规则先冻结，不新增 AWB/CCM。
- [ ] 高斯沿用3×3 `[1 2 1;2 4 2;1 2 1]`、`(sum+8)>>4`和复制边界，保持约定尺寸。
- [ ] HE沿用有效前帧CDF-min、第一帧恒等LUT、坏帧不发布LUT；多像素同bin与连续同值不能丢统计，旧LUT到新LUT只在合法边界切换。

**验收：** 小图/完整尺寸逐像素对照，边界/停顿/坏帧/模式切换正确，实际吞吐成立。三路硬件同时计算不等于必须存三份整帧；先选一路验证输出，正式 RAW 主链保持独立。

**与 Bayer 压缩的关系：** Bayer predictor只处理RAW样本。Gray8/高斯/HE结果不是Bayer，不能直接套用同色间隔2的语义。首版三算法可单独输出或用显式RAW模式传输作验证；若需要压缩处理结果，再定义Gray8预测模式及码流版本，不能冒充已经完成该模式。

### F6：DDR——从显示缓存扩展为正式生产队列

- [ ] 保留原生 PAXI 地址单位/握手，不套用标准 AXI 假设；先测现有单笔命令/单未完成读的实际带宽。
- [ ] 将预览“新帧替换旧READY”策略与传输队列分开；正式队列至少区分写入、已验证、编码中、发送中、完成可释放。
- [ ] 编码/发送持有的槽不能被覆盖；满队列丢整帧并记录原因/采集序号缺口，左右配对可识别缺帧。
- [ ] 对相机入口提供可计算的最大等待上界，测FIFO高水位；持续吞吐不足不能用加深FIFO长期掩盖。
- [ ] ready丢失/复位后的未完成响应按控制器合同清理，不让旧响应进入新会话。

**验收：** 合成数据压力、随机停顿、坏帧/重启/满队列、CRC和所有权正确；必要时才优化预取/批量命令/仲裁，不先推倒已有帧缓存。

### F8：双路和同步——提前准备，分步启用

- [ ] 现在就核对共享XHS/XVS、方向和模组真实连接；准备安全的A主/B从寄存器差异，避免共享输出争用。
- [ ] 先分别确认B路接收与完整性，再启用双路；为每路保留独立计数和源域，不因PLL锁定就默认时钟同相。
- [ ] 同步后建立采集会话及序号对应关系；共同时间基记录SOF差值，曝光同步证据单列，不能靠frame_id相等替代。
- [ ] 丢FS、任一路复位或配对失锁后撤销对应关系，重新建立锁定；坏帧不得进入匹配。
- [ ] 固定左右ROI/方向/采样/曝光参数，交付真实对应帧给队友标定；变更几何后更新标定/校正版本。

**验收：** 双路正确帧、可解释的对应关系、同步测量对象/误差、失锁恢复；深度计算可按既有许可降低负载，但不能用异步静态样例替代动态同步验收。

## 6. 吞吐和资源策略：先过单路，再扩双路

按每路1920×1080、30fps：

| 指标 | 单路 | 双路 | 双路＋25%预算 |
|---|---:|---:|---:|
| 样本处理率 | 62.208 Mpix/s | 124.416 Mpix/s | 155.520 Mpix/s |
| packed RAW10 | 77.760 MB/s | 155.520 MB/s | 194.400 MB/s |
| uint16内部/传输容器（若采用） | 124.416 MB/s | 248.832 MB/s | 311.040 MB/s |

这些是需求计算，不是实测值；帧/块头和 PCIe 报文另计。压缩器输入必须处理原始样本率，不能用输出码流变小抵扣输入计算能力。解码后无损恢复的是RAW10，不应把16bit容器高6位也算成原始图像信息来夸大节省。

策略上先评估单路1pixel/拍、约100MHz的最小流水实现；这只是设计候选，达到1pixel/拍且停顿受控才有意义。双路可比较两个独立单路核与一个2pixel/拍核。优先选已经有周期/资源/STA依据的方案，不为了“并行度好看”直接挑战16pixel/拍。

如果采用原帧/压缩帧双暂存，DDR负载约 `2R+2S`。在RAW回退导致S≈R时，双路1080p30约622.08MB/s，25%后约777.60MB/s，预览和访问低效另加。块头使回退略大，实际按冻结格式重算。

资源按实际模块报告累加：接收/调试/DDR已有占用，再加算法行缓存、预测状态、原始块/输出暂存、PCIe FIFO。现有预览工程余量不能直接证明双路整机可布通；每增加一个模块先做独立综合估算，再在统一候选做最终PnR。

**停止扩张的触发条件：**

1. 软件往返不正确或码流有二义性：停止RTL扩展，先修F2；不靠新自适应算法绕开格式错误。
2. 真实图集收益不足：公开记录结果，比较固定k/块大小/简单预测的有限变体；不要降低RAW位宽后称无损。
3. 压缩持续吞吐不足：先测瓶颈在预测、码字生成、打包还是DDR/输出，选择单一措施；加FIFO不能解决长期速率倒挂。
4. 最紧路径位于厂商DDR内部：按实际报告处理，不持续给无关颜色逻辑加流水，也不放松约束制造通过；与独立模块开发并行。
5. HDMI/颜色连续两轮无判别性进展：保留问题与回退，改用可验证帧数据推动主链；相关时序、电气风险仍需在使用该出口时说明。

# IMX415 首版模式与寄存器差异（第三批第一小步）

> 2026-10-09。范围：Sony 本地原文、现有相机配置源码及其启动控制。仅资料/代码核验，未生成新 ROM，未综合/PnR、下载或实测。模式是候选，尚未冻结为当前硬件可用配置。

## 1. 推荐从哪一档开始

建议首次单路完整接收采用 **A：1920×1080、H/V 2/2-line binning、RAW12、4 lane、594 Mbps/lane、27 MHz INCK、20 fps**。它直接对应 Sony 典型模式表，并使候选 1:8 接收并行时钟降至 74.25 MHz。后续用 **C：同一 INCK、891 Mbps/lane、30 fps** 对接已确认的双路1080p30开发里程碑。

这两个模式的传感器依据成立，不代表 PH1P100 的 PAD 电气、专用时钟路线和接收正确性已经通过。27 MHz 的 FPGA 输出生成、引脚及模组实际 INCK 也尚未验证。

|---|---|---|---|

来源 S1 第49页是模式的**最大**帧率/最短行周期，第59—60页是上述**典型**20/25/30 fps寄存器表，第53页是帧率公式。不能把 INCK=27 MHz 当作 HMAX 的27 MHz计数时基；这里按第49页脚注的74.25 MHz计算。Sony表格将行周期四舍五入写作22.3/17.8/14.9 μs，本文保留复算精度。

594 Mbps并非只能20 fps：根据第49页最短行周期786个时钟和第53页公式，HMAX=1100、VMAX=2250可以推导出594 Mbps下30 fps的候选。**这是公式推导，未列入本次直接采用的典型模式，也未实测**。首版先用表列20 fps减少变更项；后续比较这一低速30 fps候选与表列891 Mbps/30 fps，不把提速当作必经步骤。

## 3. 旧配置的具体差异

R1是PH1A平台的现有参考，带本地修改，不能叫当前板实测；R2也不是厂商未改动原件。

| 问题 | 旧源码定位 | 本次判断与处理 |
|---|---|---|
| binning却选择RAW10 | R1:56—58为HADD/VADD/ADDMODE=1，69为MDBIT=0；R2:59—61、72同类设置 | S1:p59、61明确binning输出RAW12。候选改MDBIT=1，并配RAW12解包；不能只改ROM而沿用RAW10解包 |
| 旧行/帧周期并非30 fps | R1:60—64，VMAX=0x08EB=2283，HMAX=0x021E=542 | 在合法891档74.25 MHz时基下为60.0055 fps。首版按表列A或C的成套HMAX/VMAX；该计算不证明旧硬件真的输出60 fps |
| 参考时钟意图与ROM不一致 | R1:50—53、70、114—120、225—227、246为891 Mbps/27 MHz设置；R3:284—320连接S_clk_24m；R4:35请求24 MHz | 文件配置不一致。R4是IP配置意图，不能代替真实生成频率与PAD测量；新工程需成套生成并核验INCK与ROM |
| 两只都为主机且都驱动共享线 | R1:49、105—106；R2:52、108—109 | 首次仅A工作、B保持系统清除或已经验证的安全禁输出状态；双路候选A master/30C1=00，B slave/30C1=0F，在退出待机前设置。不能复制两份主机表 |
| 启动等待位置不符合要求 | R5:206—211连续列3000=00、3002=00，123—170没有两笔间专用等待状态 | p89要求退出待机后≥24 ms再XMSTA=0。89—98的1000000周期计数从O_cfg_done开始，不是从3000写成功完成开始；不作为24 ms证据 |
| 配置完成早于图像稳定 | R5:135—139就置完成标志 | 应区分“表写完”“待机退出”“主机开始”“第9帧以后有效”；不能用O_cfg_done宣称图像可用 |
| 没有读回与上层错误否决 | R5:188—194读长=0、读数据未接；总线错误只接内部wire；166—168按busy结束递增 | 必须增加ACK/超时/错误地址记录与关键配置读回，错误不可记成成功。底层有读能力不等于当前包装已读回 |
| 保留位不能按字段表清零 | R1:53写300B=A0 | 该值符合p34固定保留位；CPWAIT字段高位为0不意味着整个300B=00。这一项应保留 |
| 若干旧写入缺本版寄存器图出处 | R1:55/59/65—66/82—104/109/121—122/223等 | 301D、3023、302C/D、HDR附加SHR/RHS/GAIN、30CF、3260、32C8、4000等不能只凭注释继承。p32限制未列地址通信，需厂家/适用修订原文；生成ROM前建立地址白名单，不擅自将未知写入照搬或反向断言其必然有害 |

R2另有MODE=1的4K设置，SYS_MODE=08对应1440/1485 Mbps族（S1:p37），超过此前查得的HR LVDS1250 Mbps表列上限；**该分支不作为当前PH1P100的4K候选**。4K以后按当前器件可承受的合法传感器档重新预算。MODE=2只是binning后FPGA裁剪的注释，不是独立720p传感器模式（R2:36、45）。

## 4. 有效图像区与接收要求

S1:p50—52给FS/FE、嵌入数据、OB与图像DT；p61图明确binning输出RAW12。图中横向依次为6列余量、1920列记录区、6列余量和12列dummy，横向示意编号延伸至1944。垂直还含EBD、OB、忽略区、处理余量和dummy。

- 1920×1080是记录区，不能把每个长包都当成图像行，也不能一见FS就数1080个负载包。
- RAW12的记录区数据量为1920×12/8=2880 B/行、3,110,400 B/帧；不含额外区、包头/footer。20/30 fps单路分别62.208/93.312 MB/s，双路30 fps为186.624 MB/s（十进制）。
- 若某图像长包包含示意中的1944个样本，WC计算为2916 B；这是按图推导的检查候选，**必须以实际包头WC及行分类确认**，不能硬编码为已测行长。
- 首版保存DT/VC/WC、包计数、短包帧号、CRC/错误状态；RAW12解包后再做记录区裁剪。正常方向的横向记录区对应图中7..1926；垂直位置需结合实际包序列对应p61，不把图中XHS编号直接当成软件包索引。
- 翻转会改变Bayer相位；p61还提示binning正/反方向同色像素有位置偏移。首次固定3030=00，标定后不得无记录地更改裁剪/方向/模式。

## 5. 启动条件：只定约束，本轮不执行

1. CAM005模组内部电源由模组管理，不能把Sony裸芯片电源顺序写成FPGA现有可直接控制的三路电源。先确认SENSOR_RSTN/CLK与XCLR/INCK内部关系。
2. S1:p85：所有电源稳定后XCLR低≥500 ns；清除释放后INCK上升至少1 μs，通信开始至少20 μs。p65角色措辞与p88/89流程的歧义保留，不设计“XCLR低期间写寄存器”。
3. 待机状态配置模式、固定设置、主从角色和驱动；初验只运行A。SHR0初始可用默认0x66=102（p71），合法范围8..VMAX-4；两路后续保持一致。固定曝光/增益用于复现，实际亮度再调并记录，首次不依赖AE。
4. 主机：写3000=00成功结束后，以独立连续控制时钟等待≥24 ms，再写3002=00；实现建议25 ms并校核计时频率。25 ms是工程余量，不是原文数值。等待不得依赖尚未启动的MIPI pclk。
5. 开始出帧后排除前8帧，第9帧起才评价图像（p64、89）。再次待机/复位/换模式需重新执行相应稳定步骤。
6. 双路候选先准备B并满足退出待机等待，再启动A共享同步；模组内部连通、共享线实装与波形尚未验证。30C1为S类，不能运行中写Hi-Z就宣称立即禁输出。

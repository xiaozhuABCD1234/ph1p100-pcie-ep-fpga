## 10 分钟速读卡

- **本质一句话**：无损压缩＝把数据里的**冗余**换成更短的写法，并保证解压后**逐样本/逐字节**与原始完全相等——省的是存储与带宽，不是信息。
- **为什么重要**：压缩是双路 RAW10 主链上最大的带宽杠杆之一；它同时是"只能赢不能输"的环节——压不动可以回退，但压出来的码流必须能一字不差地还原，否则整帧数据不可用。
- **本项目怎么用**：现行压缩主线＝**LZ77 基线＋Bayer 自有优化**（同色预测/相位重排前端可开关，块级 RAW 回退）；BPR1（预测＋有界 Rice）转**可选第二模式**，两者都要求无损可恢复与最坏情况预算（`../../workflow/tasks.json` T10；decision-register M5.4）。
- **一个记忆锚**：无损压缩像**重新装箱**——东西一件不能少、不能坏，只是箱子塞得更紧；"塞得紧"（压缩率）与"装得快"（吞吐）是两件事。

## 直觉：冗余是"可以抄的重复"

先看三个"很好压"的例子：

```text
全零行（暗场/遮盖）：0000000000000000...
平坦区（白墙/桌面）：500 501 500 499 500 501 ...
周期图案（标定板）  ：0 1023 0 1023 0 1023 ...
```

它们有共同特点：**下一个值在很大程度上能被前面的值"猜到"**。这种"猜得中"的部分就是**冗余（redundancy）**——它不携带新信息，却占了字节。【通用原理】压缩的全部可能性都来自冗余：只要数据不是完全随机的，就存在比原始写法更短的等价写法。

注意反面：**随机噪声几乎不可压**（甚至可能压大）。暗场噪声、高感光度下的颗粒，是压缩最不友好的素材——这也是本项目反复强调"合成图不能代表实拍压缩比"的原因（见下文）。

## 原理：从熵到"无损"的判据

### 熵的直觉

【通用原理】**信息熵（entropy）** 度量"一条消息平均携带多少信息量（不确定性）"。直觉版：越**常见**的取值，出现时越"意料之中"，携带的新信息越少，可以用越短的码字表示；越**罕见**的取值相反。数据取值分布越集中（比如残差总是集中在 0 附近），平均码长就能越短——熵编码就是在逼近这个下界。

- 全零序列的熵≈0：几乎不需要任何比特就能描述。
- 均匀随机 10bit 样本的熵=10bit：什么也压不掉。

### 无损的判据（写作、测试、合同都要用同一句）

把编码记作 `C = encode(X)`，解码记作 `X' = decode(C)`。**无损 ⇔ X' 与 X 完全相等**——对像素系统，通常要求**逐样本相等**（10bit 样本序列完全相同）；对字节管线，要求**逐字节相等**。

【本项目事实】项目对压缩 RTL 的验收句是"**RTL 输出由独立软件解码，恢复样本逐个相等**；比较有效位流/填充规则，**禁止仅比最终图像"看着一样"**"（`../superpowers/plans/2026-10-15-fpga-remaining-strategy.md` §4.3）。这条要求把"差不多""看着一样"等模糊判据全部排除在外。

### 范式：预测＋残差＋熵编码

【通用原理】大多数图像无损压缩器共享同一套骨架，本项目现行方案（两种模式）也在这套骨架里：

```text
原始样本 → 预测（用邻居猜当前）→ 残差（猜错了多少）→ 可逆映射（变成非负数）
        → 熵编码（常见值给短码）→ 位流打包 → 压缩帧
解码：按相反顺序执行，最后恢复原始样本
```

四步各自的意义：

1. **预测（prediction）**：用已经见过的邻居值 `p` 猜当前值 `c`。图像相邻像素高度相关，猜中率高。
2. **残差（residual）**：`e = c − p`。猜得准 → `e` 大量集中在 0 附近（分布变窄）。
3. **可逆映射（reversible mapping）**：熵编码处理"无符号小整数"最方便，把有符号残差映射成非负整数（具体映射见第 17 章）。
4. **熵编码（entropy coding）**：对映射后的整数分配变长码字，常见的小值用短码（本项目选 Golomb-Rice，见第 18 章；LZ77 路线用另一类"重复引用"逻辑，见第 19 章）。

### 回退：压不动时的"出路"必须事先定义

压缩不是"必须赢"的赌局，但**必须定义输了怎么办**。【本项目事实】策略文档要求：块压缩不划算时**发送 RAW10 packed 原始块，块头显式标记**；回退需要保留原块输入或能安全重读，"不能写完一半压缩数据就覆盖正在发送的缓冲"（策略 §4.2）。因此，"整帧可能比原始数据略大"是允许的——只要解码器按标记能正确区分压缩块与原始块。

## 数字：压缩率的四种口径与一个可手算的例子

"压缩率"不是单一数字，它必须绑定**口径**（分母配哪一段）。把本项目会遇到的四种口径排开（另见第 4 章"长度账本"）：

| 口径 | 数的哪一段 | 本项目类型示例 |
|---|---|---|
| 原长 | 原始有效载荷本身 | `2,592,000B`（1920×1080 packed RAW10） |
| 内层载荷长 | 压缩封包内部数据（不含自身内头） | BPR1 的 `P`（36B 内头之外的行块数据） |
| 含头完整封包长 | 内层头＋载荷 | BPR1 完整长度＝`36+P` |
| 外层/传输长 | 经 R10F 封装与对齐后的长度 | `align32(36+P)`，直至 DMA 长口径 |

**手算例子**（数据来自【本项目事实】的一次封装演示，`../DeepSeek独立检测与现行方案整合_2026-10-16.md` §3.1）：1920×1 全零行（原始 2400B）编码后，BPR1 完整封包＝774B（36B 内头＋738B 行块），按 32B 对齐后＝800B：

```text
含内头比率   = 2400 ÷ 774      ≈ 3.10 : 1
含头节省率   = 1 − 774/2400    ≈ 67.8%
按外层对齐算 = 2400 ÷ 800      = 3.00 : 1     ← 口径一换，"比率"就变了
```

**读这个例子的正确姿势**：① 774B 是**全零行**——最"好压"的极端演示，不是实拍数据；② 同一批数据换口径（含内头/含外层对齐）数字就变，所以"压缩率 3:1"必须配套说明是哪一段；③ 【通用原理】合成图只证明"功能路径正确"，**不能当作实拍压缩比**——本项目要求冻结真实图集（纹理、平坦、暗场噪声、标定板、亮暗突变）后再评估收益（策略 §4.3）。

## 硬件实现视角：变长输出接在哪里

【本项目事实】策略文档给"压缩接在相机流上"画了一条红线：**不要直接在不可暂停的相机流上接可变长度编码器而没有最坏情况缓冲**（策略 §3）。原因：相机不给 FPGA 反压，而压缩器输出长度是变长的——输入 2400B 的行可能变 700B，也可能变 2500B（回退＋头），下游停顿与最坏长度叠加时，没有缓冲就会丢数据。

三条硬件纪律（后续章节会反复用到）：

- **入口缓冲**：先整帧进 DDR，在"可反压的处理域"按确定速度消费（策略 §3）。
- **按最坏输出设计**：位流打包的输出 FIFO 深度按**一次输入的最坏输出位数**设计，"不能只按平均可以压小定 FIFO 深度"（策略 §4.2）。
- **输入服务率不因输出变小而变**：压缩器必须按原始样本率处理输入（双路 155.520 MB/s 预算口径），"不能用输出码流变小抵扣输入计算能力"（策略 §6）。

## 决策点与判决框架

**决策点：压缩验收拿哪个数字说话？**

| 选项 | 内容 | 代价/收益 |
|---|---|---|
| A. 只看平均压缩率 | 单一口径、单一场图 | 最省事；最坏膨胀、回退率、头开销全部不可见——改判依据不足 |
| B. 多口径＋最坏＋回退率（当前口径） | 平均/最差节省率、含头口径、RAW 回退率、输入吞吐分列 | 验收项多、要冻结图集；但这是"可验收"的最小集合 |
| C. 直接把压缩率绑吞吐结论 | 用比率推断整链性能 | 把"比率"与"服务率"混为一谈——两边都不成立（见误区 1） |

- **权衡维度**：可复现（图集/口径冻结）；风险可见（最坏与回退）；与下游接口（含头长度进入 R10F）。
- **当前选择**：B。【本项目事实】策略把"**有硬件压缩器**"与"**真实图集有足够节省**"列为**分别验收**的两件事（策略 §4.2），最终交付清单要求"含头平均/最差节省、回退率、输入吞吐"（策略 §9）。
- **何时应重开**：① 组织方对替代路线口径澄清（转第 20 章判决框架）；② 实拍图集收益不足（转 O04 候选评估）；③ 吞吐实测不达（转单核/多核评估，见第 20 章）。

## 常见误区

- **"压缩率＝省带宽"**：压缩器仍要**按原始样本率**处理输入；比率描述的是"输出/存储变小"，不是"输入端口可以变窄"。**正确做法**：吞吐看输入服务率与最坏服务时间，比率看输出口径（策略 §6）。
- **"合成图压得动，实拍一定行"**：合成图（ramp/checker/全零）只验证功能与边界；暗场噪声、纹理图的压缩收益必须用**冻结实拍图集**评估（策略 §4.3）。
- **"压不动就丢一点"**：无损约束不接受量化/截位；压不动走 **RAW 回退**，原块原样发出。**正确做法**：回退＋块头标记＋最坏膨胀预算三者齐备（策略 §4.1/§4.2）。
- **"解码出来图像看着一样＝无损"**：必须逐样本比较；边界、填充位、位流末尾处理都可能是错的。**正确做法**：独立软件解码器＋逐样本对照＋填充规则比对（策略 §4.3）。
- **"自己改个 token 也敢叫 zlib 兼容"**：互通性由**固定的位流语法**决定，不是由"思想相似"决定（详见第 19 章）；自定义 token 只能配自研解码器。

## 自测题

<details><summary>1. 无损压缩的验收判据是什么？为什么"看着一样"不够？</summary>

判据＝解码后与原始**逐样本/逐字节相等**（本项目要求独立软件解码器逐样本对照，并比较有效位流/填充规则）。"看着一样"会放过位流末尾、填充位、边界样本这类不影响观感但违反可逆性的错误；一旦进入正式管线，这类错误会累积成不可复现的数据问题。（策略 §4.3）
</details>

<details><summary>2. 1920×1 全零行（原始 2400B）编码为 BPR1 封包 774B（含 36B 内头）、对齐后 800B。含头比率与含头节省率各是多少？</summary>

含内头比率＝2400÷774≈3.10:1；含头节省率＝1−774/2400≈67.8%；若按外层对齐 800B 口径＝2400÷800＝3.00:1。注意这是全零极端演示，不是实拍数字（整合 §3.1）。
</details>

<details><summary>3. 为什么残差通常比原始像素"好压"？</summary>

图像相邻像素强相关，预测器猜中率高，残差 `e=c−p` 大量集中在 0 附近——分布越集中，熵越低，熵编码平均码长越短。反之噪声残差分布平坦，几乎压不动。
</details>

<details><summary>4. 压缩率有哪四种常见口径？为什么它们不能混用？</summary>

原长（有效载荷）、内层载荷长（P）、含头完整封包长（36+P）、外层/传输长（对齐后直至 DMA 长）。四段分母不同，同一数据会得到不同"比率"；混用会把头开销与对齐开销藏进分母，导致数字不可比、验收争议（第 4 章/整合 §3.1）。
</details>

<details><summary>5. 为什么"压缩器输出变小"不能抵扣"输入计算能力"？</summary>

压缩器必须先按原始样本率（双路 155.520 MB/s 预算口径）完整读入并预测每个样本；输出码流变小只是下游传输/存储变轻。输入侧服务率不足（如 1 样本/拍的周期预算不够），输出再小也不能补齐（策略 §6）。
</details>

<details><summary>6. 块级 RAW 回退为什么必须"块头显式标记"？</summary>

解码器需要知道每个块按哪种规则解释：压缩块按 Rice/位流语法解，原始块按 packed RAW10 直读。没有标记就只能猜，歧义流不可用于正式管线；回退还应保留原块输入或安全重读（策略 §4.2）。
</details>

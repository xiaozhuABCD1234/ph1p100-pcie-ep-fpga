# 27 如何做出自己的判决（收束章）

> 本章定位：全书收束章。前面 26 章各留下一张“决策卡”；本章把它们提炼成一套**可复用的判决流程**，并对全书重大决策做示例演算。速查入口见附录 [90_决策索引.md](90_决策索引.md)；术语/资源汇总见 [91_术语表.md](91_术语表.md)、[92_延伸资源总表.md](92_延伸资源总表.md)。

## 10 分钟速读卡

- **本质一句话**：判决不是“猜一个对的答案”，而是把一个问题变成五步可复核动作——**定义问题 → 列选项 → 写证据要求 → 列权衡维度 → 冻结并写明改判触发**。
- **为什么重要**：项目里的取舍（DDR 频点、压缩路线、显示档位、R10F 扩展）都会被新证据影响；没有“改判触发”的结论，过一段时间就无法判断它是否仍然成立。
- **本项目怎么用**：各章“决策点与判决框架”与决策登记（decision-register M1–M5）都按同一四要素结构书写；本章用四个真实决策做示例演算，附录 90 给一表速查。
- **一个记忆锚**：**“先写改判条件，再做决定。”**——写不出改判条件的决策，等于没有冻结。

## 本章要回答的问题

1. 一套可复用的“判决流程”由哪几步组成，每一步要产出什么？
2. 怎样把“证据”映射到结论强度（G0–G5 分层与【本项目事实】标记如何配合使用）？
3. DDR 频点（1600K/1333J/800E）这个决策是如何演算的？现在还需要什么证据才能改判？
4. 压缩路线、显示档位、R10F 扩展分别靠什么证据冻结、又靠什么条件回来重开？
5. 什么情况下“不决策（维持现状）”才是正确的选择？

## 正文

### 一、直觉：判决是“把一次冻结做得可复核”

工程师每天都在做两类动作：**做**（写 RTL、写文档）和**判**（选 A 还是选 B）。做得好不好一眼可见；判得好不好却常常要等几个月才暴露——等暴露时，当初为什么这么选、在什么条件下还能成立，往往已经没人说得清。

把“判”变成一个**可复核对象**的办法很简单：给每次重要决策留一张卡片，上面写清四件事——

1. **选项**：当时在选什么（含“维持现状”这个选项）；
2. **权衡维度**：按什么标准比（不是“我觉得”，而是可列出的维度）；
3. **当前选择及理由**：选了什么、一句话理由；
4. **何时应重开**：出现什么证据/条件时必须回来重看。

前 26 章每章的“决策点与判决框架”都是这张卡片；项目层的版本是决策登记（`workflow/runs/20261017_161109_decisions_compare_freeze/decision-register.md`）。本章要做的是：把“写卡片”的动作反过来读——**从一张卡片出发，得到你自己的判决**。

### 二、原理：判决流程五步

**第一步：定义问题。** 一句话，可验收。反例：“DDR 用哪个好？”正例：“在以 1080p60 预览为观察窗口的整链候选里，DDR 主线频点选 1600K/1333J/800E 的哪一个，判据是同一工具链下的时序余量、手册口径偏离度与接口迁移成本？”——问题定义里就包含了验收对象、比较口径和判据来源。

**第二步：列选项（必须含“维持现状”）。** 选项表漏掉“维持现状”，就会把“不行动”的代价藏起来；选项太少时，先问“还有没有我没写下来的第三条路”（例：第 10 章三候选之外还有“等硬核/换器件”这类低优先级项）。

**第三步：写证据要求。** 先定义“什么算数”，再去收集；否则会被顺手拿到的数据牵着走。证据要求要落到**层级**：是仿真（G1）、构建与 STA（G2），还是板测（G3）、长稳（G4）、集成（G5）——见第 01/26 章。例：“频点对比必须以**同一工具、同一脚本、同口径**的最终 STA 数据为准；不同工具版本的数字不进入对比表。”

**第四步：列权衡维度。** 常见维度：收益、成本、风险、**可逆性**、时机。可逆性是工程决策里最被低估的一项——它决定“选错的代价”：
- 高可逆：改参数/加开关（如固定 k 换逐块 k）；
- 中可逆：局部实现替换（如 PAXI 换 AXI 的迁移面）；
- 低可逆：换器件/换接口族/换整链架构。
**可逆性高的决策可以早冻结、快推进；可逆性低的决策要等证据。**

**第五步：冻结与重开触发。** 冻结=“不再重复讨论、按选定路径推进”，不是“永不再议”。触发条件至少含三类（与决策登记统一）：
1. 实测/板测数据显示假设错误或问题出现；
2. 优化窗口（时间/资源富余）出现且有量化收益；
3. 关键证据到达（同口径数据、接口确认、口径澄清）。
写不出触发条件的决策，冻结时会不自知地变成“赌一把”。

### 三、数字：证据等级与量化演算

**证据等级 → 结论强度**（与 G0–G5、第 26 章同一口径）：

| 手上有什么 | 能支撑的结论 | 不能支撑的结论 |
|---|---|---|
| 设计文档/规范（G0） | “计划怎么做” | 任何“能工作” |
| 仿真/软件（G1） | “逻辑自洽、可复现” | 时序收敛、上板行为 |
| 综合+布局布线+STA（G2） | “该工具/该约束下时序可收敛” | 板上稳定、外设真实行为 |
| 板测短窗（G3） | “这条路径真实数据上跑通过” | 长稳、边界温度/批次 |
| 长稳（G4） | “该时长内稳定” | 超出时长/场景的外推 |
| 端到端集成（G5） | “整机闭环成立” | 未覆盖模式的推广 |

**量化演算的两种工具：**
- **单指标对比**：只在两个候选间比一个可复算的数字（例：STA setup WNS 0.230 vs 0.128ns）。
- **加权决策矩阵**：多维度时给维度配权重再打分求和。用法要小心：**矩阵只是把“说不清”变成“说不清但带着小数”**——权重和打分若无证据来源，结论同样是空的。高风险决策（对外材料、跨线接口、冻结发布）才值得上矩阵，且每个分数要能指到证据。

**示例数字演算（DDR 频点，节选自第 10 章与决策登记 M1）：**
- 同工具（TD 6.2.3）E2 对比：1333 setup **0.230ns** vs 1600ctl **0.128ns**；两者 hold 均 +0.020、period 均满足、0 违例、TNS 0 → 差 **+0.102ns**，1333 不劣且更优。
- 0.300ns 探索线：两候选均如实记为 `accepted=false`（未达 0.300）——**如实评定、非强制门槛**，不阻塞采纳。
- 带宽对照（×32 理论峰值）：1600≈6.4 / 1333≈5.33 / 800E≈3.2 GB/s；双路 1080p30 预算 155.520MB/s（+25%≈194.400MB/s）——**三个候选都富余两个数量级，带宽不构成区分因子**。
- 结论形状：区分因子不是带宽，而是“时序余量（同口径）+ 手册口径偏离 + 接口迁移成本 + 板级证据”。

### 四、硬件视角：为什么 FPGA 决策特别需要“改判触发”

- **证据来得慢、窗口稀缺**：一次 STA 几分钟，一次板测要板卡+操作窗口。触发条件写清楚，才能在窗口打开时**只测最关键的那条假设**。
- **结论易被“输入变化”作废**：工具版本、IP 闭包、约束、器件批次一变，旧数字不再可引用（第 26 章：输入变则结果作废）。所以决策记录必须钉住“结论是在什么输入下成立的”。
- **fail-closed 文化**：本项目检查不过就停（不授权、不出 bit）。决策同样应当 fail-closed——**证据不到层，就维持现状/回退档**，而不是“先干起来再说”。
- **可逆性分级直接决定节奏**：本例中“1600→1333 回退档可用（002820 冻结资产）”“丢弃 002820 换器件=低可逆”。高可逆项可以早冻结（如固定 k）；低可逆项必须等板测。

### 五、本项目实例：四个重大决策的示例演算

每个演算 = 问题定义 → 证据要求 → 权衡与冻结 → 改判条件（详细履历见决策登记与各章）。

#### 演算 1：DDR 频点（1600K/PAXI、1333J/PAXI、800E/AXI）

- **问题**：整链 DDR 主线频点与接口选谁；判据=同工具同脚本时序余量、手册口径、接口迁移成本、板级证据。
- **证据要求**：同工具（6.2.3）同脚本的 E2 对比数据；板测（G3）以 SRAM-only 方式验证；不采用跨工具数字。
- **权衡与冻结**：E2 结果 1333 余量不劣且更优（0.230 vs 0.128），接口零改动 → **M1a 裁定维持 1333**（1600=回退档；上板验证通过，口径=用户目视+短窗）。PCIe 后端轨道维持 **800E/AXI**（M1b）；全局单一定案**延后至组合版窗口**（M1c）。
- **改判条件**：① 板测暴露 DDR 问题（按裁定回退 1600）；② 手册合规成为硬要求，或联调整合需要同一 DDR IP（可能触发 800E）；③ 优化窗口出现且 0.300 改善有量化收益；④ 官方口径澄清/队友 DDR IP 变更/1333 长稳证据到达。【本项目事实】依据：decision-register M1a–M1c、§1.4/§1.5；第 10 章。

#### 演算 2：压缩路线（BPR1 / 纯 LZ77 / LZ77+Bayer 优化）

- **问题**：在“JPEG/LZ77 任一硬件编码为合规基线、替代口径未决”的规则下，压缩主线走哪条。
- **证据要求**：合规可验证性优先；收益必须来自实拍图集；吞吐须以实测服务率说话（不能拿压缩率推）。
- **权衡与冻结**：BPR1=自研叙事强但互通/规则/开发面三重成本；纯 LZ77=最稳但收益受限；**LZ77 基线+Bayer 优化（单编码器）=当前主线**；BPR1 转**可选第二模式**（M5.4）。
- **改判条件**：① 组织方对口径明示异议 → 评估 JPEG/LZ77 硬件替代；② 优化窗口+量化收益；③ 吞吐实测不达（参考 ~128MB/s < 155.520MB/s 预算）→ 多核/降速评估（瓶颈须先实测定位）；④ 实拍收益不足 → 先试有限变体（固定 k/块大小/简单预测），**不得降低 RAW 位宽后称无损**。【本项目事实】依据：decision-register M5.4；第 20 章；策略文档 §8 停止条件 2。

#### 演算 3：显示档位（1080p60 / 降档 / 4Kp30）

- **问题**：显示输出维持 1080p60、降档，还是推进 4Kp30；资格问题（742.5MHz 串行超手册 650MHz、彩点未定位）怎么挂着。
- **证据要求**：资格问题不宣布通过；档位变更=独立新候选，完整走候选交付（G1 回归、G2 门禁、唯一上板入口、G3/G4 板验）；“图案干净”不替代资格确认。
- **权衡与冻结**：维持 **1080p60 工作基线**；**4Kp30=下一里程碑**（用户既定方向）；**降档=触发式备选**（无因果证据不擅自降档）。
- **改判条件**：① 板测（受控实验/诊断）确证彩点与速率/物理层相关，或长稳失稳；② 优化窗口且有量化收益（推进 4Kp30 实现链）；③ 官方澄清到达（不支持→评估降档或 TMDS33；支持→维持并登记）；④ 4Kp30 实现链证据（缩放/PLL/资源）出炉。【本项目事实】依据：decision-register M3 及 §3.4；第 25 章。

#### 演算 4：R10F 扩展（定长填充 / 变长 / 压缩 adapter）

- **问题**：帧长与填充取“定长 4KiB 整数倍＋尾零（2,592,768B）”还是“2,592,128B＋尾突发（不填充）”? 压缩接入后如何扩展。
- **证据要求**：整除假设（TLP 128B 与 AXI 4KB）必须收敛；driver 与 pusher 的硬约束要对齐（`frame_slot_bytes` 同值）；压缩不得只改 `codec_id`。
- **权衡与冻结**：**定长 4KiB 整数倍+尾零**（M2c 固化：2,592,768B=633×4096，尾 640B 零，占比≈0.025%）；M2d=128B 对齐“必须修”（driver 侧，联调前确认）；M2e=CTRL bit4 以新 FPGA 位定义为准（0x61）。
- **改判条件**：① 变长帧（BPR1/压缩）→ 槽头 `len` 语义与 adapter（T10/compress-int 范围）；② 板测出现 pad 相关异常；③ 队友硬约束变更（支持尾块）。【本项目事实】依据：decision-register M2c/M2d/M2e；第 23 章；`parallel/frame/frame_contract.py`。

## 决策点与判决框架

**决策点：判决流程本身用什么档位？**

| 选项 | 内容 | 代价/收益 |
|---|---|---|
| A. 直觉拍板（不写卡片） | 快 | 无法复核、无改判条件；返工与“重复讨论”成本高 |
| B. 决策卡五步（本章默认） | 定义/选项/证据/权衡/触发，每步留痕 | 少量书写成本，换来可复核与可交接——**默认档** |
| C. B＋加权矩阵/传播分析 | 高风险决策加量化工具 | 更重；要求每个分数可指证据，否则是“带小数的空话” |

- **权衡维度**：决策后果（错了返工多少）；复核需求（是否需要第三方/数月后重看）；书写与维护成本。
- **当前选择**：**B 为默认；C 按风险触发**（对外材料、跨线接口、冻结与发布前——与第 26 章“采信策略 B/C”同一分界）。理由：本项目大多数取舍属于“可复核的工程权衡”，五步卡片已足够；矩阵只在多维度且高后果时才划算。
- **何时应重开**：① 同类问题被第二次咬到（说明触发条件写成口号、未生效）→ 升级流程或补检查单；② 出现“未写改判条件导致返工”的实例 → 回顾并补录触发；③ 项目阶段变化（发布/冻结窗口）改变风险定价 → 调整档位。

## 常见误区

- **误区 1：把“冻结”读成“永不再议”。** 错在把流程当承诺；冻结=按选定路径推进＋登记重开触发。正确做法：冻结时同时写下“什么证据到了就回来”（如 DDR 的“手册合规成为硬要求”）。
- **误区 2：选项表里没有“维持现状”。** 错在隐去了“不行动的代价”这一列；正确做法：任何选项对比都先补上“维持现状/回退档”，两个方向都要写代价。
- **误区 3：用加权总分掩盖证据缺失。** 错在无来源的分数会让空话更像结论（garbage in, garbage out）；正确做法：每个分数指到证据，缺证据的维度标注“未测”，宁缺勿编。
- **误区 4：只比收益，不比可逆性。** 错在忽视“选错的代价”；正确做法：把可逆性单列一档（高/中/低），低可逆项强制等证据。
- **误区 5：把“共识/感觉”当触发条件。** 错在无法复核（“大家觉得不行就换”）；正确做法：触发写成可观察事件（板测命题、数据口径、文件到达）。

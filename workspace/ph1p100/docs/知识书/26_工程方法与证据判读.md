# 第 26 章 工程方法与证据判读

> 系统篇收束章：本章是全书最"方法论"的一章——把 G0–G5 各层"证明什么/不证明什么"、manifest/SHA 绑定、负对照与 fail-closed、独立综合测试讲成一套可操作的**判读流程**。G 分层直觉见第 01 章；"长度/CRC/证据语义"见第 04 章；"如何做出自己的判决"见第 27 章。
> 事实标记：【本项目事实】可追溯到项目文件路径；【通用原理】来自公认外部资料；【设计候选】【待验证】【未决】表示尚未实现/未板验/未拍板。

## 10 分钟速读卡

- **本质一句话**：每个"通过"都必须能回答四件事——**哪份输入（哈希）、哪层证据（G）、谁独立复核、什么没证明（边界）**；缺任何一个，"通过"就降级成"说法"。
- **为什么重要**：它防三类事故——**旧结论覆盖新输入**、**不同输入拼凑 PASS**、**未实测写成通过**；比赛材料与队友协作全靠它防止"看起来都过了"。
- **本项目怎么用**：`../../workflow/README.md` §4/§5/§5.1 是硬纪律；每次交付冻结 manifest＋SHA；候选唯一、位流绑定、fail-closed；由一个与开发独立的综合测试者按三维清单核验同一冻结输入。
- **一个记忆锚**：**法庭证据链**——物证（位流哈希）、记录（manifest）、见证（报告）、排除合理怀疑（负对照与边界说明），法官不看口号。

## 本章要回答的问题

1. G0–G5 各层证明什么、**不证明**什么？
2. 一次可信的验证必须绑定哪些元数据（manifest/SHA/唯一候选）？
3. §5.1 必检的 8 条里，哪些最容易被跳过？
4. 什么叫"不拼不同输入 PASS"？证据复用怎么才算合规？
5. 负对照与 fail-closed 为什么是"诚实"的机器化表达？
6. 5 分钟之内，怎么判断一份结论/位流/报告是否可信？

## 直觉：把"通过"当证据看，而不是当口号听

- 一份报告说"测试通过"时，先别信结论字符串，而是像法官一样追问：**证据是物证还是传话**？是谁在该时刻记录的？换了输入还算数吗？
- 工程上"传话"的典型形态：**旧位流的板测结论用到新候选**、**仿真结果写成上板通过**、**A 输入的测试给 B 输入背书**。
- 这套追问的答案不是靠"我保证"，而是靠**可机械复查的元数据**——哈希、清单、层级、边界。

## 原理：六层、绑定、必检、fail-closed

### G0–G5：六层各自回答什么

【本项目事实】来自 `../../workflow/README.md` §4（本项目自定的分层，不沿用芯片签核标准）：

| 层级 | 检查什么 | 通过所需证据 |
|---|---|---|
| G0 任务/接口 | 格式、单位、边界、预算、双方责任 | 可检查验收项；跨 FPGA/RK 接口有双方确认记录 |
| G1 模型/仿真/软件 | 数据内容、边界、恢复与反压 | 对应输入版本、日志、结果标记；关键缺陷有**能拒绝旧行为**的用例 |
| G2 构建/实现 | 综合、最终 STA、约束覆盖、CDC/复位、资源 | 同一最终数据库的报告；未约束路径与豁免说明 |
| G3 上板功能 | 候选实际下载、真实数据和恢复 | 位流 SHA256、连接/电源/运行参数、观察来源及错误计数 |
| G4 长稳/性能 | 持续运行、吞吐、丢帧、热态 | 事先规定的时长/负载/阈值、起止计数、原始结果 |
| G5 集成/发布 | FPGA→RK→算法与可恢复交付 | 接口版本、端到端一致性、性能、材料与回退清单 |

**边界清单（背下来）**：仿真不是板测；综合不是最终时序；选定 CDC 检查不是全芯片 CDC 证明；DDR CRC32 不是 CSI 校验；帧号配对不是曝光同步；HDMI Hz 不是相机 fps；PCIe link 不是 DMA；压缩率不是输入吞吐（`workflow/README.md` §4）。

### 每次验证绑定到什么

- **运行标识**：每次验证建立唯一 `run_id`（如 `20261012_210000_T02_packet_a1b2`），记录 Git commit/dirty、输入清单与 SHA256（含约束/IP/ROM/脚本）、仓库与 D 盘候选路径、工具版本、完整命令与实际工作目录。
- **结果三件套**：预期结果类型＋真实退出码＋通过/失败标记与原始日志——**"退出码 0"本身不足以判断 TD 成功**（§5）。
- **实现物绑定**：最终数据库/报告与位流哈希；**输入变化后，旧构建结果只对旧输入成立**。
- **板测记录**：下载的位流、会话、电源是否连续、连接、真实观察者与计数。
- **诚实分账**：预期失败测试的"**测试有效**"与"**DUT 功能通过**"分开写——旧实现触发预期拒绝可以证明测试有效，不能记成旧 DUT pass；缺日志/哈希不一致时**不提升验证状态**。

### §5.1 必检 8 条（浓缩版）

1. 冻结实际构建输入与参数，保存 manifest＋SHA256；仿真绑定实际候选文件并说明缩小几何的边界。
2. 行为修复要有**能拒绝旧行为的负对照**＋正向回归；复用旧证据须证明相关输入未变。
3. TD 原生命令同时满足退出码、完成标记、非空产物；保留失败/超时记录。
4. 用同一最终实现数据库检查 STA/约束覆盖/CDC/资源；绑定数据库、报告与位流哈希——**HDMI 并行 STA 不能证明串行电气资格**。
5. ChipWatcher 候选须校验完整 CWC 与 BID 的物理 ERAM 覆盖（工具脚本），仅有探针名单不算可交付。
6. **一个与开发独立的综合测试者**，按同一冻结输入出具覆盖相关三维检查的综合判定（三维=functional/engineering/system **检查清单**）；独立性针对开发，无需额外审阅代理。
7. 给用户唯一当前位流/CWC 入口、操作与预期现象、已知问题与回退版本；G3/G4 待测就写待测。
8. 大改后按授权同步私库：只提交本任务文件，不上传图片/凭据/数据库/大中间产物。

### fail-closed 与负对照：诚实的机器化表达

- **fail-closed（检查不过就停）**：接口探针不匹配（RKA1 `EXT_MAGIC` 不符）→不授权、只留诊断（第 22 章）；构建门禁不过→**拒绝生成 bit**（本工程多次以 STA 门禁拒绝为记）；工具链策略中 bitgen 同类纪律（M4）。
- **如实记录"未达标"**：0.300ns 探索 gate 两个候选均 `accepted=false`（0.230/0.128）——按登记口径**如实评定、不阻塞采纳**，"未达"与"造假通过"是两回事（M5.5；rev2）。
- **负对照实例**：帧头篡改能被检测（R10F 向量自检：帧头往返＋篡改被检出）；ROM 方案 TB 通过并带变异体负对照（仅仿真、未上板）；"预期拒绝"与 DUT 行为分开记账（§5.1 第 2 条）。
- **红线**：不靠放宽阈值、删除负对照或把必需层改成"不适用"获得 PASS（`../../workflow/runs/20261017_162355_fpga_knowledge_book/fpga-design-guide.md` §3 的同族纪律；现行有界规则同义）。

### 独立性与"不拼不同输入 PASS"

- **独立性**：综合测试者独立于开发者；同任务 FAIL 时续**原**开发与原综合测试者（不是每轮换人），修复后重新冻结、重新判定。
- **证据复用**：复用旧证据必须证明相关输入未变，并**绑定到当前 manifest**；否则视为不可复用。
- **不拼 PASS**：不同输入的证据不能拼成一次通过；外部并行线的漂移（如 main-log、任务板、决策登记被其他 run 更新）只做**存在性/追加型登记与归因**，不追责、也不用来推翻本包判定（示例见本 run 各 manifest 的滚动语义字段）。

## 硬件实现视角：报告怎么写才算"可判读"

- **首行唯一判定**：本工作流的综合测试报告首行为唯一判定（PASS/FAIL），并携带 task_id、dimension=integrated、三维分项结果、轮次、实际哈希与 manifest 路径（`../../.agents/skills/fpga-orchestrator/references/report-contract.md`；返回元数据约定见同目录 `relay-contract.md`）。
- **判定词汇**：每项验证结果只用 `pass / fail / not_run / blocked / not_applicable`——不适用须给理由，blocked 须写缺失条件。
- **长稳档位**：建议以 10 分钟排查、30 分钟阶段检查、2 小时集成长测逐步加压——**是建议档位，不代表已经通过**（§4）。
- **报告的价值在"边界"而不是"篇幅"**：没写"没证明什么"的报告，读者无法判断可采信范围。

## 5 分钟判读清单（本章的"决策卡"操作版）

拿到任何一份结论/位流/报告，按顺序过：

1. **输入冻结了吗**：manifest 与实际文件哈希一致？run_id/commit 可查？
2. **覆盖哪几层**：G0–G5 中跑了哪几层？没跑的有没有 `not_run/不适用` 与理由？
3. **绑定唯一候选了吗**：位流/数据库/报告哈希成链？回退版本在哪？
4. **有负对照吗**：修复类改动能不能拒绝旧行为？
5. **关键数字能手算吗**：带宽/笔数/占比随手复算一个（如 2,592,768÷128=20,256）。
6. **边界声明在吗**："不证明什么"写清楚了吗（如并行 STA≠串行资格）？
7. **有没有含糊词**："基本/应该/大致/没问题"是不是在掩盖未测？
8. **漂移归因了吗**：环境/并行线的变化有没有被登记归因，而不是混进结论？

这 8 条全部"是"→ 结论可采信到它声明的层级；任一条"否"→ 降级处理或退回补齐。

## 决策点与判决框架

**决策点：面对一份结论，采信策略怎么定？**

| 选项 | 内容 | 代价/收益 |
|---|---|---|
| A. 只看结论字符串 | 省时间 | 无法区分"旧输入/不同输入/未测"——高风险误判来源 |
| B. 看元数据齐全性＋边界声明 | 逐项对照四问 | 成本低、收益大——**默认策略** |
| C. 再加抽样复现（重算哈希/关键数字/跑最小向量） | 复核到物证层 | 成本高；用于高风险决策（对外交付、跨模块接口、发布冻结） |

- **权衡维度**：决策后果（错了要返工多少）、可得时间、证据链完整度。
- **当前选择**：**B 为默认，C 按风险触发**（对外材料/跨线接口/冻结与发布前）。
- **何时应重开**：证据链任一环缺失（哈希不齐/负对照缺/边界不写）→ 不得采信，退回补齐或降级；发现"拼输入"痕迹→ 整份报告作废重测。

## 常见误区

- **"退出码 0＝成功"**：TD 原生命令还要看完成标记与非空产物；日志/哈希不一致时状态不得提升。**正确做法**：三件套＋工件齐才算。
- **"旧位流上次跑通过，这次也能沿用"**：输入一变，旧结果只对旧输入成立。**正确做法**：重新冻结、重新绑定、重新判定。
- **"负对照可以省"**：没有负对照的修复测试无法排除"测试本身失效"。**正确做法**：行为修复必配能拒绝旧行为的用例。
- **"把必需层改成不适用就能过"**：不适用须给理由且不能用于规避难度。**正确做法**：缺条件写 blocked，不扩大"不适用"边界。
- **"报告很详细，所以可信"**：篇幅不等于绑定；先查哈希与边界，再读正文。**正确做法**：5 分钟清单先行。
- **"把预期拒绝当成 DUT 通过"**：测试有效性和 DUT 功能是两笔账。**正确做法**：分开写、分开记账。

## 自测题

<details><summary>1. G0–G5 各用一句话说"证明什么"。</summary>

G0 接口约定可检；G1 数据/边界/恢复在对应输入上成立；G2 同一数据库的构建质量（STA/约束/CDC/资源）达标；G3 位流在真实板卡上功能可用（含下载与观察记录）；G4 持续运行性能/稳定性达标；G5 端到端集成与可恢复交付成立（§4）。
</details>

<details><summary>2. 为什么"输入变化后旧结果失效"？</summary>

结果只对冻结的那份输入成立；约束/源码/IP/参数任何变化都可能改变行为。旧结论沿用（或者拿 A 的证据给 B 背书）是"不拼不同输入 PASS"的红线（§5/§5.1 第 2 条）。
</details>

<details><summary>3. "不拼不同输入 PASS"具体指什么？</summary>

同一次判定必须来自同一冻结输入；证据复用须证明相关输入未变并绑定当前 manifest；不同输入的通过项不能合并成一次"整体 PASS"（§5.1；report-contract）。
</details>

<details><summary>4. 举两个本项目的 fail-closed 实例。</summary>

①RKA1 接口探针不匹配→不授权、fail closed（第 22 章）；②构建门禁不过（如 STA 违例）→拒绝生成 bit（本项目多次以"门禁拒绝"为处置；M4 对工具链另有 bitgen 纪律）。
</details>

<details><summary>5. 0.300ns 探索 gate 的结果应该怎么表述？</summary>

如实记录"两候选均 accepted=false（0.230/0.128，其余条件全过）"；它是探索线口径、非强制门槛，不阻塞采纳——**"未达标如实记录"不等于"失败"，更不等于"可以写成通过"**（M5.5）。
</details>

<details><summary>6. 5 分钟清单里最先查哪三项？为什么？</summary>

参考答案：①输入冻结（哈希与 manifest 一致）——决定整份报告是否还"活着"；③唯一候选绑定与回退——决定拍板后有没有退路；⑥边界声明——决定结论的可采信范围。其余按风险补查（本章清单）。
</details>

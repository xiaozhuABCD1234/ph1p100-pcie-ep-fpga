【三项需求及验收结果】

一、T10 A+ 压缩 RTL 独立闭环。
1. 冻结唯一标准流包装、输入打包方式、块粒度、长度/CRC 域及 Bayer 逆变换约定。路线为 Bayer 相位重排 + 可选同色预测 → 真实 LZ77 → 标准 DEFLATE → 块级 stored 回退；整帧仍为合法标准流。Rice 仅在标准流外层接口预留，不占用 DEFLATE 保留位，不自行分配 T03 生产枚举。
2. 进度优先，一期允许先交 fixed Huffman + stored；dynamic Huffman、复杂搜索和更大字典单独列优化，不作为这一版闭环的额外硬门槛。不得用纯 literal 编码冒充已实现 LZ77 匹配。
3. 建立实际 DUT 输出到独立标准解码器再到逆变换的 round-trip，逐样本 0 mismatch；自研检查不能仅重复调用同一个解析器。覆盖不可压缩、长度/距离边界、尾块/尾 bit、截断、坏长度/CRC，以及反压、复位、溢出和坏帧撤销；不发布半帧。
4. 同候选完成必要 G0/G1/G2、STA/CDC/资源检查和实际服务率验证：单A 1080p30 RAW10 等效有效输入至少 77.76 MB/s，余量目标 97.2 MB/s。双路 155.52 MB/s 仅记录差距，不宣称达成。吞吐预算不能因暂缓 G4 而免测。

二、真实输入参数与 RAW 样例准备。
1. 利用现有相机配置、源计数和必要直接观测，确定有效区、实际 ROI X/Y/SKIP、裁切/方向、RAW10 打包及 Bayer 相位；区分已证实与 unknown。已知的 2192 行、每行 4830B 不能直接推定多余部分的含义。
2. 优先建立最小可重复的非 PCIe 数据导出路径，先取必要片段/若干行，再满足第三项至少一帧完整真实数据的验证需要；明确来源、候选身份、几何/profile 和原始 CRC。具体导出方法由规划在现有资源内冻结，不虚构已有工具。
3. 少量代表场景即可，给前处理 A/B 和压缩比对照；片段结果只报告片段，不冒充整帧。合成向量可以先推进；真实 Bayer 结论所需参数未确认时，不伪填已知或宣称通过。

三、单A实际压缩链路闭环。
1. 在同一新派生生产候选中接通“真实单A采集 → DDR → A+ 压缩 → 压缩数据保存 → FPGA读回/非 PCIe 调试导出 → PC独立解码与逆变换”，无需 FPGA 解码器、无需 RK 主机。
2. 至少一帧完整真实输入与其解码还原结果逐样本 0 mismatch；原始 RAW、变换域、标准码流的精确长度和 CRC 覆盖范围分别记录；stored 仍须正确逆变换。真实样例同时报告 A/B 压缩率和不可压缩时的最坏膨胀/缓冲容量。
3. 覆盖帧尾、反压、缓存不足、坏帧/溢出撤销、复位后恢复；完整帧才发布，已发布但未消费的数据不被覆盖。检查新增通路对原 RAW 路径和现有生产功能的影响，不借机改写三算法。

## 4. 生命周期、序号和完成可见性

单路当前流程：**配置合法地址/容量/session → 等源至少发布过一帧完整好帧 → ARM → FPGA持有一帧源块并发送 → 数据完整可见 → doorbell/held → RK复制、校验并完成消费者持有 → ACK(session,push_seq) → 释放该源块 → 下一ARM**。

当前实现ARM会锁存已有src_seq，只领取之后新发布帧；它在单路阶段保留。双路阶段MP33必须新增协商的READY-claim能力：领取指定配对中已经发布且未消费的完整帧，不再因第二次ARM跳过B(n)。单引擎可保留，旧ARM语义不能当成双路各30fps证明。

- `capture_seq`：每路采集序号，包含随后坏掉/丢弃的帧，允许缺口。
- `push_seq/held_seq`：传输序号，当前与doorbell对应，**ACK匹配的是它**。不能拿头里的capture_seq直接ACK。
- `pair_id`：RK/同步层产生的左右配对ID，单独保存左右capture_seq/时间戳；目前未实现，MP33补齐。
- `FRAME_FLAG_COMPLETE`只表示传输完成；只有严格解析/CRC/几何/session通过才是“可信图像”。
- 同一个held期间源块、长度和内容必须稳定。ACK不匹配不得release；活动中不允许改源相机/容量/地址。
- CANCEL只停止后续包并排空已发出请求，不截半个TLP；RK确认停止DMA之前不得free它可能写入的内存。CANCEL超时、ARM部分成功、remove/reset均由MP05提供受审查的生命周期实现。
- 会话重建使旧doorbell/held/ACK无效；部分初始化失败也必须按实际已授权写入状态回收，不能因一个布尔标记尚未置位跳过停止。
- 正式解析强制magic、已知版本/格式/codec、合法camera/phase/dir、长度、模式、session及三CRC；坏magic不得退回诊断PGM，unknown不得猜测格式。

## 5. 本轮选择的压缩合同候选

这是**未来实现规范**，不是现有RTL已经支持。其中v1.1/codec0/GRAY8与长度快照由MP17先落地，使三算法实收不依赖压缩实现；MP22随后补压缩布局/能力/向量。本节固定架构、枚举和字节语义，队友按此实现，不另选容器。

### 5.1 版本与内容模式

- `R10F v1.0/codec0/format0`保留原义。
- 新能力用`R10F v1.1`：`codec_id=2`为本单的分块LZ77容器；`codec_id=1`保留给将来BPR1，不启用。
- v1.1的`format_id=0`仍为packed RAW10、valid_bits10、stride=width×5/4；`format_id=2`为GRAY8、valid_bits8、stride=width，packing=0，Bayer phase/dir字段置0。
- v1.1/codec0可承载GRAY8整帧RAW回退；RAW10整帧回退优先发已有v1.0/codec0。解析器按协商能力明确支持，不把所有v1.1帧拒收或宽松放行。
- 内容模式由mode_id版本说明固定：RAW旁路、灰度、高斯、前帧HE。具体数值与相机模式版本的组合编码在MP22生成唯一表，避免把现有相机mode_id直接覆盖为算法号。
- 所有三算法真实并行，帧输出可选一路；算法输出和RAW都可进入LZ77。彩色NPU/深度基线优先用RAW解码后处理，算法示范不要求把灰度当彩色。

### 5.2 LZ77和可逆Bayer前处理

- 标准码流选[DEFLATE RFC1951](https://www.rfc-editor.org/rfc/rfc1951.html)的raw stream，fixed-Huffman块，**无zlib/gzip外壳**。真实literal/match，字典距离1..4096B，长度3..258B；每个图像块独立流并重置字典。字节从低位填充，但Huffman码字按MSB先入流，其他字段/extra bits按LSB先入流；收尾不足一字节的高位补0。
- 默认图像块16行；1080p共有68块，前67块16行、最后1块8行。每块都按原图顺序定义原长。
- Bayer优化可关：每行前两样本原值锚点，后续`d[x]=(p[x]-p[x-2]) mod1024`；逆变换`p[x]=(d[x]+p[x-2]) mod1024`，再以同样RAW10 packed顺序串行化。每行重置，不跨行/块预测。
- 这只是码流可逆变换，不做减位、白平衡或改变Bayer相位。GRAY8禁止此预测，使用plain LZ77。
- 比较plain LZ77与Bayer+LZ77只用同一真实图集；默认开关按数据定，不预先保证一定优于plain。

### 5.3 每块32B头，随后紧接精确块载荷

无块间对齐填充。小端，块按first_row递增、连续覆盖整幅图，不留洞/重叠。

| 偏移 | 字段 | 约束 |
|---:|---|---|
| 0x00 | block_raw_bytes u32 | row_count×stride，原始图像字节数 |
| 0x04 | block_payload_bytes u32 | 此块紧随载荷精确长，不含本头/其他填充 |
| 0x08 | block_raw_crc32 u32 | 原始packed RAW10或GRAY8字节 |
| 0x0C | block_payload_crc32 u32 | 实际块载荷字节；RAW块即原始字节 |
| 0x10 | first_row u16 | 从0开始，和前块连续 |
| 0x12 | row_count u16 | 1..16；正常仅末块可少于16 |
| 0x14 | block_mode u8 | 0=原始RAW块；1=plain raw DEFLATE；2=Bayer预测后raw DEFLATE |
| 0x15 | predictor_id u8 | 0=无；1=逐行x-2 mod1024，仅block_mode2/format0合法 |
| 0x16 | reserved u16 | 零 |
| 0x18 | block_index u32 | 从0连续递增 |
| 0x1C | reserved u32 | 零 |

RAW块必须payload长等于raw长，载荷保存**原始样本的packed字节**。不能把“压缩放弃”实现成直接把预测残差贴成RAW。

### 5.4 四种长度和CRC

| 名称 | 固定含义 |
|---|---|
| raw_bytes | 完整解码并逆变换后的原始图像字节；RAW10为stride×height，GRAY8亦然 |
| payload_bytes | codec2为所有32B块头与各块精确载荷之和；codec0为原始图像字节，无块头；均不含外头/DMA尾 |
| content_bytes | 128+payload_bytes |
| dma_bytes | ceil(content_bytes/4096)×4096；其余字节全零 |
| raw_crc32 | 原始图像按行串接的CRC，解码还原后验证 |
| payload_crc32 | 全部块头+实际块载荷的CRC，解码前验证 |
| header_crc32 | 保持清零0x58字段后覆盖外头128B |

**按版本/codec分支验证，保留v1.0/codec0原有严格规则。** 新增codec2分支允许raw_bytes>payload_bytes，raw CRC必须在独立解压/逆变换后计算；不能沿用codec0载荷前缀算法。解压限长为每块/全帧raw_bytes，检查精确消费、规范尾bit、块数/索引/行数和保留位。v1.1/codec0 GRAY8固定block_count=1、raw_bytes=payload_bytes=stride×height、无块头，两者CRC均覆盖原始Gray8；1080p为2,073,600B、DMA2,076,672B、尾2944B。

两层回退：块压缩不省则block_mode0；整帧含所有块头仍不省，则直接发原RAW的codec0。host按最大RAW帧容量分配，压缩不增加1080p最坏槽容量。

当前pusher有固定帧长假设，**变长不只改内容头**：MP17先补实际dma_bytes随源发布/held快照，MP22/30扩展到压缩范围，并提供新能力/版本及RK检查；host slot容量、实际搬运长度、压缩精确长度分别命名。新增长度寄存器具体偏移由MP17核对当前已占用地址后一次冻结，MP22复用/补齐压缩能力，不能在总规划中虚构一个空闲地址。

## 6. 真实几何、同步和配对

- 首版1920×1080中心ROI方向已经选定；物理dummy/OB、实际WC、Bayer相位和fps必须先板证。源有效区若不是3840×2160，MP08按已定“有效区居中、Bayer偶数起点”规则给实际数值，不把候选值当测量。
- A/B必须同读出模式、曝光/增益及方向；左右身份固定。机械基线、焦距、标定板格长均实测入文件，不能从照片估算。
- 同步首选A master→共享XHS/XVS→B slave，B同步输出Hi-Z；先证明真实模组连接与安全观测条件，不默认自行改线。
- 共同时基定为100MHz、u64 tick，明确每路SOF事件CDC与量化误差；MP33实施前绑定实际时钟和计数器。跨域异步多bit不能直接采样。
- 工程同步目标为对应曝光差<1ms；≥1000对记录，XVS/光学/滚动行证据与SOF差分别报告。SOF只能辅助，pair_id不是曝光证明。
- 配对键至少session+mode+左右身份+时间窗；每路队列上限4帧为首版，超窗/满队列丢弃整对并计数，不无限排队。对齐窗口初设1ms，在MP35校准时钟/固定偏置后固化；没有曝光证据则只能称时间戳配对。
- 传输按完整帧轮换，并先预留同pair的A/B完整帧。每相机首版3个源槽，FREE/WRITING/READY/HELD状态互斥，READY索引队列上限2；一侧发送/ACK不释放另一侧保留的帧。满队列按整对丢弃/计数，源槽/编码临时区容量由MP33重新核算。双路每路HE/LUT/行缓存与压缩字典隔离；一路复位后更新会话/配对状态，不能把新左图和旧右图拼起来。

## 8. 变更与争议处理

已确定的格式/大小端/队列/序号/责任不因“我代码原来这样”而随意改变。队友发现差异，交最小失败样例、具体字段/版本、实际结果和建议适配点；默认调整其实现，双方共享问题才修改规范并成对升级版本。

只有三类证据重开选择：实测失败/预算被推翻；关键官方/手册新证据；有时间窗口且量化收益明确。协议/几何/时钟/DDR改动必须给受影响复测范围，旧证据按输入绑定，不能改个标题续用。

**本稿拟冻结项**：责任、仓库主源、当前RAW合同、800E/AXI生产方向、LZ77标准码流/块头/回退、同步/序号原则、RK后续方案。

# 后续小任务清单 V0.9

日期：2026-10-17。与[总规划](00_总规划与验收基线.md)、[冻结单](02_队友接口与交付冻结单.md)一起审查。

这是一份**完整后续工作分解，不按天排班，不代表已经派发**。MP 是现有 T 任务的细分索引；实际状态仍写 `workflow/tasks.json`。已完成的 IP 生成、T09 模块开发、RAW 离线候选不重新列为待开发。

F=用户 FPGA 主责及助手；R=队友 RK 主责（本稿分配，承诺待取得）；J=双方联调；U=用户审查/提交。每卡含依赖、输入/落点、最多三项语义工作及退出证据。所有 MP 均以 MP01 的审查确认为共同前提；卡中只列额外技术依赖。缺环境/设备就停在对应层，不伪造 PASS。

G0=接口/验收；G1=模型/仿真/软件；G2=最终构建/时序/资源；G3=真实板功能；G4=持续性能/长稳；G5=集成/可恢复交付。改动的适用检查随本包完成，不为每个命令再建任务。下一轮如果启用项目工作流，最多取四个正式工作包，默认一包一开发/一综合测试者。

## A. 基线、真实采集与首次可信实收

### MP01 审查定稿与当前入口同步
- 归属/主责：T03、各任务记录；U/F；G0。依赖：无。
- 输入/落点：本三份规划、source-snapshot、现有任务板/README/CODEX_HANDOFF；**确认后**才改后者。
- 工作：①确认总规格和我方冻结项；②同步最新1333板验/T09模块PASS/暂停状态及MP→T映射；③从真实提交入口登记模板、视频/压缩包约束，不改旧报告。
- 退出：用户确认版本可定位；三个旧入口不再错误地写“1333没生成、三算法没开发”；队友责任与未承诺项分清，保留旧run计数和暂停边界。

### MP02 将现成 FPGA RAW 通路逐文件并入生产原仓
- 归属/主责：T07/T11；F；G0—G2。依赖：无。
- 输入/落点：T11 manifest `AAB0CC08…`、`fpga/csi2/pcie_integration` → FPGA原仓 `rtl/`、`sim/`、构建入口。
- 工作：①核对原仓main相对2a4b253的变化和协作权限；②按7改6增迁入源码，连同8TB/工具/严格向量，不覆盖相同IP/约束；③去除本机固定路径并在新位置生成候选。
- 退出：来源→目标diff可审；原仓路径8TB及负例通过；同新DB STA/CDC/资源合格，bit/manifest绑定。旧bit只作来源，不能当迁入后新候选。

### MP03 将两层 RK 补丁转成原仓正式源码
- 归属/主责：T03/T07/T11；R；G0/G1。依赖：无。
- 输入/落点：driver a0215c5、T07主补丁+T11增量/最终树 → driver原仓 `src/`、`include/`、`app/rs/`。
- 工作：①比较最新main并审查8改3增；②保留16B槽ABI、改为128B数据偏移/0x61模式/正式解析；③固定配对版本并完成静态/离线向量验证。
- 退出：不能只打T07；坏magic/CRC/长度向量均有正式拒绝路径；原仓真实diff与补丁映射齐全。真实RK编译由MP04接续。

### MP04 固定 RK 编译与 PCIe 实机环境
- 归属/主责：T05/T07；R；G0/G1/G3。依赖：MP03。
- 输入/落点：OrangePi 5 Max，配对源码 → `docs/environment/`、实际模块/工具版本清单。
- 工作：①记录OS/kernel/KDIR、工具链/cargo、RKNN留待B；②编译模块/Rust工具并识别实际加载SHA；③记录BDF、link速率/宽度、BAR、PAGE_SIZE、MPS、DMA mask/IOMMU。
- 退出：真实编译/加载可复现、旧模块可回退；MPS≥128、DMA地址/容量合法，4KiB页面假设得到验证或明确阻塞。枚举成功只算建链。

### MP05 封口 DMA 停止、回收和复位生命周期
- 归属/主责：T07；R；G1/G3。依赖：MP03；硬件部分依赖MP04。
- 输入/落点：`anlogic_pci_link.c`、`anlogic_pci_hw.c`、reset/remove路径及RKA1合同。
- 工作：①ARM已下发但后续读失败也进入需要停止的状态；②CANCEL超时/部分初始化/退出不再仅sleep后无条件free；③建立有证据的停止DMA、总线隔离与会话重建路径。
- 退出：故障注入覆盖ARM后失败、CANCEL不响应、close/remove/reset；**确认停止DMA前不得回收其可写缓冲**；旧门铃/ACK/session不可重新激活。具体内核隔离顺序必须审查，不靠固定等待代替。

### MP06 实现正式连续收帧程序
- 归属/主责：T07/T11；R；G1/G3。依赖：MP03、MP05。
- 输入/落点：RKA1/R10F库与共享向量 → `app/rs`正式capture入口。
- 工作：①首次ARM前等源至少发布过完整好帧，再ARM→等held→复制/严格校验/保存→匹配push_seq ACK→再ARM；②正式模式强制magic/session/camera/mode/长度/三CRC，不回落旧PGM路径；③分开保存`.dma/.r10f`、JSON元数据和解包预览。
- 退出：坏magic、截断、旧session、错seq/相机、CRC损坏都拒收；保存/消费者完成后才ACK；timeout/退出进入MP05停止流程，日志含分段时间与序号缺口。

### MP07 测清 IMX415 实际包几何和帧率
- 归属/主责：T02；F；G3。依赖：MP02。
- 输入/落点：真实单A、当前ROM/PHY/完整性节点 → `records/T02`几何及计数记录。
- 工作：①丢弃启动前8帧，读取DT/VC/WC/行数/FE、OB/dummy与错误分类；②测真实SOF间隔、源模式/输入时钟/寄存器；③按好帧记录有效区与恢复行为。
- 退出：以实际数值替换SKIP_ROWS=37等诊断占位；有原始采样/计数和候选SHA。配置写“4K30”与HDMI60Hz都不能代替采集fps实测。

### MP08 固定1080p ROI、RAW10和Bayer相位
- 归属/主责：T02/T06；F；G1—G3。依赖：MP07。
- 输入/落点：实流几何 → `cam_r10f_writer.v`几何参数、模式元数据、严格向量。
- 工作：①优先从已通有效全幅取中心1920×1080，偶数有效区起点；②分开记录物理dummy偏移/有效ROI，按最终奇偶推导相位；③用红蓝/方向测试与原始值确认相位。
- 退出：1920×1080、stride2400、10bit/packed真实成立；起点/镜像/翻转/phase有板证；不是960×540预览放大，不能照搬另候选GBRG结论。

### MP09 完整RAW成帧与DDR所有权实机检查
- 归属/主责：T06/T11；F；G1—G3。依赖：MP08。
- 输入/落点：正式writer/DDR → 帧长、完整发布、缓冲保护/地址诊断记录。
- 工作：①检查末行/尾组、高位地址、全部bresp和三CRC回填；②短帧/CRC错/溢出拒整帧，未发布帧不可发送；③held/未claim/取消各路径验证A/B块独立释放。
- 退出：只有完整好帧可发布；所声明2,592,768B全部正确；不借预览“替换旧READY”破坏DMA所有权。逐字节实收对照在MP11闭环。

### MP10 固定测试数据首次C2H DMA实收
- 归属/主责：T07；J；G3。依赖：MP02、MP04—06。
- 输入/落点：固定递增/地址敏感图样、配对bit/driver → DMA原件与对照结果。
- 工作：①先100帧固定图样；②核查128B写粒度/4KiB边界、doorbell可见性、完整字节；③做一次正常停止/重启。
- 退出：100帧逐字节正确、零越界/CRC错；held未ACK不可覆盖，data先于完成可见。失败不直接混入真实相机排查。

### MP11 单A真实RAW连续实收
- 归属/主责：T02/T06/T07/T11；J；G3/G4。依赖：MP09、MP10。
- 输入/落点：真实单A、正式ROI/phase、MP06程序 → 实拍RAW/R10F与10min计数。
- 工作：①首100帧严格实收和样本范围检查；②真实RAW解包/图像/元数据一致；③连续10min统计capture/publish/push/receive/CRC/fps。
- 退出：100帧零CRC/几何/session错误；正常10min无非预期丢帧、覆盖；报告实测fps和延迟。首次未过时先止于此，压缩实机和双路不越过。

### MP12 建立真实图集和可复用金参考
- 归属/主责：T04；F/R；G1/G3。依赖：MP11。
- 输入/落点：实收RAW → 图集manifest、元数据、解包参考与预览。
- 工作：①至少6类场景各20帧：白纸/色块、纹理、常规室内、运动、暗部/噪声、反光高光；②记录曝光/增益/phase/ROI来源；③按场景分开发/验收帧并固定SHA。
- 退出：不少于120真实帧、每场景≥20；不是合成图替代实拍，不只挑易压缩白纸；源RAW永存，预览与真值分开。

### MP13 单路故障注入与恢复
- 归属/主责：T07/T11；J；G1/G3。依赖：MP10、MP11、MP05。
- 输入/落点：配对系统 → fault/recovery记录及必要局部修复。
- 工作：①错ACK/旧session/容量不足/程序退出；②超时/CANCEL排空/复位与重载；③短帧/坏CRC拒收后下一帧恢复。
- 退出：无越界、旧写入、提前free和坏帧发布；每种故障有预期状态、计数与恢复步骤，不把人工重启掩盖的失败记零故障。

## B. 三算法与组合工程

- 退出：主工程只有一颗DDR IP，无双写者争用；地址/缓冲预算闭合；组合版实机回归通过。若带宽不够，给实测瓶颈另提同AXI升级，不擅自替换1333。

### MP15 DDR校准、启动与计数可观测性

- 退出：正常启动目标10/10；间歇校准问题未解释不得写“已根治”；不恢复用户取消的1600ctl干净上板对照。

### MP16 将已验T09三算法接入生产主顶层

- 退出：同候选逐像素金参考通过、最终STA/CDC/资源合格；修正文档旧SHA/负对照锚点；不用已通过模块作为理由跳过顶层检查。

### MP17 先落地GRAY8传输，再验收三算法真实输出
- 归属/主责：T03/T09/T11；F/R；G0—G3。依赖：MP16、MP11。
- 输入/落点：本冻结单v1.1/codec0/format2、同批实拍RAW → Gray8帧写者/长度快照、RK严格解析与金参考对照。
- 工作：①先实现Gray8最小协议扩展：stride1920、raw=payload2,073,600、DMA2,076,672、尾2944B，三CRC和严格版本分支；②补实际搬运长度/held稳定快照及双方能力检查；③实收三种硬件输出逐像素对照，验证并行计数/首帧HE/坏帧/帧边界切换。
- 退出：正式Gray8解析/写者已存在才做PCIe算法实收；不等MP22的压缩容器、不借RAW10头伪装Gray8。三算法都是板上硬件结果，10→8与压缩收益分开。

### MP18 RAW/三算法组合候选回归与冻结
- 归属/主责：T09/T11；F/J；G1—G3。依赖：MP15—17、MP13。

- 退出：相同输入的功能/工程/系统验收齐全；未达0.300ns单列观察，不拼T09小顶和旧预览的PASS。

### MP19 噪点/闪点分层诊断（条件触发）
- 归属/主责：T01/T02；F；G1/G3。依赖：MP07/MP11，**出现采集CRC增长、可复现像素损坏或展示验收失败才启动**。
- 输入/落点：同一候选、RAW/算法输出/HDMI对照与计数 → 最小受控实验记录。
- 工作：①区分RAW源噪声、接收错误、DDR、算法、显示串行；②每次只改一变量；③局部修复后绑定受影响项复测。
- 退出：给可复现证据及定位范围；不默认重启既有暂缓闪点线，不把减曝光或“看起来好些”当根因关闭。

## C. LZ77主线与压缩传输

### MP20 固定标准LZ77软件基线
- 归属/主责：T04/T10；F；G0/G1。依赖：无，可与实收准备并行。
- 输入/落点：冻结单压缩规范、合成边界向量 → codec参考/标准inflate交叉检查。
- 工作：①raw DEFLATE固定Huffman，距离≤4096、长度3—258、16行独立块；②建立独立zlib/标准inflate解码；③覆盖随机/常量/重复/重叠匹配/全字节与末块。
- 退出：不声称自定义token可被zlib解；所有向量精确还原且码流规范；固定库版本与许可。真实收益由MP29评定。

### MP21 Bayer可逆前处理及A/B向量
- 归属/主责：T04/T10；F/R；G1。依赖：MP20；实拍部分依赖MP12。
- 输入/落点：packed RAW10 → 逐行同色预测/逆变换金参考与开关向量。
- 工作：①每行前两像素锚点，后续(x[i]-x[i-2]) mod1024；②重打包10bit、标准压缩后独立解压/逆预测；③与不预测基线同图比较。
- 退出：全0/1023、锚点、跨行/块、四相位/方向逐样本无损；GRAY8禁止该预测；RAW回退保存原始RAW，不能误存残差。

### MP22 压缩/Gray8协议和共享样例一次冻结
- 归属/主责：T03/T10/T11；F/R；G0/G1。依赖：MP17、MP20、MP21。
- 输入/落点：冻结单的R10F1.1/codec2/块记录 → FPGA协议主目录、driver镜像、正负向量。
- 工作：①固化128B外头、32B块头、精确长度/CRC/RAW回退；②复用MP17长度快照接口并补压缩变长范围/能力版本，旧ABI不复用；③两端解析对照RAW10、Gray8、最后8行和截断/尾部负例。
- 退出：布局/偏移/枚举/寄存器/样例SHA都明确；未知minor/codec/format不得猜测；codec0 v1.0保持字节兼容；不只改codec_id沿用旧解析器。

### MP23 LZ77匹配与字典RTL
- 归属/主责：T10；F；G1/G2。依赖：MP20、MP22。
- 输入/落点：金参考与界限 → `rtl/ep_side/codec/`匹配/字典模块及实际DUT TB。
- 工作：①实现真实literal/match、4KiB有界字典；②限定搜索服务时间、长度/距离及重叠复制语义；③reset/块界/stall不污染字典或丢输入。
- 退出：DUT token与独立解码可对照，最坏随机输入也有有界吞吐/缓存预算；先局部综合，不以软件模型回放代替RTL。

### MP24 fixed-Huffman/位打包与标准流收尾RTL
- 归属/主责：T10；F；G1/G2。依赖：MP23。
- 输入/落点：literal/match tokens → RFC1951 raw DEFLATE字节流/精确bit数。
- 工作：①实现长度/距离码与固定Huffman：字节从低位填充，Huffman码字MSB先入流，其他字段/extra bits为LSB先入流（LSB移位器须反转Huffman码字）；②正确BFINAL/结束码/零尾bit；③反压、同拍take/refill、块尾不足字节与复位撤销。
- 退出：固定literal/match标准字节向量一致，独立标准inflate直接接受RTL产物并完全还原；匹配最大值/距离边界/尾bit负例通过；输出扩张和码长有上界。

### MP25 块选择、CRC与整帧RAW回退
- 归属/主责：T10；F；G1/G2。依赖：MP21、MP24。
- 输入/落点：原始块、压缩块 → 冻结块头/帧发布器。
- 工作：①压缩不省字节则块用原RAW；②计算原始/块载荷/帧载荷/头CRC与准确长度；③整帧含块头仍不省时直接发布codec0原帧。
